## 1 软件概述

### 1.1 用途

vfife 是一个以**向量式有限元（Vector Form Intrinsic Finite Element，VFIFE）**为核心的结构
分析程序。它把结构离散为一组质点，质点的运动由牛顿第二定律直接积分；单元只负责在每个时间
步由质点的相对位移算出内力，大转动通过"共旋"（逐步扣除刚体运动）处理。因此几何非线性、
材料非线性、构件断裂与分离都在同一个显式框架里自然处理，不需要组装和求解总刚度矩阵。

静力问题用**动力松弛**求解：给质点赋虚拟质量，加动能阻尼，让结构"落"到平衡位置；分级
加载时每一级都收敛到残差容差，所以荷载–位移曲线上的每一点都是真实的平衡点。

软件面向的典型问题：

* 钢筋混凝土、预应力混凝土构件与桥梁从开裂、屈服、压溃到断丝倒塌的全过程
* 锈蚀、预应力损失、温度、徐变收缩等作用下承载力的劣化
* 地震时程、移动荷载等动力问题；受载状态下的模态
* 索结构找形、悬索桥与斜拉桥的大位移分析
* 实体、壳、梁、杆、连接器混合的结构模型

### 1.2 主要功能

| 类别 | 功能 |
|---|---|
| 单元 | 实体 tet4/tet10/hexa8/hexa20/wedge6/wedge15/pyramid5；壳 shell3/shell4；梁 beam2（Euler–Bernoulli）、beam2_timoshenko；纤维梁 beam2_fiber；杆/索 truss2；六分量连接器 connector2；混合模型 mixed_line、shell_line、coupled |
| 材料 | 线弹性、正交各向异性、粘弹性、J2 塑性、Chaboche 循环塑性与损伤、混凝土损伤塑性 CDP；单轴 concrete01/concrete02、steel02、steel_cyclic、rebar、分段线性；粘结滑移 bond_ceb、bond_cyclic |
| 钢筋与预应力 | 按图纸坐标布置的嵌入式钢筋（与网格无关）、粘结滑移、先张与后张预应力（摩擦、锚固回缩、弹性压缩）、纤维截面内逐单元定位的预应力束 |
| 荷载 | 集中力、力偶、线荷载、面力、压力（可随动）、体力、重力、温度（均匀/梯度/任意剖面）、移动荷载、地震地面加速度 |
| 时间效应 | 混凝土徐变、收缩、龄期，预应力钢筋松弛 |
| 分析 | 动力松弛静力分析（连续或分级）、显式动力分析、多分析步顺序执行、受载状态模态、索找形 |
| 破坏 | 纤维断裂与构件分离、单元删除、钢绞线断丝 |
| 后端 | NumPy（参考实现）、Numba（CPU 编译内核）、Warp/CUDA（GPU） |
| 输出 | HDF5 + XDMF（ParaView 直接打开），监测量曲线图、CSV，纤维截面沿变形轴线扫掠成面，振型动画 |
| 质量保证 | 运行前模型检查（preflight）、力学不变量探针（probe）、61 份验证契约及 `verify` 命令 |

### 1.3 使用方式

vfife 没有图形界面，这是有意的设计：**命令行、Python 接口和 YAML 算例文件共用同一套流程**。
一个算例就是一个 YAML 文本文件，可以用任何编辑器编写、用版本管理跟踪、在脚本里批量生成。
网格用 Gmsh 生成，结果用 ParaView 查看。

**本手册讲概念和建模方法；算例文件能写什么，查 `docs/YAML参考.md`。** 那份文件由
`python -m vfife reference` 从代码生成：每个块的每个字段、类型、默认值、中文说明与英文原注，以及
用到它的自带算例编号；末尾列出没有算例的字段。测试保证它与代码一致，所以它不会过时。

## 2 安装与运行环境

### 2.1 安装

```bash
git clone https://github.com/maolin2000/vfife.git
cd vfife
pip install -e ".[dev,plot,cpu]"      # NumPy + Numba；需要 GPU 时加 ",gpu"，扫掠/振型导出加 ",paraview"
python -m vfife --version
```

或用 Conda（同时安装 Gmsh）：

```bash
conda env create -f environment.yml
conda activate vfife
```

依赖：numpy、scipy、pydantic、pyyaml、h5py；可选 matplotlib（画图）、numba（CPU 编译内核）、
warp-lang（GPU）、meshio（扫掠与振型导出；`paraview` 这个 extra 会装它，1.0 版）。

### 2.2 配套软件

* **Gmsh**：建几何、划网格。vfife 读 `.msh`（4.1 ASCII / 4.1 二进制 / 2.2）
* **ParaView**：打开结果旁边的 `.xdmf` 文件查看变形、应力、损伤

### 2.3 检查安装

```bash
python -m vfife list
```

输出：

```
elements: beam2, beam2_fiber, beam2_timoshenko, connector2, coupled, hexa20, hexa8, mixed_line, pyramid5, shell3, shell4, shell_line, tet10, tet4, truss2, wedge15, wedge6
materials: bond_ceb, bond_cyclic, cdp, chaboche, concrete01, concrete02, j2, linear_elastic, orthotropic, piecewise_uniaxial, rebar, steel02, steel_cyclic, viscoelastic
```

能列出单元和材料就说明装好了。命令一律写作 `python -m vfife ...`；`pip install -e .` 之后
也可以直接写 `vfife ...`。

### 2.4 编辑器补全

在 VS Code 里写算例，可以有字段补全、悬停说明和拼错键的红线（1.0 版）：

1. 安装 Red Hat 的 YAML 扩展（扩展市场搜 "YAML"，发布者 Red Hat）。
2. 在算例所在的文件夹运行 `vfife schema`，它写出 `vfife.schema.json`（`-o` 换位置），并打印要加的那一行。
3. 把这一行放在算例最前面（路径相对算例文件）：

```bash
python -m vfife schema       # 写出 vfife.schema.json
```

```yaml
# yaml-language-server: $schema=vfife.schema.json
```

之后输入键时列出这一层能写的字段和枚举值（`mode: relaxation | static | dynamic`、材料的 `type`）；悬停在字段上显示它的说明——
与 docs/YAML参考.md 同一段代码注释，中英文各一行；拼错的键、枚举外的值、缺少的必填键标红。`vfife init` 生成的算例第一行
就是这一行，并在算例旁写好 `vfife.schema.json`（已有的不覆盖；与当前版本不同时提示重跑 `vfife schema`）。schema 随版本更新，
升级 vfife 后重跑一次。几点说明：

* 它只查结构（键、类型、枚举）；材料参数只查 `type`，模型本身的问题仍由 `vfife check` 查。
* 旧写法（`b`、`h`、`torsion_constant` 等）会被标红：`vfife migrate` 把它们改成现在的名字。
* 编辑器按 YAML 1.2 读，`2e11` 是数；vfife 也把它当数。自己用 Python 的 `jsonschema` 校验时，PyYAML（YAML 1.1）
  把没有小数点的 `2e11` 读成字符串，先用 `vfife.io.schema.coerce_numbers` 转换，或写成 `2.0e+11`。

## 3 第一个算例：20 m 后张预应力混凝土简支梁

本章用一个完整算例走一遍"检查网格 → 写算例 → 检查模型 → 运行 → 看结果"。
**文中的输出都是实际运行得到的。** 实体构件的入门算例见 `docs/tutorial.md`（钢悬臂托架，
含 Gmsh 建模与四面体锁死的处理）。

### 3.1 网格

梁用一串两节点线单元表示。仓库自带一个 20 m、20 个单元的直线网格
`benchmarks/assets/thermal_span_20.msh`，先看看里面有什么：

```bash
python -m vfife mesh benchmarks/assets/thermal_span_20.msh
```

```
  element       truss2 (line), 20 elements, 21 nodes
  extent        x [0, 20]  y [0, 0]  z [0, 0]
  physical groups (use these names in `region:`)
    beam                 21 nodes   x [0, 20], y=0, z=0
    left                  1 nodes   x=0, y=0, z=0
    mid                   1 nodes   x=10, y=0, z=0
    right                 1 nodes   x=20, y=0, z=0
```

四个物理组 `beam`、`left`、`mid`、`right` 就是算例里 `region:` 可以直接用的名字。
（这里显示 truss2 是因为线网格本身不带截面；截面在算例里指派，指派纤维截面后就是纤维梁。）

### 3.2 算例文件

把网格复制到算例旁边，新建 `pc_beam.yaml`：

```yaml
version: 1
name: pc_beam
units: {length: m, force: N, stress: Pa}
mesh: {type: gmsh, path: thermal_span_20.msh}

materials:
  concrete: {type: concrete02, fpc: 40.0e+6, epsc0: 0.002, fcu: 8.0e+6, epscu: 0.0035,
             ft: 2.6e+6, Ets: 1.5e+9, rat: 0.1, rho: 2500}
  rebar:    {type: steel02, E: 2.0e+11, Fy: 4.0e+8, b: 0.01, R0: 20.0, rho: 7850}
  strand:   {type: steel02, E: 1.95e+11, Fy: 1.58e+9, b: 0.02, R0: 20.0, rho: 7850,
             rupture_strain: 0.035}

sections:
  phi16:  {type: bar, material: rebar, shape: circle, diameter: 0.016}
  duct:   {type: bar, material: strand, shape: general, area: 2.8e-3}
  girder:
    type: fiber
    material: concrete
    shape: rect
    width: 0.5
    height: 1.2
    ny: 4
    nz: 24
    integration: lobatto3
    bars:
      - {y: 0.0, z: -0.55, section: phi16, count: 4}
    tendons:
      - section: duct
        profile: [[0.0, 0.0, 0.0], [10.0, 0.0, -0.45], [20.0, 0.0, 0.0]]
        interpolation: quadratic
        jack: 1.30e+9
        friction: {mu: 0.17, k: 0.0015, jack: start, anchor_set: 0.006}

assign:
  - {region: beam, section: girder, orientation: [0, 1, 0]}

constraints:
  - {region: beam,  dofs: [0, 1, 0, 1, 0, 1]}   # 平面问题：锁住出平面自由度
  - {region: left,  dofs: [1, 1, 1, 0, 0, 0]}
  - {region: right, dofs: [0, 1, 1, 0, 0, 0]}

loads:
  - {region: beam, line_load: [0.0, 0.0, -15.0e+3]}   # 恒载 15 kN/m

amplitudes:
  live: [[0.0, 0.0], [1.0, 1.0]]

steps:
  - name: dead
    load_steps: 1
  - name: live
    loads:
      - {region: beam, line_load: [0.0, 0.0, -60.0e+3], amplitude: live}
    load_steps: 12

solver:
  backend: numpy
  mode: relaxation
  damping: {type: kinetic}
  tolerance: 1.0e-5
  max_steps_per_load: 60000

output:
  path: results/pc_beam.h5
  fields: [displacement, fiber_stress, fiber_damage]
  monitors:
    w_mid: {kind: displacement, region: mid, dof: z}
    R_left: {kind: reaction, region: left, dof: z}
```

逐段说明：

* **materials**：C40 混凝土（`concrete02`，含受拉软化）、普通钢筋和钢绞线（`steel02`，
  钢绞线断裂应变 3.5%）
* **sections**：`girder` 是 0.5 m × 1.2 m 的矩形纤维截面，4 × 24 根混凝土纤维；底部 4 根 Φ16；
  一根抛物线预应力束，跨中下垂 0.45 m，张拉控制应力 1300 MPa，一端张拉，按摩擦系数 0.17、
  偏差系数 0.0015 和 6 mm 锚固回缩计算损失
* **assign**：把截面指派给 `beam` 物理组；`orientation` 给出截面局部 y 轴的方向
* **constraints**：`dofs` 六个标志依次对应 ux、uy、uz、rx、ry、rz，1 为约束。
  第一行把整根梁锁在 x–z 平面内，后两行是一端铰、一端滚动
* **loads / steps**：恒载写在模型级，从第一步起一直作用；第二步 `live` 把 60 kN/m 活载分
  12 级加上，每级收敛后输出一帧
* **solver**：动力松弛。`max_steps_per_load` 是每级的迭代上限；总迭代数由各步
  `load_steps × max_steps_per_load` 自动相加，不必再写 `n_steps`
  （0.4.2 及以前的版本，线单元和壳单元模型仍要写 `solver.n_steps`，见第 10.3 节）
* **output**：跨中挠度和左支座反力两条监测曲线；纤维应力与损伤写入结果文件

### 3.3 运行前检查

```bash
python -m vfife check pc_beam.yaml
```

```
case: pc_beam
  preflight     PASS (0 errors, 0 warnings)
```

`check` 检查区域是否选到节点、有没有未约束的刚体运动、单位量级是否合理等。preflight 通过后，它总是
用 numpy 后端把模型建起来（不初始化 GPU，不求解）：建不起来记为错误 `MODEL_BUILD_FAILED`（退出码 2）；
算例写了 `output.fields` 时，再拒绝模型给不出的字段名（`UNKNOWN_OUTPUT_FIELD`）。

`info` 进一步把模型建起来、打印摘要，但不求解：

```bash
python -m vfife info pc_beam.yaml
```

```
  mesh          21 nodes, 20 Line2 elements
  element       beam2_fiber / fiber Euler-Bernoulli, 6 DOF/node
  section       rect 0.375 x 1.15 m, 96 fibers + 1 rebar + 1 tendon, A=6.036e-01 Iy=7.212e-02 Iz=1.172e-02
  tendon        section 0 slot 1: A=2.800e-03 m2, y +0.000..+0.000 m, z -0.449..-0.044 m, sigma 1168..1234 MPa, P 3272..3454 kN
  mass          30565.9 kg, of it members 30565.9 kg (each fibre at its material's density); weight 299749 N at g = 9.80665
  fiber         concrete02, steel02, steel02; 98 x 3 points (3pt lobatto)
  mode          relaxation; dt=1.0000e+00, 780000 steps
  axes          beam (beam2_fiber, 20 members): local x = +X, local y = +Y, local z = +Z
```

先读这几行再运行：截面面积 0.6036 m²（0.6 m² 混凝土加钢筋）、束在跨中下垂到 −0.449 m、
摩擦与锚固回缩后的束应力 1168–1234 MPa。**数对不上的时候，问题在输入里，不在求解器里。**
（`rect 0.375 x 1.15` 是纤维中心的范围，不是外廓。`axes` 一行：局部 z 是 +Z，截面的 `height` 和束的 `z` 是竖向的，见 7.5。）

程序会拒绝物理上不成立的输入。例如这根束若写成两端张拉（`jack: both`），6 mm 的回缩超过了
这根又短又平的束能吸收的量，运行时会报：

```
error: anchor set of 6.0 mm draws in more than this tendon can absorb: reflecting the profile
from this end recovers at most 1.79 mm (with `jack: both`, up to the tendon's middle). The
tendon is too short, or too straight, for that much seating -- state the draw-in the
anchorage actually has
```

### 3.4 运行

```bash
python -m vfife run pc_beam.yaml
```

```
  analysis      CONVERGED (residual 7.58e-06, analysis step 2 of 2)
  max |u|       5.901875e-02
  w_mid         final -5.901875e-02
  R_left        final 7.500285e+05
  written       results/pc_beam.h5 (+ .xdmf time series, _last.xdmf fallback for ParaView; .ckpt.h5 checkpoint)
```

**第一个检查永远是反力**：左支座 750.03 kN，对应 (15 + 60) kN/m × 20 m / 2 = 750 kN。
分级松弛时进度行显示 `increment k/n … iterations/s`。

### 3.5 结果

逐级读出跨中挠度（向上为正）：

| 活载 kN/m | 0 | 10 | 20 | 30 | 35 | 40 | 45 | 50 | 55 | 60 |
|---|---|---|---|---|---|---|---|---|---|---|
| 跨中挠度 mm | +10.6 | +3.6 | −3.6 | −11.1 | −14.9 | −19.3 | −25.0 | −33.0 | −44.1 | −59.0 |

* 恒载加预应力下跨中**上拱 10.6 mm**
* 活载在 35 与 40 kN/m 之间底部纤维开始开裂（损伤类别 1），之后曲线明显变软——开裂的纤维数从
  40 kN/m 时的 240 个积分点增加到 60 kN/m 时的 1568 个

画荷载–挠度曲线、导出 CSV：

```bash
python -m vfife plot results/pc_beam.h5 --x w_mid --y R_left     # -> results/pc_beam.png
python -m vfife export results/pc_beam.h5                          # -> results/pc_beam.csv
```

在 ParaView 里打开 `results/pc_beam.xdmf` 可看变形；把纤维截面沿变形后的轴线扫成实体、
按纤维状态着色，用 `vfife sweep`（第 12.4 节）——它要用质点的取向，须先在 `output.fields` 里加上 `rotation`
（`[displacement, rotation, fiber_stress, fiber_damage]`；不加则 `sweep` 拒绝该结果）；
任何结果的三维回放网页用 `vfife view`（第 12.5 节）。

## 4 输入文件总览

一个算例是一个 YAML 文件，顶层键如下（顺序任意）：

| 键 | 必需 | 作用 | 章节 |
|---|---|---|---|
| `version` | 否 | 算例格式版本，写 `1`；不写时与 `version: 1` 按同样的规则读 | 4 |
| `name` | 否 | 算例名，写入结果文件 | |
| `units` | 否 | 声明单位制，如 `{length: m, force: N, stress: Pa}`；用于检查量级、写入结果属性和图的坐标标注；**写出的数不换算**（带单位的默认值换算，见下文"单位"） | 4, 16 |
| `mesh` | 是 | 网格来源 | 5 |
| `materials` | 是 | 本构模型，按名字定义 | 6 |
| `sections` | 是 | 截面 = 几何 + 材料 | 7 |
| `reinforcement` | 否 | 按图纸坐标布置的钢筋几何 | 7.4 |
| `assign` | 是（实体网格只有一个 `solid` 截面时可省，它指派给整个网格，`vfife init` 就这样写） | 把截面指派给区域或钢筋 | 7.5 |
| `regions` | 否 | 自定义节点集 | 8 |
| `constraints` | 否 | 位移约束与强制位移 | 9.1 |
| `loads` | 否 | 荷载 | 9.2 |
| `amplitudes` | 否 | 幅值曲线 | 9.3 |
| `nodal_masses` | 否 | 附加集中质量（可定向、无重量、带转动惯量） | 9.5 |
| `hydrodynamic_mass` | 否 | 水下构件的动水附加质量 | 9.5 |
| `diaphragms` | 否 | 刚性楼板 | 9.6 |
| `steps` | 否 | 分析步序列 | 10.1 |
| `removals` | 否 | 定时移除构件 | 11.10 |
| `contact` | 否 | 刚性接触面 | 11.12 |
| `response_spectrum` | 否 | 在结束状态上做反应谱分析 | 11.8 |
| `solver` | 是 | 求解器设置 | 10 |
| `output` | 否 | 结果文件、字段、监测量 | 12 |

**建模的一条规则**：有物理的东西是截面（`sections`），有位置的东西是几何或区域
（`mesh`、`reinforcement`、`regions`），两者只在 `assign` 里相遇。这与 Abaqus、OpenSees
的"材料–截面–指派"结构相同；钢筋作为独立几何，改网格密度不影响钢筋。

**格式版本与旧写法**（1.0 版）：

* `version: 1` 声明算例用的是第 1 版格式。1.x 的 vfife 只加字段、不删不改语义，
  所以写了 `version: 1` 的算例在以后的 1.x 上都能读。不写 `version` 的与 `version: 1` 按同样的规则读；
  写了比程序认识的更大的数，会被拒绝并说明原因（那是更新的 vfife 写的）。
* 同一个量只有一个名字。截面上几个旧写法仍然读，preflight 给 `DEPRECATED_FIELD` 警告：
  `b` → `width`、`h` → `height`、`d` → `diameter`、纤维截面的 `torsion_constant` → `j`。
  材料仍读其参数的几个别名（`fc` 即 `fpc`、`E0` 即 `E`、`yield_strength` 即 `Fy` 等，清单见 docs/YAML参考.md 第三部分）；
  与正名同时写出且数值不同则拒绝（`MATERIAL_ALIAS_CONFLICT`，1.0 版——此前本构只取正名、把别名悄悄丢掉）。
* `python -m vfife migrate case.yaml --in-place` 把一个 0.x 算例改成第 1 版：
  * 在原文里就地改名、加上 `version: 1`，注释、排版、数字写法都不动；
  * 改写前后各降解一次，逐字段比较，模型不同就拒绝写出。
* 更旧的格式（顶层 `element:` / `material:` / `members:`）不再直接读，也用 `migrate` 改写成
  `materials / sections / assign`，同样检查改写前后是同一个模型。
* 用 materials / sections / assign 写的算例不能再写 `element`、`material`、`members`、`blocks`
  （旧格式的键），会报 `INTERNAL_KEY_IN_INPUT_FORM`；单元由截面和网格决定。
* 结果文件（HDF5）带 `result_schema_version`（现为 3，1.0 版）。检查点是结果旁单独的
  `<结果>.ckpt.h5`，带 `checkpoint_format`（现为 1）。比程序认识的更新的结果或检查点会被拒绝
  （`RESULT_TOO_NEW`、`CHECKPOINT_TOO_NEW`）；更旧的、没有这个属性的照样读。
  `tests/data/result_format_2/` 存着一份格式 2 的结果，以后每个版本都必须读得了它。
  完整布局见 docs/result_format.md。

**单位**：程序不换算单位，全部数值必须属于同一个一致的单位制（推荐 m、N、Pa、kg、s）。
`units` 声明之后，preflight 会用材料的波速检查量级，mm/t/MPa 的数混进 m/N/Pa 的算例会在
运行前被发现（`UNIT_MAGNITUDE`）。声明本身也检查：拼错的键（`UNITS_UNKNOWN_KEY`，1.0 版起为错误）、应力单位
不等于力/长度²（`UNITS_INCONSISTENT`，如 `{length: mm, force: N, stress: Pa}`）、重力加速度
不是所声明长度单位下的 g（`GRAVITY_MAGNITUDE`，毫米制里 g 是 9810）。

**带单位的默认值**（1.0 版）按 SI 给出，算例声明了非 SI 的 `units` 时**换算到声明的单位**；不写 `units` 或声明
SI 时按 SI 用。它们是：车辆的 `gravity`（9.80665 m/s²，mm 下 9806.65）、`hydrodynamic_mass` 的水密度 `density`
（1025 kg/m³，即 1.025e-9 t/mm³）、箍筋模量 `E`（2e11 Pa，即 2e5 MPa）、路面谱的 `n0`/`n_min`/`n_max`（周/长度单位），
以及材料的默认值：`rho`、`concrete01`/`concrete02` 的 `fpc`、`steel02` 的 `E` 与 `Fy`、`steel_cyclic` 的 `E` 与牌号的
`fy`/`fu`、`bond_ceb` 与 `bond_cyclic`（同一 MC2010 包络）的 `tau_max` 与滑移值。一致的质量单位是 力 × 时间² / 长度（mm/N/s 下为吨），应力单位是
力 / 长度²。声明了 `stress` 而缺 `length` 或 `force` 时，由另外两个推出第三个：`{force: N, stress: MPa}` 按 mm 读，
`{length: m, stress: kPa}` 按 kN 读（`UNITS_INFERRED`，INFO），量级检查（`GRAVITY_MAGNITUDE`、`UNITS_INCONSISTENT`、
`UNIT_MAGNITUDE`）按补全后的单位制做；推不出已知单位（`{force: kN, stress: MPa}` 对应 31.6 mm 的长度）或只写了
`stress`（`Pa` 除外）时，preflight 拒绝该算例：`UNITS_INCOMPLETE`（ERROR）指出缺哪个键。其余情况下声明里没写的键按 SI（m、N、s）。preflight 列出它换算过的每个默认值（`UNIT_DEFAULT_CONVERTED`，INFO）；
声明的单位是它换算不了的时，该默认值保留 SI 并给出警告（`UNIT_DEFAULT_SI`）。1.0 版之前它们不论声明什么一律是 SI：mm 算例里
车辆只有千分之一的重量。

## 5 网格

### 5.1 四种来源

```yaml
mesh: {type: box, dimensions: [2.0, 0.2, 0.3], divisions: [24, 4, 8]}   # 结构化六面体
mesh: {type: gmsh, path: beam.msh}                                      # Gmsh 文件
mesh: {type: abaqus, path: part.inp}                                    # Abaqus .inp 子集
mesh: {type: lines, points: {...}, lines: {...}}                        # 线单元网格，写在算例里（5.4）
```

* `path` 相对于算例文件
* `scale` 乘所有坐标：`scale: 0.001` 把按毫米建的网格换成米
* 单元类型由网格决定：Gmsh 的四面体、六面体、楔形、金字塔（含二次单元）、四边形/三角形
  面单元、两节点线单元
* Abaqus `.inp` 只读节点、所支持的实体与线单元、NSET/ELSET；材料、截面、荷载仍写在 YAML 里

### 5.2 物理组

Gmsh 的 `Physical` 组（体、面、线、点）读进来就是同名区域，可在 `region:` 中直接使用。
**没有物理组的网格没法施加边界条件**；面的编号不要靠猜，用 `vfife mesh` 看每个组选到了
哪些节点、坐标范围是多少。

物理组同时记住它包含的**单元**：一根柱的两个节点也属于梁时，按节点无法区分柱和梁，按物理组
的单元可以。物理组按（维数, 编号）区分：`Physical Volume(1)` 和 `Physical Surface(1)` 是两个组。

读网格时直接拒绝、并说明原因的几种文件：参数化节点坐标（`MESH_PARAMETRIC_NODES`）、
重复的节点编号（`MESH_DUPLICATE_NODE_TAG`）、单元引用了不存在的节点（`MESH_UNKNOWN_NODE_TAG`）、
三角形与四边形混用的壳（`MIXED_SHELL_ELEMENTS`）。只有三角形的网格按壳读。算例 `regions:`
里的名字不能和网格物理组重名（`REGION_NAME_CLASH`）；`type: box` 的网格不接受 `scale`。

### 5.3 从网格生成算例骨架

```bash
python -m vfife init beam.yaml --mesh beam.msh --fixed-region left --load-region tip --load 0 0 -5000
```

生成的算例带一个加载区域的位移监测和一个支座反力监测，改材料、改荷载后即可运行。

**Midas Civil 的施工阶段模型**（`.mct`）也从这里进来：`vfife init bridge.yaml --mesh model.mct` 写出算例、线网格
`bridge.msh` 和对照表 `bridge.map.json`（Midas 的节点、单元各成了哪一个，每个区域是什么）。梁单元按 Midas 截面的尺寸算出
面积、惯性矩和扭转常数（圆管、实心圆、箱形、H 形、双槽钢），桁架单元成为 `bar` 并带上它的初拉力，支承、刚性连接
（成为很刚的无重梁）、自重、节点荷载和均布梁荷载，以及每个施工阶段一个分析步。单位一律换成 m 和 N。它会列出没带过来的
东西（板单元、温度、组合截面的后期部分等）和做了近似的地方。索的初拉力写成 `jack`：在建索的那一步张拉到给定的力（Midas 的"体外力"）；
一根索若分成几个单元越过滑动索鞍，只张拉通向新建结构的那一个，其余按长度装（`prestress`），在报告里计数。弹性连接成为连接器：
弹簧按全局坐标轴写（与 Midas 一致，不随两端转动），在两端都有东西托住的第一个阶段建立、无应力出生；只有索和连接到达的节点，
连接的转动刚度被提高，让节点随连接转动。`vfife mesh model.mct`
只读不写，给出模型的摘要。

1.15 起还转换：文件给出的截面特性（`*SECT-PSCVALUE`、VALUE 和变截面、`*TS-GROUP` 上的变截面）及其剪切面积——知道剪切面积的梁
是 Timoshenko 梁，与 Midas 一致（`convert(..., shear=False)` 为 Euler 梁）；节点不在形心的截面（偏心 CT/CB：构件放在形心线上，
用刚臂连到画图的节点，该节点的行仍给出 Midas 在那里报的位移）；主从刚性连接（`*RIGIDLINK`）；点弹簧（`*SPRING`）；节点局部
坐标系（`*LOCALAXIS`，绕 Z 转：其中的导向支座）；以及**预应力钢束**（`*TDN-PROPERTY`、直线或单元参考线上二维线形的
`*TDN-PROFILE`、`*TDN-PRESTRESS`）：钢束是用刚臂粘结在主梁上的杆，在张拉它的阶段（其荷载组已激活、其单元已建成）张拉到
扣除摩擦和锚具回缩后的力，之后是普通的杆：随后各阶段随主梁一起缩短，并把它的刚度加到截面上。两端张拉的钢束，两端的锚具回缩
联立计算（不动点在两端回缩相遇处，短束即 JTG D62 的 l_f > l/2）。1.16 起，`*TDN-PROPERTY` 声明松弛（规范法）的钢束按该规范
松弛：每根杆按自己锚固后的应力得到松弛曲线（来自 `vfife.codes`，见 11.3 节），有这类钢束的施工阶段模型在每个阶段之后跑该阶段的
天数（`to_age` 时间步；对照表的 `stage_steps` 给出每个阶段结束的步，Midas 的阶段结果就在那一步）。不考虑徐变和收缩。
短桩（短于回转半径 0.05 倍且刚度超过 1e13 N/m 的构件）成为刚性连接器。`convert(..., cases=("风",))` 把成桥后的一个荷载工况
作为再加的一步。对照表的 `tendons` 给出每根钢束的阶段、张拉力、各段杆的区域和力。在六座真实的桥上与 Midas 对照，两边模型
相同的地方位移和内力相差约 1%（1.15 版）；在一座 132 束钢束、悬臂施工的连续刚构上，计入松弛后钢束合力相差 1%，恒载内力
（成桥恒载弯矩）相差 0.2%。只比 Midas 的恒载时，对照中不带钢束的位移比 Midas 大 6%，把钢束作为不张拉的杆放进去后大 3%
（转换出的模型本来就带着钢束，作为粘结的杆）。看来 Midas 把灌浆后的钢束计入了主梁截面（换算截面）：用 Midas 自己输出的弯矩、
剪力和它自己的毛截面特性手算积分，不带钢束的转换与之相差 0–3%，而 Midas 本身比手算刚 1–6%，并随悬臂上的钢束增多而增大。
剩下的 3% 里，约 1% 是这里的荷载略重（反力大 0.4–0.7%，悬臂弯矩大约 1%），约 2% 最可能是截面里的普通钢筋——Midas 可能也计入了
（未证实），本转换不读。钢束偏心大 1–3% 很可能是同一原因的另一面：换算截面的形心更靠近钢束（只是估算，没有单独验证；1.16 版）。

`init` 写的是实体截面，只接受体单元网格：壳网格或线网格会被拒绝，并告诉你该手写什么截面（壳写
`shell` 截面和 `thickness`，线写 `bar`/`beam`/`fiber`/`connector`）。实体网格旁带有 Line2 单元时
会给出警告：这些单元只作为物理组的节点集读入，要当杆件算，须加 `bar` 截面并在 `assign` 里指派到
它们的物理组。目标文件已存在时拒绝写，加 `--overwrite` 才覆盖；目标是网格文件本身时一律拒绝。
交互运行时给了 `--fix` 就不再问固定支座，给了 `--force` 就不再问荷载。提示时只列出边界大小的物理组；
`--fix`、`--force`、`--fixed-region`、`--load-region` 可以写任何物理组，包括整个体（如 `--fix body 010`
约束所有节点的 y）。网格只有体组时须用这些选项给出区域。

### 5.4 在算例里写线单元网格：`type: lines`（1.1）

桥梁的杆系模型是几十个点和它们之间的构件。不必再写 Gmsh 脚本、导出 .msh，可以直接写在算例里：

```yaml
mesh:
  type: lines
  points:                                  # 命名的点；每个名字是只含该节点的区域
    A: [0.0, 0.0, 0.0]
    B: [40.0, 0.0, 0.0]
    C: [80.0, 0.0, 0.0]
    P: [40.0, 0.0, -15.0]                  # 墩底
  lines:                                   # 命名的构件组；名字是这些构件和它们节点的区域
    girder: {through: [A, B, C], size: 2.0}          # 每段按 2 m 左右划分
    pier:   {through: [P, B], divisions: 6}
    arch:   {through: [A, C], divisions: 24, arc: {rise: 12.0}}    # 抛物线拱，矢高 12 m
assign:
  - {region: girder, section: box_girder, orientation: [0, 0, 1]}
  - {region: pier,   section: pier_rc,    orientation: [1, 0, 0]}
constraints:
  - {region: P, dofs: [1, 1, 1, 1, 1, 1]}
```

* `through` 列出依次经过的点（`points` 里的名字，或直接写坐标），相邻两点之间是一段；每段分成
  `divisions` 个单元，或写 `size`（单元目标长度，分成 ceil(段长 / size) 个；曲线按弧长算）；都不写时为 1 个。
* **生成的就是一个 Gmsh 线单元文件读进来的样子**：一个 Line2 块，每个点、每条线各是一个区域，每条线
  另是一个单元组（供 `assign` 按单元区分梁和柱）。`assign`、约束、荷载、监测量、`regions:` 里的
  union 的用法与 Gmsh 物理组相同；把 case_03、case_22 的 .msh 改写成 `lines` 后，计算结果与原来一致。
* **命名的点就是节点**：经过同一个点的线在那里相连，别处不相连。两个节点落在同一位置会被拒绝
  （两个命名点重合；一条线叠在另一条线的一段上；一条线按坐标接到另一条线的分段节点上），两根构件连着同一对节点也会被拒绝。
  支座两侧写成两个错开一点的点，中间用连接器。直接写的坐标落到该位置已有的点上。
* **几条线合成一组**：`groups: {main_girder: [span1, span2, span3]}` 是一个**单元**区域，和 Gmsh 里由几段组成的
  物理组一样，可用于 `assign` 和 `removals`。`regions:` 里的 union 只是节点集：两端节点都在其中的构件都算进去，
  不管它属于哪条线——给吊杆组按 union 设移除会把主梁一起拿掉。主梁的一跨要单独指派截面时，把各跨写成线，再用 `groups` 合起来。
* `arc: {rise, shape, up}`：两点之间画成曲线。`shape: parabola`（默认，节点沿弦等分，拱轴常用）或
  `circle`（按圆心角等分），矢高 `rise` 在弦中点沿 `up`（默认整体 +z）量。
* 坐标按算例的长度单位写，不接受 `scale`。点、线、组重名，用 `all`、`surface` 作名字，`through` 里引用未定义的点，
  某个点不在任何线上，都会被拒绝（`LINE_MESH`）；算例 `regions:` 里的名字不能和点、线、组重名（`REGION_NAME_CLASH`）。
  `size` 决定段内单元个数，抛物线的节点仍沿弦等分（两端单元稍长）。
  这种网格只含线单元；带壳或实体的模型仍用 Gmsh。

### 5.5 从场景模板开始：`vfife new`（1.2）

```bash
python -m vfife new --list                     # 列出模板
python -m vfife new girder my_bridge.yaml      # 写出一个能直接运行的算例
python -m vfife info my_bridge.yaml
python -m vfife run my_bridge.yaml
```

| 模板 | 内容 | 接着可以做 |
|---|---|---|
| `girder` | 30 + 40 + 30 m 三跨连续钢箱梁，自重加 60 kN/m 二期恒载（带质量） | `run`（静力）、`summary`、`modal` |
| `pier_on_piles` | 12 m 墩立在 25 m 桩上，桩周 p–y 土弹簧，墩顶竖向反力与 500 kN 水平推力 | `run`、`summary`、`buckling` |
| `arch` | 80 m 跨、16 m 矢高的抛物线钢拱肋，拱脚固结，50 kN/m 桥面荷载 | `run`、`buckling`、`modal` |
| `cable` | 100 m 间距、102 m 长的索在自重下下垂（动力松弛找形） | `run`、`summary` |

* 模板都用写在算例里的线网格（5.4），带注释；写出时第一行指向 `vfife.schema.json`，并在旁边写出这个文件（编辑器补全）。
* 截面、荷载、土的曲线都是示意值，改成自己的再用。每个模板都有测试：写出、`check`、运行，`summary` 的反力校核等于 1。
* 目标文件已存在时拒绝写，加 `--overwrite` 才覆盖。

## 6 材料

材料在 `materials:` 下按名字定义，`type` 选本构。`python -m vfife describe <材料名>` 列出
该材料的全部参数、状态变量、输出字段、支持的后端与分析模式；`python -m vfife capabilities`
查询单元–材料–后端的可用组合。

### 6.1 三维材料（实体、壳、梁）

| type | 用途 | 主要参数 |
|---|---|---|
| `linear_elastic` | 线弹性 | `E, nu, rho` |
| `orthotropic` | 正交各向异性弹性 | `E1..E3, nu12, nu13, nu23, G12..G23, rho` |
| `viscoelastic` | 线性粘弹性（Prony 级数，仅动力） | `E, nu, rho, g, tau` |
| `j2` | von Mises 塑性，等向/随动强化 | `E, nu, rho, yield_strength, hardening, kinematic` |
| `chaboche` | 循环塑性（非线性随动 + 等向）与损伤 | `yield_strength, Q_inf, b, C1, gamma1, C2, gamma2`、损伤参数 |
| `cdp` | 混凝土损伤塑性（与 Abaqus CDP 同一模型） | `E, nu, rho, compression, tension, dilation_angle, Kc, wt, wc, crack_band` |

`cdp` 的受压、受拉曲线可按规范生成（如 `compression: {source: gb50010, fc: 44.0e6}`、
`tension: {source: fracture_energy, ft: 3.42e6, Gf: 140}`），也可给 Abaqus 格式的表；
`crack_band` 做裂缝带正则化，使软化段与网格尺寸无关。详见 `docs/concrete.md`。

### 6.2 单轴材料（纤维、钢筋、杆）

| type | 用途 | 主要参数 |
|---|---|---|
| `concrete01` | Kent–Park 混凝土，不计受拉 | `fpc, epsc0, fpcu, epscu` |
| `concrete02` | 带受拉软化的 Yassin 混凝土（OpenSees Concrete02 的同一模型） | `fpc, epsc0, fcu, epscu, rat, ft, Ets` |
| `steel02` | Menegotto–Pinto 钢材加 Filippou 等的各向同性强化（OpenSees Steel02 的同一模型），可设断裂应变 | `E, Fy, b, R0, cR1, cR2, a1..a4, rupture_strain` |
| `steel_cyclic` | 循环钢材，含低周疲劳断裂准则 | `grade, fy, fu, ...` |
| `rebar` | 双线性钢筋，等向/随动强化 | `E, yield_strength, hardening, kinematic_fraction, rupture_strain` |
| `piecewise_uniaxial` | 分段线性拉压曲线 | `tension, compression, hardening_mode` |

混凝土强度参数按正值输入（如 `fpc: 40.0e6`），与自带算例一致。`steel02` 的 `rupture_strain` 给出后，纤维应变达到它时该纤维断裂、
不再承力（损伤类别 4），这是模拟断丝的方式。

### 6.3 粘结材料

`bond_ceb`（CEB-FIP/MC2010 粘结–滑移曲线）与 `bond_cyclic`（带损伤累积的循环粘结）用于
嵌入钢筋的粘结滑移（第 7.4 节 `bond`）。

### 6.4 时间相关性质

写在材料里，与本构独立：

```yaml
materials:
  concrete:
    type: linear_elastic
    E: 3.87e+10
    nu: 0.2
    rho: 2450.0
    creep:     {model: mc90, notional_size: 480.0, rh: 75.0, fcm: 63.0e+6}
    shrinkage: {model: mc90, notional_size: 480.0, rh: 75.0, drying_start: 7.0}
    ageing:    {s: 0.25, of: modulus, reference_age: 28.0}
    thermal_expansion: 1.0e-5
```

* `creep`、`shrinkage`、`ageing`：徐变、收缩、弹模随龄期增长，见 `docs/creep.md`
* 预应力钢筋的 `relaxation`：幂函数或实测曲线两种形式，**系数必须由用户给出出处**，
  程序不内置规范公式（原因见 `docs/creep.md`）
* 各时间效应规格在建材料时逐键检查，模型不读的键（如把 `rh` 写成 `RH`）按名字拒绝。
* `mc90` 的徐变系数以 28 天弹模为参考：J(t,t0) = 1/Ec(t0) + φ/Ec28。材料有 `ageing` 时由它换算
  Ec(t0)/Ec28；没有 `ageing` 时须在 `creep` 里给 `E28`（Pa），此时 `E` 是加载龄期的弹模；两者都没有
  或都给，按名字拒绝。**已知局限**：用 `ageing` 而不是 `E28` 时结果仍偏低约 2%——龄期方案按一个系数
  缩放整个刚度，弹性部分从 1/Ec(t0) 漂向 1/Ec(t)；给 `E28` 时得到的正是 MC90 的值。`cement`
  （4 慢硬、5 普通、8 快硬高强）按 MC90 调整加载龄期；`rh` 限 40–100，`fcm` 以 Pa 计，取 20–88 MPa
  （MC90 的 C12–C80），超出即拒绝。
* `aci209` 徐变乘以加载龄期系数（`curing: moist` 为 1.25 t0^-0.118，`steam` 为 1.13 t0^-0.094），
  每个增量按自己的加载龄期计算；`ultimate` 不含这一系数。
* `mc90` 收缩在 RH ≥ 99% 时为湿胀（β_RH = +0.25，构件伸长）。
* `curve` 表隐含原点 (0,0)：从 0 到第一行之间按时长线性增长。
* 松弛的 `rho_1000` 与曲线中的损失都是小数（3.1% 写 0.031，范围 0–0.2）；`tensioned_at` 不得晚于
  分析开始的龄期，缺省为 `solver.age`（若第一步的 age 更早则取之）；由 `initial_state` 续算时保留原
  张拉龄期。除纤维截面预应力筋外，指派到命名区域、带 `prestress` 或 `unstressed_length` 的杆也计算
  松弛；同一材料既用于预应力杆又用于梁时，只有预应力杆松弛；材料的构件中没有一根带预应变时，按名字拒绝。
* `thermal_expansion`：线膨胀系数（1/K），温度荷载需要它（第 11.4 节）

## 7 截面与指派

截面是"几何 + 材料"，是被指派的对象。

### 7.1 截面类型

| type | 需要 | 对应单元 |
|---|---|---|
| `solid` | `material`；可选 `formulation`（`b-bar`、`full`、`reduced`、`selective`）、`hourglass_coeff` | 由网格决定的实体单元 |
| `shell` | `material`、`thickness`；可选 `shear_correction`、`drilling_factor` | `shell4` / `shell3` |
| `beam` | `material`，`shape` 或直接给 `area, iy, iz, j`；`theory: timoshenko` 另给 `ay, az` | `beam2` / `beam2_timoshenko` |
| `bar` | `material`；`shape: circle`（`diameter`）或 `shape: general`（`area`） | 线区域上为 `truss2`；在 `reinforcement` 上为嵌入钢筋 |
| `fiber` | 见 7.2 | `beam2_fiber` |
| `connector` | `stiffness`（六个分量）和/或 `connector_damping`、`curves` | `connector2` |

梁截面形状：`circle`（`diameter`，可带壁厚 `t`）、`rect`（`width`、`height`，可带 `t` 为箱形）、
`I`（`bf, tf, hw, tw`）、`box_girder` 与 `t_girder`（按图纸尺寸，见下文 7.2）、`general`（直接给积分量）。显式给出的积分量覆盖由形状算出的值。

实体网格上可以有多个 `solid` 截面（材料分块）：指派按顺序执行，后面的覆盖前面的，所以先指派
整体、再指派局部。一个单元属于"其全部节点都在区域内"的那个截面。

### 7.2 纤维截面

```yaml
sections:
  rc:
    type: fiber
    material: concrete          # 默认纤维材料
    shape: rect                 # rect | tube | box | patches | box_girder | t_girder
    width: 0.25
    height: 0.35
    ny: 8
    nz: 8
    integration: lobatto3       # gauss2（默认）| lobatto3 | lobatto4 | lobatto5
    j: 1.2e-3                   # Saint-Venant 扭转常数，箱梁务必给
    bars:
      - {y: 0.09, z: 0.14, section: bar20}
      - {y: -0.09, z: 0.14, section: bar20, count: 2}   # count：几根同样的筋并在一点
```

* `rect`：均分 `ny × nz`；`tube`（圆管：`diameter, t, nt`）；`box`（矩形管：`width, height, t, ny, nz`）
* `patches`：任意四边形拼成的截面，每块 `{corners: [[y, z] × 4], ny, nz}`，可带圆孔
  `holes: [[y, z, r], ...]`。箱梁、T 梁、空心板都用它。**坐标原点就是构件轴线**，
  要放在形心上需自己先算
* `j`（旧写法 `torsion_constant`）：不给时用极惯矩 Iy + Iz，对箱梁偏大数倍（杭州湾箱梁：Bredt 公式
  29.5 m⁴ 对极惯矩 150 m⁴），扭转和振型会明显偏刚
* `integration`：沿构件的积分点。Lobatto 含端点，构件端截面先屈服时更准
* `cover`、`core_material`：保护层与约束核心用不同材料（`cover` 须与 `core_material` 同用）
* 纤维截面不读的键按名字拒绝（如 rect 上的 `nt`、`t`，tube 上的 `width`）；patch 只读 `{corners, ny, nz, material?, holes?}`，
  钢筋只读 `{y, z, section, count?}`——钢筋面积和材料来自它引用的 bar 截面
* 一个模型可以有多个纤维截面，各自指派到自己的区域（如变截面墩的每一段）
* 质量与重量：每根纤维按其自身材料的密度计重、计惯性——混凝土纤维、钢筋与预应力束，各截面、各 patch 各用自己的材料（1.0 版）。此前纤维构件一律用第一个纤维截面保护层材料的密度乘整个面积。`vfife info` 打印模型总质量与重量，请与支反力之和对照。
* `shear_stiffness`：构件剪切柔度（弹性，纤维看不到剪切）
* `shear`：**开裂剪切律**（1.0 版），与 `shear_stiffness` 二选一：

  ```yaml
      shear:
        direction: z                 # 剪力沿截面高度（绕 y 弯曲的平面）；或 y
        stiffness: 1.25e9            # 未开裂 κGA（N）
        stirrups: {area: 2.0e-4, spacing: 0.125, depth: 0.35, E: 2.0e+11}   # 或 cracked_stiffness: 9.8e7
        cracking: flexural           # 构件混凝土第一次弯曲开裂时剪切随之开裂；或给一个剪力（N）
        # yield_force: 3.0e+5        # 可选：箍筋屈服，之后刚度乘 hardening（默认 0.01）
  ```

  * 剪切与纤维的弯曲**串联**：构件多一个剪切转角 γ，满足 M_i + M_j = L·V(γ)。
    弹性时就是 Timoshenko 构件（对 PL³/3EI + PL/GA 到 1e-8）。
  * 开裂后刚度可以直接给，也可以给箍筋，按 45° 桁架模型算：
    GA_cr = ρ_v/(1 + 4nρ_v)·E_s·b_w·d（Park & Paulay 1975）。
  * 开裂后卸载、再加载都沿指向原点的割线。
  * 只走 NumPy 后端（`backend: numba` 会被拒绝）。
  * 不是 MCFT：剪切不与轴力、弯曲的应变场耦合，纤维看不到剪应力。

纤维截面的其余选项（预应力束、断裂、应变渗透）见第 11 章和 `docs/fiber_beam.md`。

#### 箱梁、T 梁与成排的钢筋（1.2）

按图纸尺寸写梁。同一个 `shape` 用在 `beam` 截面上时由外形积分出截面性质，用在 `fiber` 截面上时外形变成 `patches`，因此同一根梁的梁模型与纤维模型 A、Iy、Iz 一致；20 m 悬臂端部受力，纤维模型的挠度比梁模型大 0.3–0.5%（纤维网格的 Iy 偏小这么多），扭转相同。宽桥面的横向振型差得多一些（12 m 桥面：15.0 Hz 对 15.8 Hz），因为纤维单元计入了截面的转动惯量，梁单元没有。

```yaml
sections:
  deck:
    type: fiber                  # 或 beam
    material: c50
    shape: box_girder
    height: 2.5                  # 桥面顶到底板底
    top_width: 12.0              # 桥面全宽，翼缘尖到尖
    bottom_width: 6.0            # 底板外宽
    cantilever: 2.5              # 翼缘尖到腹板外侧面，在桥面顶量（0：无悬臂）
    top_thickness: 0.25
    bottom_thickness: 0.22
    web_thickness: 0.45          # 斜腹板按水平方向量
    cantilever_thickness: [0.5, 0.2]   # 根部、尖端（默认 top_thickness）
    top_haunch: [0.6, 0.2]       # 箱内顶部承托 [宽, 高]（可选）
    bottom_haunch: [0.3, 0.15]   # 可选
    # cells: 2                   # 箱室数；中腹板竖直，均分在两外腹板之间
    # layers: 3                  # 纤维截面：每块板沿厚度的纤维层数（默认 3）
    # fiber_size: 0.3            # 纤维截面：沿板长方向的纤维最大尺寸（默认 height/8）
    # origin: centroid           # 纤维截面：centroid（默认）| top | bottom
    bar_layers:
      - {section: d16, from: [-5.9, 0.05], to: [5.9, 0.05], spacing: 0.15, z_from: top}
      - {section: d25, from: [-2.8, 0.06], to: [2.8, 0.06], count: 24, z_from: bottom}
```

* 腹板从底板角点直线连到距翼缘尖 `cantilever` 处；`bottom_width` 小于 `top_width − 2·cantilever` 时腹板外倾。
* `shape: t_girder` 读 `height, top_width, top_thickness`（翼缘在腹板处的厚度）、`web_thickness`、`cantilever_thickness: [top_thickness, 尖端]`（变厚翼缘；根部不等于 `top_thickness` 时拒绝），给 `bottom_width` + `bottom_thickness` 即有下翼缘（工字梁或带马蹄的 T 梁）。
* **原点**：截面原点即构件轴线穿过的点，默认是形心；纤维截面可写 `origin: top` 或 `bottom`。钢筋和预应力束的坐标都相对它；形心位置不必自己算，钢筋用 `z_from` 从上下缘量即可。钢筋必须在板内（梁的外形是精确的，不享有手画 patch 截面的 1% 容差）；预应力束还可以穿过箱室（体外束）。梁截面总是对形心，写 `origin` 会被拒绝。轴线偏离形心时，单元的线性轴向场与三次弯曲场会耦合：端部受力，2 m 单元偏刚 0.11%，1 m 单元 0.02%。
* **扭转与剪切（梁截面）**：箱梁的 `j` 按壁中线的 Bredt 公式，多室箱按各室剪力流方程求解，再加悬臂的 ∫t³dy/3；壁厚时偏小几个百分点（12 m 箱梁有限差分解为 12.5–12.8 m⁴，Bredt 为 12.19）。T 梁、工字梁的 `j` 直接在外形上解 Saint-Venant 问题（Prandtl 应力函数的有限差分，误差 1% 以内）；按矩形相加会低 11–26%。纤维梁用同一个 `j`（而不是极惯矩）。`az` 取腹板面积乘其倾角余弦的平方，`ay` 取顶底板面积（T 梁取翼缘面积的 5/6）。这些是手算值；给 `j`、`ay`、`az`（或 `area`、`iy`、`iz`）即覆盖。
* **纤维数**：单室箱梁默认约两百根（case_24d 的杭州湾箱梁用了 166 根）。
* **`bar_layers`**（凡能放钢筋的纤维截面：rect、patches、两种梁）：每排为 `{section, from: [y, z], to: [y, z], count 或 spacing, z_from}`。两端都放；`count: 1` 放在中点；`spacing` 取不大于该间距的等间距（d16@150 布满 11.8 m 是 80 根）。`z_from: top` 从上缘向下量 z，`bottom` 从下缘向上量，`origin`（默认）即截面坐标。成排钢筋展开成 `bars`，同样检查是否在截面外形以内。
* 梁的参数写在别的形状上，或写了该形状不读的键（箱梁上的 `width`、梁截面上的 `layers`），都按名字拒绝。

### 7.3 连接器截面

```yaml
sections:
  fixed_pot:
    type: connector
    material: concrete
    stiffness: [5.0e+10, 1.0e+9, 1.0e+10, 1.0e+10, 1.0e+10, 1.0e+7]
```

六个分量依次是局部 ux、uy、uz、rx、ry、rz 的刚度。连接器是两个节点之间的弹簧（可带阻尼），
典型用途是支座。局部方向由指派时的 `orientation` 和 `coordinate_system: local` 决定。
分量上也可以写非线性律（间隙、双线性滞回、摩擦），见 11.11 与 `docs/connector2.md`。连接器截面的
`material` 不参与计算（连接器的本构就是它的刚度与律）；`coordinate_system: global` 的有长度连接器，
两端力留下的力偶按一半一半还给两端（弹簧固定在空间里，刚体转动也会使它变形）。

### 7.4 钢筋几何

实体构件中的钢筋按图纸坐标布置，与网格无关：

```yaml
reinforcement:
  main:     {layer: {from: [0, 0.0443, 0.0443], to: [2.0, 0.0443, 0.0443], count: 3, spacing: [0, 0.0557, 0]}}
  stirrups: {hoop: {corners: [[0.0443, 0.0443], [0.1557, 0.258]], axis: x, from: 0.05, to: 1.95, spacing: 0.075, divisions: 8}}
  tendons:
    path:
      points: [[0.0, 0.09, 0.30], [4.0, 0.09, 0.10], [8.0, 0.09, 0.30]]
      shape: parabola
      segment_length: 0.25
      repeat: {count: 4, offset: [0.0, 0.04, 0.0]}
```

图元：`line`（起终点，可 `repeat`）、`layer`（一排 `count` 根平行钢筋）、`hoop`（沿轴重复的
矩形箍筋）、`lines`（列表）、`path`（折线或抛物线，用于曲线预应力筋）。

### 7.5 指派

```yaml
assign:
  - {region: all, section: body}
  - {reinforcement: [main], section: bar15, segment_length: 0.025, name: tension}
  - {reinforcement: tendons, section: strand12, name: tendons, prestress: 1000.0e+6}
  - {region: beam, section: girder, orientation: [0, 1, 0]}
  - {region: bearing_1, section: fixed_pot, orientation: [1, 0, 0], coordinate_system: local}
```

每条指派针对 `region`（网格上的节点集）或 `reinforcement`（一组或几组钢筋）之一。
指派上的选项属于"这一对"：

* 梁：`orientation`（截面局部 y 轴方向）、`releases`；连接器：`orientation`、`coordinate_system`（连接器没有 `releases`）
* 杆/索：`prestress`、`unstressed_length(s)`（`vfife formfind` 写出）、`tension_only`；`jack`（1.13，按力张拉，单位 N）：在建立这根索的分析步（从头就建的是第一步）里，千斤顶保持的力等于 `jack` 乘以该步的进度，不管结构让了多少；该步结束时索力正好是 `jack`，此后它是一根普通的杆，无应力长度就是那时定下的。`prestress` 说的是长度（网格几何下给出该应力的长度），结构一让力就掉；`jack` 说的是力。四者只能给一个。框架模型（梁、杆、连接器）可用，纤维梁模型拒绝
* 嵌入钢筋：`bond`（粘结滑移）、`segment_length`、`host_deduction`、`anchorage`、`prestress`
  * 嵌入钢筋的质量按它材料的 `rho` 计入惯性，但**不受重力**：`gravity` 只按实体各块的密度积分。习惯上把钢筋混凝土的密度取 2500 kg/m³ 时，钢筋的重量已经算在混凝土里，所以不会重复。如果混凝土取的是素混凝土的密度（约 2400），钢筋的重量就要另用荷载补上。
* 纤维梁：`anchorage: {region, bar_diameter}`（应变渗透）；纤维梁没有 `releases`

截面的 `width` 沿局部 y、`height` 和纤维的 `z` 沿局部 z；局部 y 由 `orientation` 定，默认全局 +Z，所以水平构件默认局部 y 竖直、
局部 z 水平。`vfife info` 打印每个线构件组的局部轴（全局坐标），如
`axes  girder (beam2_fiber, 42 members): local x = +X, local y = +Z, local z = -Y`；矩形或箱形截面（宽不等于高）的 `height` 在水平构件上躺平时，再打印一行 `note`，给出让局部 z 向上的 `orientation`，如 `note  beam: section height 1.2 m lies along local z = -Y (horizontal); if the depth should be vertical, set orientation so local z is up (e.g. orientation: [0, 1, 0])`。patches 截面（y、z 由用户自己画）、圆、管、按 A/Iy/Iz 给的截面、杆和连接器只有 `axes` 一行（1.0 版）。

写了这一对不读的键（纤维截面上的 `releases`、梁上的 `prestress`、索上的 `friction`……）会被拒绝，
并说出键名——这些键过去被接受后丢掉（1.0 版）。截面也一样：梁截面上的 `tendons`、纤维截面上的
`theory` 都会被拒绝。只有一个纤维截面时，它的区域必须包含全部纤维构件；多个截面用多条指派。

未被任何指派覆盖的单元、或一个单元都没拿到的截面，会被拒绝并给出单元号
（`ELEMENTS_UNASSIGNED`、`SECTION_EMPTY`）。

## 8 区域

区域是节点集，约束、荷载、指派、监测都通过区域名引用。三个来源：Gmsh 物理组、内置的
`all` 与 `surface`、以及 `regions:` 下的自定义选择器：

```yaml
regions:
  base:      {plane: {point: [0, 0, 0], normal: [0, 0, 1]}}
  support:   {where: {x: 0.10, z: 0}}                  # 一条线：固定两个坐标
  pin:       {where: {x: 0.10, y: 0.10, z: 0}}         # 一个点
  web:       {where: {y: {min: -0.05, max: 0.05}}}     # 一个坐标范围
  box1:      {box: [0.35, 0.45, 0.0, 0.2, 0.2625, 0.3]}  # xmin xmax ymin ymax zmin zmax
  diagonal:  {line: {from: [0, 0, 0], to: [2, 0, 0.3]}}
  bolts:     {cylinder: {point: [1, 0.5, 0], axis: [0, 0, 1], radius: 0.05}}
  shear:     {intersect: [base, web]}
  ends:      {union: [left_face, right_face]}
  interior:  {difference: [all, surface]}
```

另有 `sphere: {centre: [...], radius: r, rmin: r0}`（`center` 也收）、`group`、`node_ids`、
`nearest`。区域可以引用在它后面定义的区域。`plane`、`line`、`cylinder`、`sphere` 里拼错或缺少
的键会被指名拒绝；`node_ids` 超出节点数也拒绝。

两条要记住的规则：

* **选不到节点的区域是错误**，不是空集——容差稍紧、支座就差一点的模型，看上去和对的一样
* `where` 里的单个数字会**吸附到最近的节点线**上，preflight 报告实际用的坐标
  （`REGION_SNAPPED`）；固定了两三个坐标时，它们一起吸附到同一个节点上

容差默认是网格对角线的 1e-6，同一个文件在毫米和米下都能用。

## 9 约束、荷载与幅值

### 9.1 约束

```yaml
constraints:
  - {region: base, dofs: [1, 1, 1]}                                  # 实体：ux uy uz
  - {region: left, dofs: [1, 1, 1, 0, 0, 0]}                         # 梁：ux uy uz rx ry rz
  - {region: head, dofs: [1, 0, 0], value: 0.010, amplitude: drift}  # 强制位移
```

`dofs` 的长度等于节点自由度数（实体 3，梁、壳 6）。`value` 给强制位移，可随幅值变化；
动力分析中 `motion: velocity | acceleration` 表示给定的是速度或加速度。

在动力松弛下，结构存在未约束的刚体运动是错误（自由体没有平衡位置），preflight 会指出是
哪个运动、需要加哪条约束；动力分析中只作警告。

### 9.2 荷载

每条荷载有一个 `region`（默认 `all`），只给一种荷载量：

| 键 | 含义 | 单位 |
|---|---|---|
| `vector` | 区域上的合力，平分到节点（`per_node: true` 则每个节点各施加这么大） | N |
| `moment` | 力偶（梁节点；或实体面上的定轴力偶，`follower: true` 随面转动） | N·m |
| `line_load` | 沿构件的均布线荷载，默认整体坐标，`coordinate_system: local` 为局部 | N/m |
| `traction` | 外表面上的面力向量 | N/m² |
| `pressure` | 外表面压力（正值向内），`follower: true` 随变形更新方向 | Pa |
| `body_force` | 体力 | N/m³ |
| `gravity` | 重力加速度，乘材料密度 | m/s² |
| `temperature` | 截面温度场（第 11.4 节） | K |
| `moving_load` | 沿构件移动的轴重组（第 11.5 节） | N |
| `ground_motion` | 地面加速度记录（第 11.6 节） | m/s² |

面荷载按实际外表面积分、体荷载按单元体积积分，与节点疏密无关。
单位一栏按 SI 算例写；声明了别的单位制时，各量用该单位制的单位（N/mm、MPa、mm/s² 等）。

### 9.3 幅值

幅值给出荷载或强制位移随**分析步进度**（0 到 1，而不是物理时间）的变化：

```yaml
amplitudes:
  live:    [[0.0, 0.0], [1.0, 1.0]]
  service: {table: [[0.0, 0.0], [0.2, 1.0], [0.8, 1.0], [1.0, 0.0]]}
  drift:   {cyclic: {peaks: [0.333, 0.667, 1.0], repeats: 2}}
```

内置 `ramp`（0→1）、`hold`（一开始就满值）、`ramp_hold`（前半步加满、后半步保持）。
缺省值：分级步用 `ramp`，连续步用 `ramp_hold`。带 `to_age` 的时间步里，未写幅值的荷载和强制位移默认 `hold`（第一个时间站即全量并保持）；要随时间加载须写幅值。表可以超过 1——`[[0, 0], [1, 20]]` 把荷载
推到 20 倍，这是推覆分析的常用写法。

### 9.4 荷载在分析步之间

* 模型级的约束和荷载是"基础"，在第一步里施加、之后一直保持
* 某一步自己的约束和荷载只在该步有效（写 `keep: true` 时以后各步也有效，1.2，见第 10.1 节）；与基础在同一个自由度上冲突时，该步的优先
* 位移、材料状态、断裂在步与步之间完整传递。动力计算里速度也接着传（一个动力分析步是同一条时程的一段，第 10.2 节）；
  松弛或静力分析步从静止开始
* `line_load`（以及任何荷载）默认是力而不是质量：写成 `line_load` 的二期恒载有重量、无惯性。它若是某样东西的重量
  （二期恒载、铺装、栏杆），写 `with_mass: true`（1.1）：带上质量 |q|/g，按构件长度分到两端节点、三个平动方向，
  在时程、模态和反应谱里有惯性；这份质量不再称重（重量就是这个荷载），与 `gravity` 同用不会算两遍；g 取 9.80665 m/s²，
  按声明的单位换算（mm/N 下为 9806.65）。只能写在模型级 `loads` 里；只有平动质量，没有转动惯量。
  ```yaml
  loads:
    - {region: deck, line_load: [0.0, 0.0, -1.2e+5], with_mass: true}   # 二期恒载 120 kN/m，连同 12.2 t/m 的质量
  ```
  不是均布的附加质量仍用 `nodal_masses`（线荷载已计重量时写 `weight: false`），或折入截面密度（第 9.5 节）

### 9.5 附加质量

```yaml
nodal_masses:
  - {region: pier_top, mass: 4.0e+4}          # 平分到区域节点；per_node: true 则每个节点
  - {region: deck, mass: 2.0e+5, components: [1, 1, 0]}   # 只在 x、y 上：附加质量，不称重
  - {region: tower_top, mass: 1.0e+4, inertia: [0, 0, 5.0e+6]}   # 绕 z 的转动惯量 kg·m²
hydrodynamic_mass:
  - {region: piles, diameter: 4.0, coefficient: 1.0, density: 1025, water_level: 0.0}
```

1.0 版起：

* **默认**三个平动方向都有这份质量，重力也看得见它（和以前一样）。
* `components` 让质量只作用在部分平动方向上。定向质量是**附加质量**（水、土、只沿一个方向
  随动的桥面），**没有重量**：`weight` 缺省为 false，写 `weight: true` 会被拒绝——会称重的物体
  在每个方向都有惯性。三向质量也可以写 `weight: false`。
* `inertia` 是绕整体轴的转动惯量，只用于梁、壳（六自由度）；桁架和实体拒绝。
* `hydrodynamic_mass` 是水下构件的 Morison 附加质量：每延米 C_a·ρ_w·A（`diameter` 给圆截面，
  `area` 给其他截面），只算竖向坐标低于 `water_level` 的那一段，按杠杆分给两端节点。
  * 只作用在**垂直于构件**的两个方向上，不称重。
  * 构件轴线与最近整体轴的真实夹角要在 5° 以内（墩、桩）：集中质量是对角的，斜构件的"垂直于轴"写不进去，
    会被拒绝。1.0 版起按真实夹角判断（以前按坐标分量分别判断，两个平面各斜 4.9°、实际斜 6.9° 的构件
    也被接受）。
  * 地震时它和结构质量一起参与 −M·a_g，反应谱的有效质量里也有它。
* 桁架和实体上的节点质量现在也会在 `gravity` 下称重（以前只有梁族会）。

算例 case_37：水中 20 m 圆墩（D = 2 m）顶上 500 t 桥面，反应谱下与闭式解差 0.02%–0.3%。
水让第一周期只长 1.4%（桥面质量主导），第二周期长 18%，基底剪力大 6%；轴向周期不变。

### 9.6 刚性楼板

```yaml
diaphragms:
  - {region: floor_1, normal: z}
```

区域内节点在垂直于 `normal` 的平面内作刚体运动（两个平动加绕法线的转动），平面外仍自由。

模态分析和反应谱也按刚性楼板做（1.0 版起；以前被忽略）：楼板平面内的两个平动和绕法线的转动
由楼板质心处的三个主自由度决定。

## 10 分析步与求解器

### 10.1 分析步

```yaml
steps:
  - name: axial                      # 模型级荷载在这一步加上
  - name: cyclic
    constraints:
      - {region: head, dofs: [1, 0, 0], value: 0.010, amplitude: drift}
    load_steps: 8
    max_steps_per_load: 20000
```

每一步可以覆盖 `n_steps`、`load_steps`、`max_steps_per_load`、`stage_ramp_iterations`、
`tolerance`；`mass`、`backend`、`damping` 属于模型，不能按步改。徐变算例的步还有
`age`、`to_age`（第 11.3 节）。

#### 每步自己的分析类型，构件的出生与移除（1.2）

线单元模型（`beam2`、`beam2_timoshenko`、`mixed_line`、`beam2_fiber`）的一步可以像 Abaqus 的分析步那样改变分析类型和模型：

```yaml
steps:
  - name: span_1
    activate: [span1]                  # 本步出生的构件
    load_steps: 4
  - name: span_2
    activate: [span2]
    birth: tangent                     # tangent（默认）| design
    procedure: static                  # relaxation | dynamic | static；默认 solver.mode
    load_steps: 4
  - name: strike_falsework
    deactivate: [falsework]            # 移除的构件：其作用力在本步内卸掉
    release: [temporary_pier]          # 解除继承的支座：支反力在本步内卸掉
    load_steps: 4
  - name: earthquake
    procedure: dynamic
    total_time: 20.0                   # 动力步的时长；默认 solver.total_time
    loads: [{ground_motion: {path: elcentro.txt, direction: [1, 0, 0]}}]
```

* **`procedure`**：一次计算里可以有松弛步、静力步和动力步。松弛或静力求得的恒载状态交给动力步时是静止且平衡的：不加新荷载，结构不动（测试到挠度的 1e-9）。各类型用各自的设置：松弛步用虚拟质量和 kinetic 阻尼，动力步用物理质量、稳定步长和 `solver.damping`（此时不能是 `kinetic`）。`solver.mode` 为 `static` 的模型每步都是静力。
* **`activate`**：区域内的构件（区域是一组线——Gmsh 的线物理组或 `lines` 的组——时，就是这组线自己的构件，与 `assign` 同义；区域是一个框或一组点时，是两端节点都在其中的构件）在本步之前不存在——没有刚度、质量、重量和线荷载——在本步**于结构已到达的位置无应力出生**：出生那一刻的局部变形（伸长与两端转角）就是它的参考。它的自重和作用在它上面的模型级线荷载在本步内逐渐加上（同 Abaqus 的重新激活），其余荷载保持不变。没有任何已建构件连着的节点各方向固定，不报支反力。
* **`birth`**：只连着新构件的节点放在哪里。`tangent` 让它随最先到达的已有节点做刚体平移和转动——悬臂节段沿端部切线安装。支座约束的平动分量留在支座上（远端墩上的滑动支座；平面约束下其余方向仍随切线），因此在已下挠的墩顶与下一个墩之间浇筑的一跨，出生时无应力但远端有折角——在支架上按图纸浇筑的一跨请写 `design`，节点留在设计坐标。一组新构件若不连着任何已建部分，总在设计坐标上。给了 `prestress` 或 `unstressed_length` 的杆按设计长度安装：一出生就按设计受拉（安装时张拉的斜拉索）；其余构件出生时都无应力。
* **`deactivate`**：移除构件。它们对其余结构的作用（作用在它们上面的荷载——自重与线荷载，取上一步结束时的值——减去它们给节点的内力）作为荷载在本步内卸到零（同 Abaqus 的移除），结构不会感到突变。它们的质量、转动惯量和刚度比例阻尼一并去掉。
* **`release`**：解除这些区域节点上继承下来的约束（模型级的，以及之前步 keep 的）；上一步结束时的支反力在本步内卸到零。本步自己的约束照常施加；之后的步再 keep 的约束重新有效。解除没有任何继承约束的节点会被拒绝。
* 步内荷载或约束写 **`keep: true`**：以后各步保持，取它在本步结束时的值（keep 的约束直到被 `release`）。不写则只在本步有效，与以前一样。
* **后加的支承就地固定**（1.14；梁、杆、连接器和纤维梁）：不带 `value` 的约束，如果固定的是上一步结束时还自由的自由度，就把它固定在当时的位移上——施工时铰接、之后封固的拱脚，顶在已下挠主梁下面的临时支撑——以后各步只要仍被约束（`keep`）就一直在那里。它不把节点带回坐标位置：要把一点顶到某个位置，给约束写上这个 `value`。节点的三个转角都被约束时，转角也按当时的值固定。不变的：从第一步起、或从节点建成那一步起就被约束的自由度，在坐标位置上（支座在哪里就是哪里：新节点直接放在那里；三个转角都被约束时不带转角，新构件在已建一端与支座之间无应力出生）；先被 `value` 推动、再由不带值的约束接手的自由度回到零——它从未自由过。凡是多步的计算都如此，不论有没有 `activate`、`release`、`keep`。1.14 之前这类约束一律固定在零：拱脚会被转回它转过的全部角度。
* **时间轴**：有动力步的计算，结果里的 `time` 是时钟——动力步推进其时长，松弛步和静力步不推进（其帧都在当时的时钟上）。每帧另记 `analysis_step`、`procedure`，以及本帧已建的构件（`member_built`，1 或 0）。
* **各节段自己的混凝土龄期**（框架模型：`beam2`、`beam2_timoshenko`、`mixed_line`；纤维梁自 1.8 起）：在某步出生的构件此时为 `activate_age` 天（默认 `solver.age`），与模型时钟读数无关；此后按自己的时钟徐变、收缩、硬化——φ(t + 偏移, t0 + 偏移)，不记出生之前的任何增量——模板里的收缩不算荷载。验证：时钟 100 天时以 7 天龄期浇筑并加载的杆，到时钟 1000 天伸长 N/EA (1 + φ(907, 7))；28 天加载的杆为 (1 + φ(1000, 28))；当时浇筑的自由杆缩短 (ε_sh(907) − ε_sh(7)) L；后期出生的杆在保持伸长下的松弛，逐个时间站等于按其龄期加载的杆。写在**第一步** `activate` 里的构件在那时出生，不计 `activate_age` 之前的收缩；从一开始就建的构件则带着自干燥起的收缩（1.2 之前的规则）。
* **纤维梁**支持所有模型变更和分析类型。后期出生的纤维构件在出生时的力学状态下无应力，移除后再建的构件从纤维的初始状态开始（新混凝土）；出生时已有的温度不扣除（出生时就带着该温度的约束力），预应力束的预应变也不扣除（出生即起作用）。1.8 起（1.8 版）有徐变或收缩的纤维模型也能改变模型：各节段按自己的时钟徐变、收缩，规则同上一条；律输入上的徐变缩放按构件给（NumPy 参考路径上逐构件设律的 `strain_scale`，融合内核里用它按构件的参数）。框架的几项验证在 concrete02 纤维上同样成立（tests/test_fiber_segment_ages.py）：φ(907, 7) 与 φ(1000, 28)；(ε_sh(907) − ε_sh(7)) L；后期节段保持伸长下的松弛逐站等于按其龄期单独加载的节段，到 1e-6；内核与参考路径一致到 1e-8；后期节段徐变中途停下再续算，逐位相同；在推进时钟的步里出生的节段等于按其龄期单独建模的杆，移除后再浇筑的节段等于只浇筑一次的。未建构件不计入残差的尺度。纤维截面上的龄期（`ageing`）照旧拒绝（非线性律的模量不是一个数）。预应力束会松弛的纤维模型仍不能改变模型。
* **后期出生的连接器**（框架模型，1.13）：与梁、杆一样，建立时在两端所在的位置不受力——那一刻的六个变形就是它的参考——本构的历史从零开始；移除后再建是一个新的。`birth: tangent` 下连接器不带新节点，正在张拉的索也不带：只有它们到达的新节点从模型里的位置开始。
* **暂不支持**（按名字拒绝）：纤维梁模型里后期出生的连接器（请从一开始就建）；壳和实体；有松弛纤维预应力束时改变模型；在移动荷载、车辆、地震动上写 `keep`。（1.16 起，有松弛的预应力杆或张拉杆时可以改变模型：每根杆从出生或锁定起松弛，见 11.3 节。）
* 有动力步的模型里，`solver.damping` 是动力步的（不能是 `kinetic`；此时松弛模型也可以用 Rayleigh 的 `beta`），其中的松弛步用 kinetic 阻尼。混合了分析类型的计算不做能量核算。

与闭式解的对比：两跨等跨逐跨浇筑，R_A = 7/16 wL、R_B = 9/8 wL（一次浇筑为 3/8、5/4）；移除第二跨后 R_A = R_B = wL/2；解除中间支座后两端各为整跨的 wL；悬臂按切线浇筑与一次浇筑终点相同，按图纸浇筑差 w_B + θ_B L。

### 10.2 求解模式

```yaml
solver:
  mode: relaxation          # 或 static（隐式 Newton）、dynamic
  backend: numpy            # numpy | numba | warp
  damping: {type: kinetic}  # 松弛用动能阻尼；动力用 viscous / rayleigh / none
  tolerance: 1.0e-5
```

**动力松弛（`mode: relaxation`）** 求静力平衡：

* 质量是虚拟的（按刚度行和取，`relaxation_safety` 控制），时间步为 1
* **连续**：一步内加载，只报告最终平衡
* **分级**（`load_steps: n`）：荷载分 n 级，每级收敛到 `tolerance` 并输出一帧——要荷载–位移
  曲线必须用分级。每级的迭代上限是 `max_steps_per_load`，每级开始时用
  `stage_ramp_iterations` 次迭代把荷载平滑地加上去

**隐式静力（`mode: static`，1.0 版）** 用 Newton 法逐级求平衡：

```yaml
solver:
  mode: static
  load_steps: 20            # 每步分几级（默认 10）；分析步自己的 load_steps 优先
  tolerance: 1.0e-5
  static: {max_iterations: 30, cutbacks: 10, line_search: true, tangent: full}
```

* 切线是**同一个内力**的有限差分：没有第二套单元刚度。
  * 互不相邻、也没有共同邻点的节点一起扰动（节点图的距离-2 着色）。
  * 一次切线只要 2 × 每节点自由度 × 颜色数 次内力计算，框架一般 36–100 次，与模型大小无关。
  * 转动按自旋扰动、按自旋更新，与显式求解器的共旋公式一致。
  * 1.15 起，梁、杆、连接器组成的模型在 `backend: numba` 下（没有塑性铰、土弹簧、会断的构件和刚性接触面），每种颜色的列只从连着这些节点的构件读出——别的构件内力不变——于是每次切线每个构件只算 24 遍，与颜色数无关；矩阵与全模型内力相减得到的相同到舍入量级。运行日志里会写明用的是哪一种（换回全模型内力相减的 `VFIFE_TANGENT_MEMBERS=0` 在 1.18 去掉了）。
* 每级开始用切线预测（强制位移按 K_fc 分到整个结构，而不是全部堆在受驱节点旁的一个单元里）。
  之后是带回溯线搜索的 Newton；不收敛就把这一级减半重试，但输出帧总落在你给的级上。
  * 监测量每个增量都记，`output.every` 只稀疏输出帧。
  * 不收敛的增量减半重试，但增量不会小于给定增量的 `cutbacks` 次减半；到此仍不收敛即报告为极限点（荷载控制越过峰值时这样结束，不再无限缩小）。
  * 残差的尺度含已收敛状态承受过的最大力（含纤维内力）的百万分之一，只由收敛状态更新，并随检查点续算。
  * 一步自带的 `tolerance` 优先于求解器的。
  * 容差低于舍入误差时报 "Newton stalled … round-off"，而不是极限点：把容差放宽到它给出的值。
  * 无外力的平衡（自由温度弯曲、简支梁温度梯度、只有预应力、后一步释放支座）可以用 Newton 求解。
* 路径相关的材料每次都从上一个收敛点试算，每级收敛后提交一次（与分级松弛相同）。
* 适用范围：框架与纤维梁（beam2、beam2_timoshenko、mixed_line、beam2_fiber）。
  mixed_line 模型里的 truss2 构件也可以；独立的 truss2 模型（`all` 上只有一个 `bar` 截面）会被拒绝（`STATIC_UNSUPPORTED`），请用 `relaxation`。
  壳、实体，以及纤维断裂、塑性铰、开裂剪切律、定时移除、`split: true` 的失效，拒绝并说明原因。1.16 起梁和 mixed_line 模型
  上可以算徐变、收缩、龄期和松弛（带 `to_age` 的步里每个收敛增量是一个时间站点，见 11.3 节），纤维模型和 `arc_length` 下不行。
* **刚性楼板（`diaphragms`）**（1.7）：楼板是一个线性多点约束，Newton 解的是主自由度系统 Tᵀ K T
  （每块楼板三个主自由度：面内两个平动和绕法线的转动，与松弛对加速度施加的是同一个约束）。
  残差按主系统量，楼板节点上的约束力不算不平衡。
* **构件失效（`failure`）**（1.7）：在一个**已接受的平衡**里达到承载力的构件被整根取出（不分裂——碎片没有静力平衡），
  同一级不带它再解一次，再失效再解，直到没有新的失效（备用荷载路径法，一次一根）；失效记在 `member_failures` 里，时间轴是步号加进度。
  取出之后找不到平衡，就报"the structure has lost its load"。定时的 `removals` 没有时钟，用分析步的 `deactivate`。
* **回落到松弛（`static.fallback: relaxation`）**（1.7）：Newton 把增量减半到 `cutbacks` 次仍不收敛时——荷载控制下的极限点，
  或者平衡路径上的跳跃——这一级改用动力松弛从上一个收敛状态算到**所给的级**（虚拟质量、动能阻尼，与 `mode: relaxation` 同一算法，
  每级 `max_steps_per_load` 或 `static.fallback_iterations` 次迭代），**本步余下的各级也都用松弛**，下一步再从 Newton 开始。
  默认 `none`，仍按原来的报错停下（报错里提示这个选项）。一座浅拱被推过极限点：Newton 不带线搜索跨不过去，松弛 784 次迭代到了翻转后的拱，
  Newton 从那里接着往下走（tests/test_static_fallback.py）。
  **跳过去落在哪一支，由这段虚拟的动力过程决定**：在软化截面上它未必是 `mode: relaxation` 走的那支——case_25 从 Newton 的峰后状态回落，
  松弛收到的是一支荷载继续上升到 335 kN、钢绞线应力反而下降的平衡；`mode: relaxation` 在同一级压溃坍塌。两者都是离散系统的平衡，
  契约是按后者写的，所以**四个钢筋混凝土推覆（case_25、25b、30、31）保留松弛**；case_30、31 回落走完时荷载与松弛相差 1.6%，但局部应变差 12–16%。
  开了回落时减半次数的预算按所给的级计，不再每个小增量成功就清零：在下限上爬行的路径说明是在跳跃上，直接回落。
* **哪些算例该用它**（1.5；1.7）：自带算例里能用它的静力算例都改用了它——弹性框架、带支座律的梁、温度、移动荷载影响线、
  开裂前的钢筋混凝土框架（1.5），联邦大桥的车队与温度、杭州湾主梁的恒载与活载（1.7：case_24 74 s → 10 s，case_28 102 s → 1.4 s）——契约不变。
  推过极限状态的钢筋混凝土纤维梁（case_25、25b、30、31 的推覆）保留松弛，原因见上一条；case_16 保留松弛（它是 case_16b 弧长法的对照）。
* **极限点**：荷载控制下的峰值、跳跃找不到平衡，会报出失败的荷载因子。
  要过峰值，用位移驱动，或者用弧长法：

  ```yaml
    static:
      arc_length:
        initial: 0.05              # 第一个增量的荷载因子，据此定弧长
        max_increments: 400
        target_iterations: 4       # 弧长按 sqrt(期望/实际迭代数) 伸缩
        stop: {region: tip, dof: z, value: -0.5}   # 荷载因子到不了 1 时在哪里停
        steps: [live]              # 只对这些分析步用弧长；其余步按荷载控制（不写则每步都用）
        control: {region: tip, dof: z}   # 1.3：弧长只量这一个位移（位移控制，荷载因子是未知量）
  ```

  * 1.0 版。每一步的荷载与强制位移都当作一个模式，荷载因子 λ 成为未知量。
    约束是 Crisfield 柱面弧长 ‖W Δx‖ = Δl，转动按模型尺寸加权。
  * 能越过极限点、跳跃（snap-through）、回跳（snap-back），λ 可以变负。
  * 步在两种情况下正常结束：λ 到 1（最后一个增量用荷载控制落在 1 上），或到 `stop`。
    增量数用完而两者都没到，是失败（MAX_STEPS），不是答案：加大 `max_increments` 或 `initial`，或给 `stop`。
  * 弧长校正步没有线搜索；`line_search` 作用于荷载控制的增量，以及每个弧长步的 λ=0 平衡与落到 λ=1 的最后一个增量。
    `tangent: modified` 在每个增量开头算一次切线，迭代收敛变慢时重算；对强非线性路径，`full` 通常更快。
    迭代数在 `target_iterations` ±1 内的增量保持弧长；弧长降到首个弧长 1/4 以下且连续三个增量无回退时加倍（1.0 版）。
    监测量的 `time` 是 前面已完成的步数 + λ（只有一步时就是 λ）。
  * 弧长从 λ = 0 处的平衡出发：若一步开头就不平衡（例如上一步的步内荷载这一步不再施加），
    先在 λ = 0 用 Newton 求平衡。**分析步里的 `loads` 只属于这一步**，要一直在的荷载（恒载）
    写在顶层 `loads` 里。
  * 常见用法：恒载 + 预应力一步 Newton，活载一步弧长（`steps: [live]`）。
  * **`control`（1.3）**：弧长只量一个节点沿 x、y 或 z 的位移，不量整个状态，即荷载因子为未知量的位移控制
    （OpenSees 的 DisplacementControl）。每个增量都让这个点往前走 Δl，所以让它往回走的平衡（例如从上一状态弹性卸载）不在弧上。
    * 跟不了被控位移自己的回跳（snap-back）。到那里时，增量会收敛到远处另一支上的平衡。
      现在这样的增量被拒绝：每单位被控位移，状态移动的速度超过上一个增量的 1.5 倍，就算跳跃，弧长减半。
      减半次数用完就停下，消息里写明这里可能是回跳。要走过回跳，不写 `control`，量整个状态。
    * 区域必须只有一个节点；这个自由度在这一步不能被约束；荷载模式要能推动它。
    * 杭州湾推覆的第二个峰值（case_24g，−0.38 m）用它也过不去：2 mm 的增量在 −0.386 m 附近停下，那里看来是一处回跳；
      量整个状态的弧长在这里也停住。粗一些的增量会"越过"它，那是跳到另一支上，不是路径（1.3 版）。
  * 算例：Lee 框架（case_16b）61 个增量、6 s 走完全程。
    极限荷载 18.577 EI/L²（NAFEMS 18.552），终点 v/L = 0.781（NAFEMS 0.784，Abaqus 0.781）。
    回跳段在路径上，而位移控制的 case_16 只能动力地跳过去。
* 有限差分的步长是 `perturbation` × 单元中位长度（1.0 版起；此前乘的是模型最大坐标，
  580 m 的桥上步长 3e-5 m，跨过了混凝土纤维的开裂折点，峰值附近 Newton 退化成线性收敛）。
* 效果：
  * Vecchio & Emara 框架（case_21c）8 s，同一模型动力松弛 22 min；两者在契约读取的每一级上差 0.3% 以内。
  * 纤维柱的往复加载（case_11）17 s。
  * 杭州湾一联带墩的推覆（case_24g）：恒载一步 Newton，活载弧长 18 个增量，在双核容器里约 30 s（1.0 版实测 29 s）；
    显式动力版本（case_24d）50 min。越过峰值 k = 14.69（−0.186 m）后走到软化段（k 降到 12.76，−0.275 m）再回升，到 −0.38 m 的 stop（k = 14.08）。
    恒载状态跨中挠度 −23.47 mm（1.0 版以前为 −23.18 mm，1.0 版的锚固回缩修正使主梁预应力增加 0.8%；动力松弛与当时的值相差 3e-6）；case_24d 的 −27.77 mm 是 t = 0 突加恒载
    超调到 −42.7 mm 留下的开裂。

**多线程（`threads`，1.0 版）**：`backend: numba` 的纤维梁内核和框架（beam2）内核
可以把单元分到多个核上。

```yaml
solver:
  backend: numba
  threads: 0                # 1 串行（默认）；0 用全部核；n 用 n 个
```

* 每个单元写自己的一行，算完按单元顺序加到节点上：结果与串行逐位相同，与线程数无关。
* 实测，杭州湾一联带支座的地震时程（`_hzb_seismic`，算 1 s 折算全程 31.18 s）：

  | 线程 | 1 | 4 | 8 | 16（`threads: 0`） |
  |---|---|---|---|---|
  | 全程 | 22.0 min | 11.4 min | **9.0 min** | 10.9 min |
  | 加速 | 1.00 | 1.92 | 2.44 | 2.02 |

  Core Ultra X9 388H（16 核，大小核混合），四种线程数的结果逐位相同。
* **线程不是越多越好**：
  * 一步里只有约三分之二能并行（纤维内核）；支座连接器和积分仍是串行，
    所以上限约 3 倍。
  * 大小核混合的 CPU 上，16 个线程要等最慢的核，反而比 8 个慢。
  * 先用 `python benchmarks/bench_threads.py <算例> --time 1.0 --threads 1 4 8 0`
    在自己的机器上量，取最快的那个数，不要直接写 `threads: 0`。
* 2 核容器上：一次内力 3.4 → 2.1 ms，显式动力 347 → 550 步/s。
* 框架内核（1.0 版）：单元按连续的段分给线程，每段只分配一次临时数组。
  西堠门（851 根梁、356 根索和吊杆）一次内力 0.62 → 0.33 ms（2 核），
  每模拟秒 42.5 → 30.5 s（2 核容器）。一步里其余约 0.3 ms 是向量更新、转动推进、能量账，当时仍是串行。
* **编译的整步（1.3）**：框架、框架加索的显式动力，两次进度检查或输出之间的那些步
  在一次编译调用里走完：外荷载、构件内力、阻尼、能量账、速度、位置、转动、支座，
  节点和构件一样分给各线程。结果与逐步的循环逐位相同（位置、速度、转动、能量账、监测、反力），
  与线程数无关。西堠门（2 核容器，算 1 s）：

  | | 1.2.1 | 逐步（本版的内核） | 编译的整步，1 线程 | 编译的整步，2 线程 |
  |---|---|---|---|---|
  | 每模拟秒 | 30.1 s | 27.5 s | 29.0 s | **14.9 s** |

  * **纤维梁和支座（1.4 版）**：连接器和支座编译了（各种律、阻尼器、滑移历史都在内），
    纤维梁模型和带支座的框架模型也走编译的整步，结果同样与逐步的循环逐位相同，与线程数无关。
    杭州湾地震（纤维梁加两个盆式支座，2 核容器，2 线程）每步：

    | | 1.3.0 | 连接器编译，逐步 | 编译的整步 |
    |---|---|---|---|
    | 每步 | 2.33 ms | 1.16 ms | **0.88 ms** |

    * 编译的连接器与 NumPy 的参考实现差在舍入量级（力约 1e-8，差分雅可比放大了末位），不逐位；
      框架模型的参考实现是 `backend: numpy`；纤维梁模型只要装了 numba，连接器就随融合内核走编译版本（关掉它的 `VFIFE_COMPILED_CONNECTORS=0` 在 1.18 去掉了）。两端相对转角接近 π 时两者都不可信，支座转不到那么大。
    * 纤维梁的整步每个进程要编译一次（约 3 s），所以不到 20000 步的纤维梁计算仍走逐步的循环
      （答案一样）；`VFIFE_COMPILED_STEP=1` 强制走整步。
  * **给定运动、塑性铰、断裂与分裂、移动荷载和车辆（1.6，1.7 版）**：这些一步里有自己代码的功能也进了整步。
    做法是每项的逐步代码只写一遍、编译成一个函数，逐步的循环和整步都调用它（铰的更新、脱落构件和附属构件的随动、
    给定运动、轴重的一致节点力、车辆的一步），所以两条路**按构造**逐位相同，而不是靠对照。
    构件达到承载力是一个**事件**：内核在那一步之前停下，循环接手那一步（记失效、去活或分裂、停放没了实体的粒子），
    然后在剩下的模型上重建整步；纤维截面的断裂同理（那一步算完再交回）；定时移除在到期的那一步前把整步截断。
    车辆的状态在整步里推进，离地事件按步序记在计算的时钟上。
    2 核容器：西堠门吊杆依次移除并失效（1.5 s）43.6 → 29.0 s（1 线程）；case_34 爆破拆除 12.1 → 1.8 s；
    case_38 簧上质量过桥 3.7 → 0.6 s，case_26 移动荷载 1.1 → 0.2 s（两者输出间隔放大到 500 步计时：
    每两步写一帧时输出本身占去一步的大半，整步就没什么可省的）。
    * 车辆和 PSD 路面不平度现在走编译的函数，与 1.5 的 NumPy 版本差在末位（求和顺序），不逐位；移动荷载逐位不变。
    * 哪些情形仍走逐步的循环，见下面的表（“哪些情形走编译的整步”）。
  * **开裂剪切律进了融合内核（1.7）**：纤维截面的 `shear` 律原来只在 NumPy 参考路径上
    （`backend: numba` 被拒绝），现在在编译的纤维内核里，整步也随之接纳它。NumPy 路径仍是参考，两者相差在舍入量级
    （tests/test_fiber_shear.py）。case_21b（Vecchio–Emara 框架带开裂剪切）从 20 分钟到半分钟。

**显式动力（`mode: dynamic`）**：

```yaml
solver:
  mode: dynamic
  total_time: 60.0
  damping: {type: viscous, coeff: 2.0}      # 质量比例阻尼；或 rayleigh 的 alpha/beta
  dt_safety: 0.6
```

时间步由稳定性条件自动确定（`dt_safety` 为安全系数）。**动力分析不写 `damping` 即无阻尼**（默认 `type: none`）；
要什么阻尼请写明。动能阻尼
会在每个动能峰值把速度清零，那是找静力解的办法，用在动力分析里会把动力响应抹掉——所以
动力分析里写 `kinetic` 会被拒绝。每一步的荷载与地面加速度取步初时刻的值（1.0 版起，二阶精度）。
动力分析的分析步就是一段时程：不接受 `load_steps` 和分析步自己的 `n_steps`，步与步之间速度延续。

阻尼的几个量各在哪里起作用（其余组合按名拒绝，1.0 版）：

| | 松弛 | 动力 |
|---|---|---|
| `type: kinetic` | 动能峰值清零；可再加 `alpha`（软化问题上用，见下） | 拒绝 |
| `type: viscous, coeff` | 质量比例 | 质量比例 |
| `type: rayleigh, alpha` | 质量比例 | 质量比例 |
| `beta` | 拒绝 | 只在 `type: rayleigh` 下 |

`kinetic` 加一个小 `alpha` 是为软化问题设计的（0.1 版）：动能单调增长时动能阻尼不起作用，
`alpha·M·v` 总是阻碍运动。它会选择解的分支，用能跑通的最小值，并在结果里写明。

Rayleigh 阻尼可以直接给 `alpha`、`beta`，也可以按工程习惯给**两个频率上的阻尼比**：

```yaml
  damping: {ratio: 0.02, frequencies: [0.3, 3.0]}       # 0.3 Hz 和 3 Hz 各 2%，alpha、beta 由此算出
  damping: {ratio: [0.02, 0.05], frequencies: [0.3, 3.0]}   # 两处不同的阻尼比
```

刚度比例项（`beta`）会缩小稳定步长——阻尼比 β·ω/2 在最高阶模态最大。这一项按模型**真实的**最高
频率算（参考刚度与质量的幂迭代，毫秒级），而不是 Gershgorin 上界：上界比真实值大 1.5–4 倍
（单个梁 1.0，Lee 框架 3.4，壳 4.1），带 `beta` 的计算步长因此可以大同样的倍数。无阻尼和只有
`alpha` 的计算步长不变，仍按上界取。日志里的 `damping` 行给出 β 使步长缩小的倍数和两个频率（`damping  step x… for beta at omega_max … (power iteration; Gershgorin …)`），纤维模型自 1.0 版起还给出由 `ratio` 换算的 α、β（`damping  rayleigh alpha=… 1/s, beta=… s`）。

极限承载力分析常用"慢速动力推覆"：荷载按很慢的速率斜坡加上，峰值之前是准静态的，过了
极限点挠度自己发展——静力松弛过不了极限点，只能报告最后一个收敛的荷载级。

### 10.3 迭代预算

动力松弛下每一步都要有迭代预算：`solver.n_steps`，或该步自己的 `n_steps`，或分级步的
`load_steps × max_steps_per_load`。都给了分级步时 `solver.n_steps` 可以省略，由程序相加。

> **版本说明**：0.4.2 及以前，这一相加只在实体（连续体）求解器里做，线单元和壳单元模型省略
> `solver.n_steps` 会在求解器初始化时报 `TypeError`，所以自带的几个纤维梁算例写了一个占位的
> `n_steps: 100`。此后的版本在输入校验时统一算出，所有求解器读同一个数。

### 10.4 后端

| 后端 | 说明 |
|---|---|
| `numpy` | 参考实现，所有单元都支持 |
| `numba` | CPU 编译内核，结果与 numpy 一致到 1e-12；首次运行要编译 |
| `warp` | GPU（`device: cuda`，`precision: mixed` 或 `fp64`）；实体与壳 |

哪种单元、材料、分析模式支持哪个后端，以 `python -m vfife capabilities` 为准。纤维梁在
`numpy` 下会自动启用编译内核（条件满足时），`solver.kernel_status` 说明是否启用及原因。

### 10.5 收敛

每一级要同时满足残差 `tolerance` 和动能比 `kinetic_tolerance`。一级不收敛时，程序停止并
报告残差最大的节点和自由度。调试方法见 `docs/convergence_debugging.md`：常见原因是荷载级
太大（单级增量接近开裂或屈服位移）、约束不足、单元或材料在该状态下软化。

`tolerance` 限制的是不平衡力相对于模型力尺度的大小，而不是支反力之和。30+40+30 m 连续梁在 1e-5 下，各徐变时间站之间
支反力之和最多变动 25 kN（自重的 0.16%），10 年挠度差 0.6%；1e-7 时稳定在 ±400 N。供后续分析步或动力计算起步的
恒载状态宜用 1e-6～1e-7。

---

### 10.6 质量缩放（显式动力的步长）

显式动力的稳定步长由刚度与质量之比最大的那个自由度决定，在实际桥梁模型里它常常是一个无关
紧要的节点——例如挂在刚臂上、自身几乎没有质量的锚点的转动。`mass_scaling` 只给步长低于目标
的那些自由度补上恰好够用的质量，其余不动：

```yaml
solver:
  mode: dynamic
  mass_scaling: {target_dt: 2.0e-5}      # 可选 max_added_fraction，默认 0.01
```

* 补的是**真实质量**：重力按它计重，地面运动按它计惯性力；运行摘要报告补了多少
* 超过 `max_added_fraction`（默认模型平动质量的 1%）直接拒绝——目标步长已经大到要改变结构的
  动力特性，就不再是一个"速度设置"
* 同一个算例在动力松弛下补的质量完全相同，所以用松弛求出的恒载状态，与之后动力计算承受的
  重量一致
* 适用于 beam2、beam2_timoshenko、beam2_fiber、mixed_line；其他单元拒绝
* 西堠门模型：步长 1.07×10⁻⁷ s → 2.0×10⁻⁵ s，补 757.5 t（0.176%），前 40 阶频率变化不超过
  0.60%（`benchmarks/xihoumen_dynamic.py`）

**转动惯量**（1.0 版）：线单元节点的转动惯量取构件真实值——beam2 绕自身轴 ρ·I_p·L/2、绕两个
横轴 ρAL³/24；Timoshenko 梁和纤维梁 ρ·[I_p, I_y, I_z]·L/2（I_p = I_y + I_z）——从构件局部轴转到
整体轴后取对角元（沿整体轴的构件就是张量本身）。模态、反应谱、动力计算都用它。以前 beam2 的扭转
惯量是 ρAL³/24，扭转频率随单元数增大而不收敛；Timoshenko 梁和纤维梁的局部惯量未经旋转直接加到
整体转动上，频率随构件朝向而变。显式步长仍按原来的规则计算，任何算例都不会变慢；某个转动自由度的
真实惯量不足以在这个步长下稳定时，取刚好稳定的值（与 0.4 版同一规则，不称重）。一个理论上的缺口：
带 Rayleigh β 阻尼且有斜向 Timoshenko 或纤维构件时，阻尼步长折减仍按旧质量检查。

### 10.7 从已有状态起步

地震、车辆等时程通常要从恒载平衡状态开始。`initial_state` 让一次计算从另一次计算的最终状态
出发——位置、转角、材料状态全部接过来，速度置零、时间从 0 开始：

```yaml
solver:
  mode: dynamic
  initial_state: ../results/bridge_dead.h5    # 相对算例文件
loads:
  - {region: all, gravity: [0, 0, -9.80665], amplitude: hold}   # 恒载已在，保持
```

典型用法是先用动力松弛（分级、收紧容差）算恒载状态，再从它开始动力计算。与 `--restart` 的
区别：restart 是**接着**同一次计算往下算（同一种模式、同一个步数计数、保留速度），
`initial_state` 是**从**另一次计算的终点**开始**一次新的计算。结果文件必须是同一网格算出的，
否则拒绝。不这样做而直接从网格几何开始，重力会让结构绕平衡位置大幅振荡（西堠门：1.68 m），
从松弛状态开始则 5 s 内偏离 0.023 mm。

续算从检查点所在的位置接着算：同一个分析步、同一个荷载级、同一个时刻，地震记录、车辆、
分级荷载都不从头重来；材料状态、断裂与分裂、徐变历史、能量账一起续上（1.0 版之前框架、纤维、
桁架和隐式静力的续算都会从第 0 步重新算一遍）。检查点已经在分析的终点时，续算会被拒绝
（`RESTART_BUDGET_EXHAUSTED`）。`initial_state` 同样带过去徐变历史——那是混凝土的记忆，
不属于某一次计算。warp 后端的壳不能续算，换 numba 后端。

续算的结果要写到**新的文件**：`vfife run case.yaml --restart part.h5 -o rest.h5`；检查点是结果旁的
`part.ckpt.h5`，两个文件要一起复制。写回检查点所在的文件会被拒绝（`RESTART_OVERWRITES`）；
`initial_state` 就是输出文件时同样拒绝（`INITIAL_STATE_OVERWRITES`）。

检查点记录它属于哪个模型、由哪次计算写出（1.0 版）：续算要求单元族、计算模式、网格、截面布置、
材料、破坏设置、荷载、约束、质量、阻尼和单位都相同（只有步数、总时长、容差、后端、线程数和输出可以改，
`solver.initial_state` 被忽略），否则拒绝并说明哪里不同（`CHECKPOINT_MISMATCH`）；`initial_state` 可以换
模式、荷载、约束、质量、阻尼、材料常数和可破坏设置（`fracture`、`failure`），但单元、网格、截面布置和
状态数组形状必须一致（节点可以多出备用质点）。材料、截面、区域的名字不算在内。结果旁的检查点不是这次
计算写的会被拒绝（`CHECKPOINT_NOT_THIS_RUN`）；结果文件不能命名为 `*.ckpt.h5`。

Ctrl-C 或 SIGTERM 在下一次进度检查处停下，检查点恰好在一步的边界上；再按一次立即停，保留上一个
检查点。Ctrl-C 退出码 130，SIGTERM 退出码 143；Python 中 `AnalysisInterrupted.signal` 给出信号。最终状态
不是有限值的计算保留最后一个有限的检查点。停下的计算记下停下前最后一个应写的帧，`part.h5` 的帧加 `rest.h5` 的帧就是
一次完整计算的帧。被杀掉的进程（SIGKILL）留下可读的结果（到最后一帧）和最后一个检查点，此后写过
的帧在两个文件里都有。续算的结果带属性 `restarted_from`，只含后半段。

1.0 版之前检查点存在结果文件里，没有模型记录，拒绝续算（`RESTART_OLD_CHECKPOINT`），仍可作
`initial_state`；1.0 版之前写的检查点没有循环位置，同样拒绝续算。

```yaml
    tendons:
      - section: strand
        profile: [[0, 1.6, 0], [35, -1.5, 0], [70, 1.6, 0]]   # [s, y, z]
        interpolation: quadratic
        jack: 1.395e9
        friction: {mu: 0.17, k: 0.0015, jack: both, anchor_set: 0.006}
        elastic_shortening: compensate
        extent: [0.0, 70.0]
      - section: strand
        profile: [[0, -1.7, 0], [70, -1.7, 0]]
        prestress: 1.2e9
      - section: strand
        profile: [[70, -2.36, 2.5], [140, -2.36, 2.5]]
        prestress: [[70, 1.15e9], [105, 1.10e9], [140, 1.15e9]]
```

* 束是"每个单元有自己位置的一根钢纤维"：`profile` 在每个单元中点取值，(y, z) 是截面坐标，
  `s` 是沿构件自起点的距离（`normalised: true` 时为构件长度的分数）；`extent` 限定束的范围
* 有效应力三种给法：`prestress` 常数；`prestress` 沿束的 `[[s, σ], ...]` 表（必须覆盖束经过
  的所有单元）；`jack` + `friction`（σ = σ_con·exp(−(μθ + ks))，锚固回缩反射，回缩量精确等于给定值；
  `friction` 只读 `mu, k, jack, anchor_set`）
* `interpolation: quadratic` 是每三个相邻点一条抛物线（0-1-2、2-3-4、……），点数须为奇数；放进去的曲线和 `bars` 必须在截面外轮廓内（`rect`/`box` 外矩形、`tube` 外圆、`patches` 各块并集，容差为截面尺寸的 1%；箱室、管孔、`holes` 算在内）
* 弹性压缩由松弛自动算出；后张的千斤顶读数已含这部分时写 `elastic_shortening: compensate`
  （用换算截面关于原点的 3×3 刚度，T 梁、箱梁不必以形心为原点）
* **预应变是在初始化时建在纤维里的，不能斜坡加载**：自重和预应力应同时从一开始作用
* 一个模型多个纤维截面时，每个截面的束 `s` 从**该截面区域的起点**量起、摩擦按区域分别求解。
  需要沿梁改变束的性质（如锈蚀段）时，保持一个截面，把束切成几段，每段用 `prestress` 表
  给出整根束的摩擦结果

### 11.2 断丝与断裂

* 钢绞线：`steel02` 的 `rupture_strain`；纤维应变达到它时断开，损伤类别 4
* 普通钢筋：`rebar` 的 `rupture_strain`，或 `steel_cyclic` 的疲劳准则
* 构件分离：纤维截面的 `fracture: {threshold: 0.5, split: true}` 使断裂截面两侧脱开、碎块在
  重力下落下（`split` 需要 `mode: dynamic`；没有接触，见第 16 章）

纤维的损伤类别：0 完好、1 开裂、2 压溃、3 屈服、4 断裂（`fiber_damage` 字段）。

### 11.3 徐变、收缩、龄期与松弛

材料上给 `creep`、`shrinkage`、`ageing`（第 6.4 节），求解器给起始龄期，分析步用龄期表示
时间：

```yaml
steps:
  - {name: build,   age: 28.0,      load_steps: 1}
  - {name: 3_years, to_age: 1123.0, load_steps: 12}    # 对数间隔的时间站点
solver:
  age: 28.0
```

纤维截面上每根混凝土纤维有自己的徐变历史；预应力钢筋的 `relaxation` 表现为预应变随时间
减少。见 `docs/creep.md`。纤维徐变每个单元在中点取一次：偶数点积分规则（默认 `gauss2`、
`lobatto4`）取跨着中点的两个积分点的平均。

每个构件按自己材料的 `creep`/`shrinkage`/`ageing` 计算，没有声明的构件不徐变。时间只能向前：后一步的
`age` 早于已算到的龄期、或 `to_age` 早于本步 `age`，均按名字拒绝。不带 `load_steps` 的松弛步是一个
时间站点，龄期直接取 `to_age`。带 `to_age` 的时间步里，未写幅值的荷载和强制位移默认 `hold`（第一个时间站即全量并保持）；要随时间加载须写幅值。有 `creep` 时，动力步不得推进混凝土龄期（写 `to_age`，或 `age` 与
当前龄期不同，按名字拒绝）：徐变用松弛步计算，再以其结果作 `solver.initial_state` 做动力分析，已发生
的徐变作为冻结的附加应变保留。实体、壳、耦合模型、整模型的 `truss2`（杆截面指派到 `all`）
以及嵌入钢筋上的 `creep`/`shrinkage`/`ageing`/`relaxation` 均按名字拒绝。

**静力步里也有时钟（1.16）。** `solver.mode: static` 在梁和 mixed_line 模型上跑同样的时钟：带 `to_age` 的步里每个收敛的增量
是一个时间站点，与分级松弛的每一级相同，结果与分级松弛一致（测试算例上到 1e-9）。纤维模型和 `static.arc_length` 下的时间步按名字拒绝。

**每根预应力杆有自己的时钟（1.16）。** 带 `prestress` 的杆从 `tensioned_at`（默认分析开始）起松弛；后续步出生的从出生的龄期起；
在某步 `jack` 张拉的从该步锁定的龄期、按千斤顶留下的应变起。`curve` 松弛可写 `interpolation: linear`（按 t 线性，按天数列表的
比值本来就是这样读）代替默认的按 log t 线性。

**规范公式不在求解器里。** 求解器读的是算例文件里写明的松弛曲线（或幂函数），算例的结果不随产生这些数的公式将来如何变化而变。
规范公式放在 `vfife.codes`，每本规范一个模块，求解器不导入：`vfife.codes.jtg3362.relaxation_curve(sigma_pe, fpk, zeta, psi)`
给出 JTG 3362（及 JTG D62）的钢绞线松弛 `curve`，已与 Midas 的钢束损失表对到四位有效数字；时间比值表两天以后的各行还没有用独立来源核对。

### 11.4 温度

```yaml
loads:
  - region: girder
    temperature:
      profile: [[-2.4785, 0.0], [0.5215, 0.0], [1.5215, 14.0]]   # [截面坐标, 温度 K]
      axis: y
```

* `uniform`：全截面均匀温差；`gradient`：`[dT/dy, dT/dz]`（K/m）；`profile`：沿截面的
  任意分布（规范的非线性温度梯度照写）
* 标量 `gradient` 沿 `axis`（默认 y；矩形截面高度方向写 `axis: z`）
* 各纤维材料都应给 `thermal_expansion`，受温截面中有的给有的没给时预检警告 `THERMAL_EXPANSION_PARTIAL`
* 写在分析步里的温度只作用于该步；材料有 `creep` 时持续温度会松弛
* 温度是施加的应变而不是力：超静定结构里被约束的部分变成内力，截面里不能保持平面的部分
  变成自平衡应力

### 11.5 移动荷载

```yaml
loads:
  - region: deck
    moving_load:
      axles: [[0.0, 3.0e+5], [-4.2, 3.0e+5], [-5.6, 3.0e+5]]    # [相对参考点位置, 轴重]
      start: -10.0
      speed: 20.0            # 动力分析：s = start + speed·t
      # stop: 220.0          # 或者：分级松弛下在 start→stop 之间取 load_steps 个位置 = 影响线
      direction: [0, 0, -1]
```

区域必须是**一条不分叉的构件链**。轴的位置沿**行进方向**量：后轴写负值，`speed` 为负（或 `stop < start`）往回走时同一组轴照样后轴在后。一队车可以写成一个荷载组、一串轴（每辆车的轴加上车距），所有轴一起计算，比每辆车一个荷载组快得多。它是移动的**力**：车辆没有质量和悬挂，不跟随桥面变形，
冲击系数不能靠它算。见 `docs/moving_load.md`。

带 `speed` 的移动荷载只用于动力模式；静力/松弛下用 `stop` 扫位置。移动荷载不能与 `static.arc_length` 同用。`moving_load`/`vehicle` 只作用于梁构件，壳模型拒绝。轴或均布荷载落在节点之间时，输出的构件端力（`*_i/_j`）和 `bending_y` 等已计入固端弯矩；`beam2_fiber` 的单元值是截面合力，节点间集中荷载下需加密网格。轴载或车辆位于有端部释放的构件上时，其等效荷载与固端力按该构件的释放凝聚，与 `line_load` 相同。

**有质量的车辆**（1.0 版）：

```yaml
loads:
  - region: deck
    vehicle:
      name: truck
      speed: 20.0
      start: -30.0                      # 参考点起始里程；负值在引道上
      body: {mass: 2.4e+4, pitch_inertia: 1.5e+5, cg: -2.0}
      axles:
        - {offset: 0.0,  unsprung_mass: 700, suspension: {stiffness: 1.0e+6, damping: 2.0e+4},
           tyre: {stiffness: 3.5e+6, damping: 2.0e+3}}
        - {offset: -4.5, unsprung_mass: 1100, suspension: {stiffness: 2.0e+6, damping: 3.0e+4},
           tyre: {stiffness: 7.0e+6, damping: 4.0e+3}}
      roughness: {psd: {g0: 64.0e-6, n0: 0.1, w: 2, n_min: 0.011, n_max: 2.83, seed: 1}}
output:
  monitors:
    truck_acc: {kind: vehicle, of: truck, field: acceleration}
    front_P:   {kind: vehicle, of: truck, field: contact_force, axle: 0}
```

* 车身是刚体：竖向平动，多于一根轴时再加俯仰（此时必须给 `pitch_inertia`）。
* 每根轴：悬挂（弹簧 + 阻尼）→ 簧下质量 → 轮胎（弹簧 + 阻尼）→ 路面。
  * 轮胎只压不拉：车轮离开路面（轮胎不再受压）时接触力为零，阻尼也不再作用；离地步数和刚性轴受拉步数及首次发生时刻写进运行报告（`vehicle_contact`，结果文件 `diagnostics` 的 `vehicle_contact_json`）和日志。
  * 不给轮胎和簧下质量的轴刚性贴着路面，就是文献里的"移动簧上质量"。
* 路面 = 桥面在接触点的挠度（用与 `moving_load` 相同的 Hermite 形函数读回）+ 不平度。
  * 不平度可以给 `profile` 文件（里程、高程）。
  * 也可以给位移功率谱 G_d(n) = g0 (n/n0)^−w，按种子用谐波叠加生成。
  * 库里**不存**规范的不平度等级表：g0 由你给。
  * 不平度 `psd` 的键只有 g0、n0、w、n_min、n_max、count、seed，拼错即拒绝；`scale` 对 profile 和 psd 都乘；psd 路面按谐波和精确求值。
* 车辆和结构用同一个中心差分、同一个步长推进；车辆从起始里程上的静平衡出发。
  车辆自身最硬的模态（轮胎上的车轮）要求更小的步长时会直接报出来。
* 只用于动力模式；框架与纤维梁可用。
* 监测器 `kind: vehicle` 读：`heave`、`pitch`、`acceleration`（车身竖向加速度）、
  `contact_force`、`wheel`、`station`；`axle` 选第几根轴。
* `name` 不写时，每一步里依次命名为 `vehicle`、`vehicle_2`……（每一步的第一辆未命名车辆都叫 `vehicle`）；同一步里两辆车不得重名。监测器读的车辆若不在当前步中，该步记为 NaN。车辆不接受 `amplitude`，`direction` 不能是零向量。监测器的 `of` 必须是某辆车的名字，`axle` 必须小于该车的轴数，否则读入时即拒绝。
* 限制：平面模型，没有侧倾，每根轴一条轮迹；接触点取未变形路径上的里程。

算例 case_38：Yang & Yau（1997）的簧上质量以 100 km/h 通过 25 m 简支梁，对独立的模态解
（20 阶正弦振型 + scipy 高精度积分）。跨中峰值挠度差 0.03%，车身峰值加速度差 0.2%。

### 11.6 地震

```yaml
loads:
  - ground_motion: {path: ../benchmarks/assets/elcentro_1940_ns_g.dat, scale: 9.80665, direction: [1, 0, 0]}
```

两列记录（时间 s、加速度），`scale` 换算到 m/s²，`direction` 是单位向量，施加相对坐标下的惯性力
−M·a_g(t)。只接受这三个键；不接受 `amplitude`（记录本身就是时间历程）和 `region`（整个模型的基底；
单个支承按自己的记录运动见下面的多点激励）。多步动力分析里，模型级的 `ground_motion` 每一步都从
记录起点重放（preflight 警告 `GROUND_MOTION_REPEATS`），应写在它所属的那一步里。
这是**一致激励**：所有支承同一时刻、同一运动。反应谱见 11.8。从阻尼显式分析读反力时要
滤波或加一点刚度比例阻尼（高频振荡）。

**多点激励**（1.0 版）。千米级的桥，两个墩相距几百米，地震波走过去要零点几秒：两墩的运动
有相位差，构件被两端的差动拉扯，一致输入算不出这一部分。给约束加 `record`，这个区域就按
自己的记录运动（绝对坐标）：

```yaml
constraints:
  - {region: piers, dofs: [1, 1, 1, 1, 1, 1]}     # 照常固结 ……
  - region: piers                                 # …… 其中 x 跟着记录走
    dofs: [1, 0, 0, 0, 0, 0]
    record:
      path: ground_x.dat                          # 两列：时间 s、数值
      quantity: displacement                      # 或 velocity / acceleration
      scale: 1.0
      delay: 0.0                                  # 这个支承自己的时延 s
      wave: {speed: 1000.0, direction: [1, 0, 0], origin: [0, 0, 0]}
```

* 记录只驱动平动；转动由旁边那条普通约束固定，记录覆盖它在被标记分量上的零值。
* 推荐使用（经基线校正的）**位移**记录：位移记录同时施加其速度。位移按 C1 三次 Hermite 插值读取（过各采样点，
  用保单调的 Fritsch–Carlson/PCHIP 斜率，不越出相邻两采样点的范围——原来的三点斜率在粗采样的阶跃上超调 7%），支座速度连续且是位移的精确导数（1.0 版；此前线性插值使速度在每个采样点跳变，墩底剪力为同一运动以加速度记录输入时的 3.2 倍：
  2266 对 708 kN；现为 698 对 700 kN）。记录开始前支座静止，结束后位移保持终值。速度和加速度记录按记录的分段线性插值精确积分（1.0 版起；以前是一阶精度），
  与位移记录一样和步长无关；加速度记录结束后支承按末速度继续运动，积分漂移（基线）由用户负责。
* `wave` 给区域里每个节点再加时延 (x − origin)·direction / speed；不同墩用不同记录就写多条约束。
* 只用于动力模式；框架、纤维梁、壳可用，实体和独立桁架拒绝。
* 位移是**绝对**的。Rayleigh α 和 `type: viscous`（二者都与质量成正比，`·M·v`）作用于绝对速度，会阻尼地面施加的
  刚体运动；请用 β，或注意这部分额外阻尼。监测器的 `relative_to` 可以读相对某个支承的位移。
* 能量账把地面通过支座反力做的功记为外力功，支承质点自己的动能归地面。
* 同一方向上既有支承 `record` 又有整体 `ground_motion` 时，preflight 报错 `GROUND_MOTION_AND_RECORD`：
  两者都会施加，响应翻倍。多点激励每个支承都写 `record`，一致激励只写一条 `ground_motion`。

算例 case_36：100 t 桥面质量在相距 400 m 的两墩之间，波速 1000 m/s，东墩比西墩晚 0.4 s
（差不多半个周期）。桥面峰值位移 0.1019 m，是一致输入（0.285 m）的三分之一多，构件力
却差不多（1.50 MN 对 1.46 MN）：两墩反相，把桥面按住，把构件拉开。与闭式解差 0.02%。

桩的土弹簧（p–y 曲线）见 11.13；辐射阻尼还没有，地震记录施加在写它的地方。

### 11.7 支座

支座用 `connector` 截面放在梁节点和墩顶节点之间（网格里是一个 0.5 m 左右的竖向线单元）：
固定盆式支座给大的纵向刚度，滑动盆式支座给小的纵向刚度，转动刚度按支座实际（盆式支座放开
绕横桥向轴的转动）。纤维梁可以直接与连接器同处一个模型。

### 11.8 模态

```bash
python -m vfife modal cases/case_23_suspension_bridge.yaml --result results/case_23_suspension_bridge.h5
python -m vfife modal cases/_xihoumen.yaml --modes 40 --paraview
```

在给定的受载状态上用有限差分切线刚度和物理质量求自振频率与振型；`--paraview` 把每阶振型
写成 ParaView 时间序列（需要 meshio）。给了 `--result` 时，用该帧所在分析步的约束（1.0 版起；
以前总是第一步的）。没有平动分量的振型（例如柱的扭转）按最大转角归一，表中标 `rotation only`，
模态文件的 `rotation_only` 数据集标出这些振型（以前被数值噪声除，转角达 1e13）。有 `diaphragms`
的模型按刚性楼板求振型。

* 带 `--result` 时，若所取帧为结果的最后一帧（即检查点所存状态），则像 `solver.initial_state` 一样恢复全部状态——纤维与连接器律的历史、徐变历史、松弛后的预应变——摘要显示 `full state from its checkpoint`；其他帧只读位置并给出说明。`probe --result` 同样处理（1.0 版）。
* 徐变计算之后，模态与反应谱把已发生的徐变按瞬时弹性模量作为施加应变保持，与从该状态起步的动力计算一致；此前用最后一个时间站的 E/(1+φ)，周期偏长 20–35%，且随时间站数变化。
* 连接器律处在拐点上（摩擦滑动、双线性屈服、间隙到达限位）时，线性化取两支的平均；`modal` 与反应谱会点名警告，反应谱结果记录 `connector_kinks`；做反应谱时请给这类支座等效线性刚度。

**反应谱**（1.0 版）：在算例里加一段 `response_spectrum`，`vfife run` 在计算结束的状态上
（松弛到的恒载平衡态；没有荷载就是图纸位置）做模态，按谱求每阶峰值再组合：

```yaml
response_spectrum:
  spectra:
    - {direction: [1, 0, 0], path: spectrum_x.txt, scale: 9.80665}   # 前两列为周期 s、谱加速度（这里以 g 给），其余列不读
    - {direction: [0, 1, 0], table: [[0.0, 0.9], [0.1, 2.25], [0.5, 2.25], [5.0, 0.3]]}
  combination: cqc          # 或 srss
  damping: 0.05             # CQC 的振型阻尼比（谱本身应按同一阻尼比给）
  mass_fraction: 0.9        # 不写 modes 时取到每个受激方向有效质量达到 90%
```

* 每阶峰值 U_i = φ_i Γ_i S_a(T_i)/ω_i²；位移、构件端力、支座反力逐分量按 CQC（Der Kiureghian，
  一个阻尼比）或 SRSS 组合，各方向再按 SRSS 组合
* 构件端力和反力来自模型本身：沿振型移动 ±h 求内力差，与求振型用的是同一个切线（索的张力刚化、
  主梁轴力都在里面）。**基底合力按每阶先求和再组合**
* 谱表由用户给，库里不存任何规范的谱。周期超出谱表时默认拒绝并报出是哪几阶；写
  `beyond_table: hold` 取端值
* 没有剩余质量修正：取的振型达不到 `mass_fraction` 时如实报出达到了多少
* 相等或很接近的频率（方形柱两个方向的弯曲、对称结构）要用 CQC：SRSS 在简并振型上会错
* 可用于 `mode: relaxation` 或 `mode: static`（线性化要在平衡态上做）
* 反应谱用计算结束时（最后一个分析步）的约束
* `modes` 与非默认的 `mass_fraction` 不能同时写（以前 `modes` 会静默覆盖）
* `path` 指定的谱文件在计算开始前读入并检查：每行两个数（空格、制表符或逗号分隔，`#` 为注释），
  周期从 0 或正数开始递增，谱值非负；不合格时报 `SPECTRUM_FILE`
* 桁架模型输出杆件轴力 `axial_force`
* 契约读 `displacement`、`rotation`、`reaction`、`base_force` 这些向量量并用 `final`/`first`/`delta`
  归约时必须给 `component`；`reaction` 的 `nearest` 取最近的节点
* 结果写在结果文件的 `response_spectrum` 组里：`period`、`frequency`、`effective_mass`（比例）、
  `modal_mass`（kg）、`spectral_acceleration`、`displacement`、`rotation`、`reaction`、
  `base_force`、`end_actions` 和 `axial_force`/`bending_y`/……（两端较大者）。验证契约用
  `source: spectrum` 读它们。算例 case_35

**线性屈曲**（1.1）：`vfife buckling <算例>` 求某一步荷载的屈曲荷载因子 λ 和失稳形状，即 (K_b + λ K_G) φ = 0 的最小正根。

```bash
python -m vfife buckling cases/pier.yaml                       # 第一步荷载，从参考构形出发
python -m vfife buckling cases/pier.yaml --step 2 --modes 4    # 第二步的荷载
python -m vfife buckling cases/pier.yaml --result results/pier_dead.h5 --paraview   # 在算到的受载状态上再加荷载
```

* **K_b** 是基础状态的切线刚度，取自 `modal` 用的同一个有限差分切线：连接器、支座、纤维截面以及基础状态已有的应力刚度都在里面。
* **K_G** 是该步荷载的应力刚度，由线性增量 u = K_b⁻¹F 中各构件的**轴力和弯矩**组装（1.5 起；1.1 只有轴力）。
  杆和索为 N/L (I − e eᵀ)。梁分两部分：
  * 共旋转部分：构件坐标架转动时它所带的端力随之转动（弦的弦刚度 N/L、端弯矩和剪力），与求解器自己的运动学一致，
    所以弯矩绕过构件夹角的节点（一根的弯曲变成下一根的扭转）时，转法和非线性计算相同；
  * 构件内部的二阶项：端部相对于弦的转角（轴力项）、扭转的 Wagner 项 N·Ip/A·θ′²、弯矩把扭转与另一平面的弯曲耦合起来的项。

  所以算的是柱、墩、塔、框架、拱（面内与面外）的弯曲屈曲，柱的**扭转屈曲**，梁和主梁的**侧向扭转屈曲**。
  壳和实体被拒绝（`BUCKLING_FAMILY`），它们的稳定用非线性静力（弧长）算到极限点。
* **侧向扭转屈曲的适用范围**：
  * **不含翘曲**：构件只有圣维南扭转 GJ。开口薄壁截面（工字梁）的临界弯矩因此偏低，偏低的倍数是
    √(1 + π²EI_w/(GJL²))，偏于安全，对短而高的工字梁偏得很多。箱形、实心和窄矩形截面不受影响。
  * 截面按双轴对称处理：剪心取在形心，单轴对称截面（T 梁）的 Wagner 系数不在其中。
  * 荷载作用在形心：荷载作用点高于形心（桥面在梁顶）的影响不在其中。
  * 扭矩只通过共旋转部分进入：受扭构件按求解器自己的方式转动（它的弯矩是空间矩，与角速度共轭），
    只受扭矩的轴在非线性计算失稳的地方失稳，而不是在教科书的 Greenhill 荷载上（那个值取决于扭矩怎样施加）。
  * 外加弯矩当作构件端部处理，不另计荷载刚度；在扭转被约束的叉形支座上，各种弯矩的结果相同。
  * **屈曲前的弯曲变形计入了**：每个平面的弯矩乘以 Kirchhoff 系数 √((1 − I_z/I_y)(1 − GJ/EI_y))（绕 y 弯曲时；
    I_y ≤ I_z 或 GJ ≥ EI_y 时为 0，两个括号各自截到 0），对叉形支座纯弯精确，其他弯矩分布近似（Pi 与 Trahair；悬臂差 2–4%）。系数为 0 时，那个平面的弯矩和剪力在 K_G 里整个去掉（共旋转部分也去掉），只留轴力和扭矩。所以两个惯性矩接近的构件
    （圆墩、方形或箱形截面）和绕弱轴弯曲的构件不会报出并不存在的侧向扭转屈曲；窄矩形截面的临界弯矩高 0.3%，
    I_z = I_y/4 的截面高 17%，非线性计算在它的 2% 以内失稳。设计规范用的教科书值是报出的值乘以这个系数。
* **λ 乘的是该步的全部荷载**，含自重，取幅值在步末的值。
* **默认从参考构形出发**，参考构形必须是静止的：预应力、徐变、温度这类在参考构形上就有内力的模型会被拒绝
  （`BUCKLING_BASE_NOT_AT_REST`），先把它算到受这些作用的状态，再用 `--result` 从那里问。
  松弛的索在参考构形上没有刚度，也要用 `--result`。
* **`--result`**：基础状态是结果里那一帧的状态（检查点所在的最后一帧带上全部材料、徐变、支座的历史），
  λ 是**在这一状态上再加的**该步荷载的倍数。例如墩在恒载下算到平衡后再问，λ 就是恒载之外还能加几倍。
* 机构（刚度在自由度上奇异）被拒绝（`BUCKLING_BASE_NOT_STABLE`）：最小刚度既低于最大刚度的 1e-10，又低于差分切线自身的不对称量才算（1.5 起；窄而高的截面划成很细的网格时，最弱的弯曲刚度曾被当成机构拒绝）。
* 没有抗拉的纤维材料（concrete01、ft 为 0 的 concrete02）在参考构形上每根纤维都正好在零应变的折点上，K_b 取受压刚度与零的平均，只受轴压的柱会报出欧拉荷载的一半左右；说明里会提示，用 `--result` 从受载状态问，纤维都在受压侧。负的因子（荷载反向时屈曲）只在离第一个正因子不远时于说明里给出。
  有律或曲线的连接器（间隙正好在挡块上、支座正在滑动）在 K_b 里取荷载推向的一侧（沿增量方向偏一点再求切线）；
  没有这类连接器的模型不偏（1.5：偏的那一点也会把每根构件的刚度随增量的转角转动，窄梁的侧向扭转屈曲对它很敏感）。
* 输出写到 `results/<算例>_buckling.h5`（`load_factor`、`shape`（振型、节点、自由度）、`axial_force`、`reference_load`），
  `--paraview` 另写形状动画（同 `modal --paraview`）。和 `modal` 一样是稠密求解，适合几千个自由度以内。
* 侧向扭转屈曲与闭式解对照（无翘曲，荷载在形心，32 个单元，闭式解都乘上 Kirchhoff 系数）：
  叉形支座简支梁在纯弯下 M_cr = π/L·√(EI_z GJ)（差 0.04%，第二阶为两倍）；跨中集中力、满跨均布荷载、悬臂端集中力 γ = 16.94、28.31、4.013（差 < 0.1%）；
  扭转荷载 GJ·A/Ip 低于欧拉荷载的柱；纯弯加轴压的梁柱 M² = (Ip/A)(P_E − P)(P_T − P)；
  混合线模型、沿 y 轴的梁、纤维截面给出同样的结果。没有闭式解的 Argyris 直角刚架（平面内受推，平面外失稳）
  与求解器自己的非线性计算对照：静力平衡状态上的共旋转切线在线性因子的 1% 以内变为奇异，推和拉两个方向都是；
  I_z = I_y/4 的悬臂在 5% 以内；方形截面和绕弱轴弯曲的构件没有侧向扭转模态。
* 弯曲屈曲与闭式解对照：悬臂柱的欧拉荷载（4 个单元偏高 3e-5，旁边加上轴力 30% 的侧向力也不变）、两端铰接柱、
  固定柱脚门架的侧移屈曲（稳定函数解，差 0.01%）、自重下的悬臂柱（Greenhill 7.837，16 个单元差 0.2%）、
  Timoshenko 柱（Engesser，误差 < 0.1%；剪切极柔时 3%）、纤维柱、弹簧支承的杆、刚性楼板下的摇摆柱。

### 11.10 线构件的弹脆性断裂与定时移除（索、吊杆、钢箱梁）

线构件模型在动力计算里可以让构件断开：构件线弹性，直到达到承载力，然后被移除（不再受力，
质量留在节点上）。写在指派上——按构件组（混合线单元模型），或一个截面指派到 `all` 时对
全部构件：

```yaml
assign:
  - {region: hang_pure, section: hanger, failure: {tensile_strength: 1.77e9}}
  - {region: rail_box, section: rail_box, orientation: [0, 0, 1],
     failure: {yield_strength: 3.7e8, extreme_fibre: [2.5, 6.5], shape_factor: 1.12}}
removals:
  - {region: cut_0, time: 3.0}        # 这个区域里的构件在计算开始后第 3 秒被剪断（多步时跨步累计）
```

* **索（杆）**：拉力达到 `tensile_strength × 面积` 即断
* **梁**：任一端 |N|/(A f_y) + |M_y|/M_y,cap + |M_z|/M_z,cap ≥ 1 即断，
  M_cap = shape_factor · f_y · I / c；`extreme_fibre` 是截面局部 y、z 方向到最外纤维的距离。
  不检查剪力和扭矩
* 判据是**承载力**而不是应变：弹性构件的应变到钢材真实断裂应变（约 15%）时应力是 3 万 MPa，
  永远到不了。承载力只需要面积、惯性矩和截面尺寸
* 没有塑性重分布和耗能，比真实结构倒得更早、更突然——偏保守。而且一到承载力就在一步之内卸掉
  全部弯矩，卸载冲击会让相邻截面跟着超限：连续倒塌里构件会"拉链"式断开，碎块尺寸就是单元长度
* **塑性铰**（mixed_line，0.5 版）：在梁的 `failure` 里加 `rotation_capacity: 0.03`（rad），每根
  构件两端就是塑性铰——端弯矩按 |N|/N_p + |M_y|/M_y,p + |M_z|/M_z,p ≤ 1 封顶（M_p 即上面的
  M_cap），超出的部分变成塑性转角并耗能，卸载是弹性的；某一端累计塑性转角到 `rotation_capacity`
  才在那一端断开，轴力到 N_p 仍立即断开。理想弹塑性、没有强化；弯矩超过屈服面最多一个时间步。塑性转角只在每步自己的内力计算里累计，与输出频率无关（1.0 版）。
  输出场 `hinge_rotation` 是较差一端的累计塑性转角（rad），`hinge_usage` 是它与转角能力之比（0 弹性，
  1 断开）；1.0 版以前 `hinge_rotation` 存的是比值。钢构件的连续倒塌
  应当用它
* **断了之后有两种做法**（`failure.split` / `removals[].split`，0.5 版）。**质点分裂**（梁和
  mixed_line 的默认）：梁在断开的那一端离开原质点、移到开始就为它预留的备用质点上（每根可断构件两端各预留一个，
  `core/topology`），另一端仍焊在结构上，之后可能在那一端再断（0.5 版）；索（杆）、定时移除和不分裂而停用的构件两端一起断开。它那份质量跟着走，构件继续是一段有刚度、有自重的自由构件——两端都断的
  一段箱梁就是一块会飞、会落到海底停住的碎片，剩下的结构少掉的正是它的重量，也不再被躺在
  海底的碎片拽着。支座上的质点（受约束的）一定复制，碎片不会留在它断开的支座上（只有当前步受约束的质点才算支座，之前某步已解除的支座视为自由）；分裂碰到的
  质点按 0.4 版的规则补足在当前步长下稳定所需的质量：每个质点补一个平动质量，x、y、z 三向相同（取三向中最大的需要），速度按 原质量/新质量 缩小（动量守恒，少掉的动能记为耗散）；补的质量**不计重量**（与水动力附加质量一样），所以一块补了质量的碎片自由下落略慢于 g（按 m/(m+Δm)）；日志写明实际补了多少 kg（1.0 版）。
  **无质量构件**（ρ≈0 的横梁、刚臂——质量抹在别的构件里）断了只移除不分裂；一簇无质量构件
  哪一端都不挂有质量构件时移除；只挂在一个有质量的质点上、且那个质点还连着支座时成为**附属件**
  （吊杆剪断后的外挑横梁），跟着该处一根有质量构件的弦线刚体运动（不跟节点绕自身轴线的滚转），
  挂在碎块上的则移除；挂在两个及以上时照常受力——它们是连接件，不是物体。无质量构件全断了
  留下的质点（不在支座上、没有节点质量）停在原处，不带着断开那一刻的速度一直滑下去。**只移除**
  （`split: false`，独立桁架的默认）：不再传力、质量留在节点上——一根剪断的吊绳这么做就够。
  分裂后的构件连接关系逐帧写在 `connectivity` 场里，`vfife view` 按它画；`diagnostics/member_splits`
  每行一次 [时间, 单元, 原质点, 新质点]。质点分裂需要 `mode: dynamic`；纤维梁走
  `fracture.split`（0.3 版）；碎片质点不属于任何区域，重力按它原来的质点所在区域作用到它上面，写在区域上的节点力不会分到碎片上（1.0 版以前纤维梁的碎片只加进 `all`）
* 不写 `contact.members`（11.12，1.11 起）时，下落的构件会穿过它下面的构件；有刚性面时落到面上停住
* 哪些模型：mixed_line（按构件组）、单一截面的 beam2 / beam2_timoshenko / truss2（`failure`
  写在指派到 `all` 的那条上，对全部构件）；`removals` 另外也用于纤维梁模型。**纤维梁不接受
  `failure`**——它的截面逐根纤维知道自己的强度，断在材料律里（`fracture`，见 11.2），或者
  用 `removals` 定时剪断；纤维梁的 `fracture` 事件也写进下面同一张 `member_failures` 表。
  只在动力计算里判；动力松弛拒绝（松弛迭代里的状态不是平衡态）
* `removals[].time` 从整个计算开始算起，多个动力步时跨步累计（纤维梁在 1.0 版以前按步内时间算，第二步的移除不发生）；晚于计算结束（步数 × `solver.total_time`）的移除 preflight 警告 `REMOVAL_AFTER_END`。
* 只移除时构件不再受力：mixed_line 把它移出批处理，beam2 把它的局部刚度置零，truss2 把面积
  置零（应力仍按应变报告），纤维梁走 `fracture` 同一个开关。用 Rayleigh 刚度比例阻尼（β）时，
  断了的构件也从参考刚度阵里减掉（分裂的构件挪到它的新质点上）——否则一个掉落的碎片会被
  一个阻尼器拴在桥面上
* 结果：单元场 `member_failed`、`capacity_ratio`（需求/承载力），`diagnostics/member_failures`
  每行一次断裂 [时间, 单元号, 断时承载力比, 原因 0=承载力 1=定时移除 2=无质量构件连接的东西没了（分裂时）]；断了的构件记在检查点里

### 11.11 非线性支座：滑动、限位与隔震滞回

连接器（`type: connector`）的每个分量可以不用线性刚度，而用一条**路径相关律** `laws`：

```yaml
sections:
  sliding_bearing:                      # 弦是竖直的：ux 竖向，orientation [1,0,0] 使 uy 为纵桥向
    type: connector
    stiffness: [1.0e+10, 0, 0, 0, 0, 0]
    laws:
      uy: {type: friction, mu: 0.05, normal: ux, stiffness: 1.0e+8}   # 库仑摩擦：粘住到 mu·N 后滑动
  expansion_joint:                      # 弦沿纵桥向：ux 是缝的开合
    type: connector
    laws:
      ux: {type: gap, lo: -0.006, stiffness: 2.0e+9}   # 6 mm 内自由，合拢后是限位刚度（碰撞）
  lead_rubber:
    type: connector
    stiffness: [2.0e+9, 0, 0, 0, 0, 0]
    laws:
      uy: {type: bilinear, k1: 2.0e+7, k2: 2.0e+6, fy: 5.0e+4}      # 双线性滞回（运动硬化）
      uz: {type: bilinear, k1: 2.0e+7, k2: 2.0e+6, fy: 5.0e+4}
  viscous_damper:                       # 弦沿纵向：ux 是阻尼器的行程（1.10）
    type: connector
    laws:
      ux: {type: damper, c: 2.5e+6, exponent: 0.3, linear_below: 0.005}   # F = c·sign(v)·|v|^0.3
  friction_pendulum:                    # 弦竖直，同滑动支座（1.10）
    type: connector
    stiffness: [1.0e+10, 0, 0, 0, 0, 0]
    laws:
      uy: {type: pendulum, mu: 0.05, radius: 3.0, normal: ux, stiffness: 1.0e+8}
      uz: {type: pendulum, mu: 0.05, radius: 3.0, normal: ux, stiffness: 1.0e+8}
```

* `damper`（1.10）：液体粘滞阻尼器，F = c·sign(v)·|v|^α，作用在该分量的变形**速率**上，0 < α ≤ 1
  （α = 1 就是 `connector_damping` 的线性阻尼器）。`c` 的单位是力/速度^α（按算例声明的单位）。只在**动力**步里起作用
  （静力、松弛步只看到可选的并联弹簧 `stiffness`）。**速度低于 `linear_below` 时按线性** F = c·v₀^(α−1)·v：
  幂律在 v = 0 处斜率无穷大，显式积分会在零速附近来回抖。α < 1 时必须写 `linear_below`，取设计速度的 1% 左右
  （一个循环里少算的耗能约为 0.1·(v₀/v_max)^(2+α)：取 1% 时 3e-6，取 20% 时 3e-3）；取得越小越接近幂律，稳定步长也越小
  （dt < 2m / (c·v₀^(α−1))，求解器自动满足）。对照：弹簧—阻尼器—质量的细步长龙格库塔积分（tests/test_seismic_devices.py）
* `pendulum`（1.10）：摩擦摆支座——库仑摩擦 μN（同 `friction`）加球面的恢复力 (N/`radius`)·d，两者都跟着支座**当时**的压力 N
  （`normal: ux` 或常数）。按恒载拟合的 `bilinear` 跟不了竖向地震和倾覆力矩引起的压力变化，这条律可以。
  滑动后结构的周期是 2π√(R/g)，与质量无关。压力为零（脱空）时水平向不受力（量压力的 ux 弹簧是线性的，脱空后仍会拉住梁；ux 要用 `gap` 律时 `normal` 只能写常数）。`uy`、`uz` 上同写时按平面内一条律处理。
  双摆、三摆按等效半径写；摩擦系数随速度的变化没有模拟
* `friction`：`normal: ux` 取同一连接器局部 ux 线性弹簧**当前**的压力为压紧力——
  梁抬起（压力为零）时滑动力也为零；也可以写一个常数。只能是 `ux`：其他分量的正负随 Line2
  节点顺序翻转，整体坐标的连接器也不能用分量名`stiffness` 是粘着刚度，越大越接近
  理想库仑，也越缩小稳定步长
* `gap`：`lo`/`hi` 给自由行程的两端，缺一侧即该侧无限位；局部 ux 是伸长，所以 `{lo: 0}` 是只受压的支承、
  `{hi: 0}` 是只受拉的拉杆（1.0 版以前文档写反了）。gap 分量上的 `connector_damping` 只在间隙闭合时起作用
* `uy`、`uz` 上写**同一条**律（摩擦、双线性或摩擦摆）时按平面内一条律处理：沿合力方向屈服、滑动，屈服面是圆
  （1.0 版以前是两条独立的律，屈服面是方的，45° 方向摩擦力为 1.414 μN）
* `bilinear`：初始刚度 `k1`、屈服力 `fy`、屈服后刚度 `k2`，运动硬化——铅芯橡胶支座、摩擦摆、
  屈服耗能装置的骨架；一个滞回环耗能 4(f_y − k₂u_y)(u_max − u_y)
* 每个分量一条律或一个刚度，不能同时；律的历史（滑移量）进检查点，输出场 `connector_slip_*`
* **静力**下每一级荷载的每次评估都从上一个平衡态的滑移出发（与纤维材料的处理一样），到平衡
  才提交；**动力**下每步提交。所以静力的摩擦、滞回是按加载路径的分级走的，级数要够分辨路径
* 桥梁里的"碰撞"多数是这三样：梁端撞桥台（gap）、支座滑动（friction）、隔震（bilinear）；
  它们发生在已知的两点之间，不需要接触搜索。算例 case_32
* **支座连接器要建得短。** 两端转动不同时，连接器的平动变形是在两端的平均框架里量的：一根
  1 m 长的竖直支座会把梁端转角 θ 读成 θ/2 × 1 m 的纵向滑动（恒载下的转角就能给出几毫米）。
  锚固节点放在梁端下方 10–50 mm 即可

### 11.12 刚性面接触：地面、海底、承台

```yaml
contact:
  rigid:
    - {name: seabed, plane: {point: [0, 0, -40], normal: [0, 0, 1]}, damping: 0.5}
    - {plane: {point: [0, 0, 0], normal: [0, 0, 1]}, region: deck_nodes, friction: 0.3}
```

一个刚性、不动的面，`region`（默认全部）里的节点碰到它就受一个罚力：法向弹簧乘穿透量，
动力下可加库仑摩擦（`friction`，对切向速度）和接触阻尼（`damping`，碰撞不再完全弹性，碎片会
停下来）。法向指向允许的一侧。没有配对、没有主从、没有搜索——每个节点对每个面几次点积。

* `stiffness: auto`（默认）按每个节点的质量和步长取 k = m(2/dt)²/4：接触弹簧自己的 ω·dt = 1，
  与结构的 ω·dt ≤ 1.2 合在一起仍在中心差分的稳定极限 2 以内，所以**步长不会因接触缩小**；
  静置的节点穿透 g·dt²，微米量级。给数值的 `stiffness` 以同一个值为上限（更大就不稳定，1.0 版以前照用不误）。自由飞行的碎片没有自己的刚度可借尺度，`auto` 正是为它
* 一次碰撞只持续几步，恢复系数不是可控的量；要看反弹高度就给一个软一些的 `stiffness`
* 摩擦是速度律，只在动力计算里；松弛下给 `friction` 或 `damping` 会拒绝。静止在粗糙面上的
  节点在低于 μN 的切向力下会以正则化速度（0.1 mm/s 量级）蠕动，不是严格粘住；要粘住用连接器的
  `friction` 律（11.11 节）
* 开始时就在面后面的节点按名字拒绝——接触不负责把模型推回原位
* 限定 `region` 的面，也挡得住从这个区域的节点上分裂出去的碎块（1.0 版以前碎块会穿过去）
* 刚性面不认识构件：它不知道截面的厚度，停下的是节点。构件**之间**的接触是下面的 `contact.members`
* 结果：节点场 `contact_force`、`contact_penetration`。有接触面时，preflight 对自由体的机构
  检查降为警告——面就是它的支承。算例 case_33（剪断吊绳的梁落地）

**构件之间的接触（`contact.members`，1.11）。** 落梁砸在下层桥面上、梁端撞相邻梁、断掉的吊杆甩过其他吊杆、倒塌后的堆积：

```yaml
contact:
  members:
    bodies:
      - {region: upper_deck, radius: 1.2}    # 每根构件是绕轴线、这个半径的胶囊体
      - {region: lower_deck, radius: 1.0}
      - {region: hangers}                    # 杆和索：`auto`，取与截面等面积的圆
    friction: 0.4
    damping: 0.3
```

* 线单元没有体积，接触里它是一个**胶囊体**：到轴线距离不超过 `radius` 的点。两根构件的轴线距离小于半径之和就算接触，
  沿两轴线的公法线互相推开：对重叠量的罚弹簧，动力步里再加阻尼器（`damping`）和库仑摩擦（`friction`，正则化方式同刚性面）。
  各组之间、组内的构件都互相检查，共用节点的除外；连接器不参与
* **`radius` 由建模的人给**：梁必须写（截面没有说它的表面在各个方向上离轴线多远）。宽 12 m、高 2 m 的箱梁平着落下时按半径 1 的胶囊算，
  它的边缘在哪里没有模拟。`auto` 只用于杆和索
* 接触力按最近点的权重分到两根构件的节点上，与作用在接触点的力静力等效；摩擦作用在接触点上、偏离轴线，所以也会扭转构件（滚动的圆木会慢下来）
* `stiffness: auto`（默认）：k = m/dt²，m 是这一对的折算质量（每一步都被约束住的节点按无穷大算），再除以最忙的那个节点上的接触数——
  **步长不会因接触缩小**，搁在别的构件上的构件重叠几十微米。写数时以它为上限。摩擦的正则化把力臂算了进去，会滚动的构件也在稳定步长之内。
  杆和索不承受力偶（接触点取在它们的轴线上）
* **多快算太快**：两根构件一步里靠近的距离不能超过半径之和的一半左右（接近速度 × dt < 0.5 (r₁ + r₂)），否则会互相穿过。
  主梁远远到不了；质量缩放下的细索有可能（r = 0.07 m、dt = 1e-3 s 时是 70 m/s）
* **开始时就重叠的不管。** 主梁通过支座搁在盖梁上方 30 mm；按真实半径，两个胶囊在什么都没发生之前就重叠了一米。
  参考构形里重叠的、或者离接触不到 `slack`（默认较小半径的 5%）的每一对，把当时的重叠量加上 slack 记作**容许量**：接触只对超出的部分起作用。
  slack 是留给它们之间的支座工作的（不留的话，比任何支座都硬得多的接触弹簧会把恒载从支座上接走）。容许量只减不增，随这一对分开而减小，
  分开超过 slack 后清零。所以支座失效的主梁下落一个 slack 之后，从原来的位置落在盖梁上。从相邻构件上断开的构件，在断开的那一步得到容许量
  （只给断口两侧的那一对），后面的分析步里出生的构件也一样。开始时离接触不到 slack 的一对，因此在接触起作用之前最多可以重叠一个 slack。
  日志里会写有多少对是这样开始的；容许量进检查点
* `mode: static` 拒绝它（用松弛，松弛可以；`friction` 和 `damping` 只在动力步里起作用）。两根很长、几乎平行的构件只有**一个**接触点，
  倾斜时它会从重叠段的中点跳到一端
* 没有模拟的：截面的形状（见上）、与实体网格的接触、碎块粒子的接触（停放的粒子没有构件；`contact.rigid` 仍然能在地面挡住它）。
  静止在斜面上的构件会以正则化速度蠕动
* **速度**：1.12 起 `contact.members` 在编译的整步里算（`backend: numba` 下的梁、杆、连接器，以及纤维梁），与逐步的循环逐位相同——
  接触的一次计算是一个编译函数，两条路调用的是同一个。2 核容器：西堠门（1207 根构件全部参与接触）18758 步 20.4 → 9.8 s，
  不带接触是 9.3 s；case_34 全部构件参与接触 33.1 → 3.4 s（不带接触 2.6 s）。接触对的搜索用邻居表，有节点移动超过最小半径的四分之一才重建。
  有刚性面（`contact.rigid`）的模型仍走逐步的循环，带接触的松弛也是。带 `fracture` 的纤维模型在 1.12.0 里走循环，之后也走编译的整步
  （纤维点断裂的那一步由循环走完，循环在那一步的接触之前把断掉的构件拿走；主梁断裂后砸在下面的梁上，18.8 → 2.4 s）
* 结果：`contact_force`、`contact_penetration`（与刚性面的合在一起）。对照：一根梁落在另一根上，t = √(2(h − r₁ − r₂)/g) 时接触，
  静止后两轴线相距 r₁ + r₂，支座反力等于它的重量；两根自由梁碰撞动量守恒到舍入；在两根轨道上滑动的梁滑行 v²/(2μg) 后停下（tests/test_member_contact.py）

### 11.13 桩的土弹簧：按深度给的 p–y 曲线（1.2）

```yaml
soil_springs:
  - region: pile                     # 桩的构件区域
    ground: 0.0                      # 地面高程（沿 vertical 的坐标）
    vertical: z
    direction: horizontal            # 水平面内径向；平面模型写 x 或 y
    curves:                          # p：单位桩长的土抗力；y：桩的水平位移（都按算例声明的单位，SI 下 N/m 与 m）
      - {depth: 0.0,  p_y: [[0, 0], [0.005, 4.0e+4], [0.02, 9.0e+4], [0.05, 1.2e+5]]}
      - {depth: 10.0, p_y: [[0, 0], [0.005, 1.6e+5], [0.02, 4.0e+5], [0.05, 5.2e+5]]}
```

* 区域里地面以下的每个节点得到一个水平弹簧：力 = 该深度的曲线 × 该节点代表的桩长（相邻构件埋入部分
  按线性形函数分给两端；穿过地面的构件，露出地面的一端也分到一份，取地面处的曲线）。深度之间按同一 y 线性插值；浅于第一条取第一条，深于最后一条取最后一条；
  曲线最后一点之后 p 不再增加（极限抗力）。曲线从 [0, 0] 起，y 递增，p 不为负。
* **曲线由用户给**：API、JTG 3363 等规范公式不在库里，按土层参数算好填进来。
* **非线性弹性**：加载、卸载走同一条曲线，没有滞回耗能，也没有桩后间隙。静力推覆、恒载状态、模态、
  屈曲用它；地震时程里它本身不耗能（Rayleigh β 阻尼会按弹簧的最大斜率给它一些阻尼），辐射阻尼要另外考虑。
  弹簧只抗水平位移：斜桩的轴向运动在水平面上的分量也会被它抵抗。支座带 `record`（多点激励）时拒绝：
  弹簧按绝对位移算，土不会跟着支座的记录动；一致激励 `ground_motion` 是相对位移，可以用。`direction: horizontal` 时按两个水平位移的合量取抗力
  （斜向推与正向推遇到同样的土），有势能，所以切线对称。
* 土是支座：土对桩的力计入 `reaction_force` 场和 `kind: reaction` 监测量，`vfife summary` 的反力和里也有它；
  preflight 把地面以下的桩节点算作水平受约束。弹簧的最大斜率计入显式步长和松弛质量的参考刚度。
* 适用于 beam2、Timoshenko、纤维梁、混合线模型；杆（truss2）、壳、实体拒绝。没有 t–z（桩侧摩阻）和 q–z（桩端），
  竖向请用约束或连接器。
* 与闭式解对照：长桩桩顶受水平力（Hetenyi 弹性地基梁，y0 = 2Hβ/k）：自由桩顶 60 个单元低 0.48%，随单元长度
  二阶收敛（地面落在单元中间时也是）；固定桩顶、刚性短桩（4H/kL、H/kL）、纤维截面桩、模态（√(k/ρA)）、
  Winkler 地基上的屈曲都对上。曲线第二点的 p 必须大于 0（没有初始刚度的土挡不住桩）。

### 11.14 框架模型的钢束块 `tendons:`（1.20 版）

框架模型（梁、杆）的后张粘结钢束可以一束写一条，读入时由程序展开：

```yaml
tendons:
  - name: T1                         # 钢束名；展开出的区域是 T1/bar1、T1/arm1……
    nodes: girder                    # 它粘结的主梁节点：网格的一个组
    section: strand                  # bar 截面：一根钢绞线的面积和材料
    count: 12                        # 孔道里的根数
    line: {origin: [0, 0, 0], direction: [1, 0, 0]}   # 参考线；可加 turn（度）
    profile_z:                       # 竖弯：[x, z, 半径]，折角按半径倒圆
      - [0.0, 0.0, 0]
      - [15.0, -0.8, 40]
      - [30.0, 0.0, 0]
    stress: {step: 张拉, ends: both, stress: [1.395e9, 1.395e9]}   # 或 force: [整束的力, ...]
    friction: {mu: 0.17, k: 0.0015}
    draw_in: {begin: 0.006, end: 0.006}
    relaxation: {code: jtg3362, fpk: 1.86e9, zeta: 0.3}           # 可选
```

* 展开的结果与 1.15 起 Midas 转换器写出的相同（1.15、1.16 版）：
  * 主梁组里落在钢束长度内的每个节点，以及离两个锚点最近的节点，各对应一个钢束节点；
  * 每个钢束节点用一根刚臂连到主梁节点；
  * 相邻钢束节点之间是一段杆，张拉到扣除摩擦和锚具回缩后它中点处的力（`jack`）。
* 杆在张拉它的那一步出生；刚臂和钢束节点随该处主梁出生，钢束不会因主梁已经下挠而错位。
* 钢束材料复制截面的材料、去掉重量（主梁的重量里已含孔道）。有 `relaxation` 时，每段按它锚固后的应力得到松弛曲线，与 11.3 节相同。
* 展开出的节点和单元排在网格原有的之后，原有节点的行号不变。
* 不成立的写法按名拒绝（HIGH_LEVEL_BLOCK），例如组不存在、截面不是 bar、步名不存在、剖面点不前进。只能近似处理的情况在 preflight 里给 TENDON_APPROXIMATE 警告：锚点在构件之外、节点离参考线太远、局部超过 fpk。
* 只用于 Gmsh 网格上的框架模型。纤维梁的预应力束仍写在截面里（11.1 节）。
* `vfife expand model.yaml -o flat.yaml` 写出展开后的算例和网格（MSH 2.2），只用来查看、核对；两者计算结果逐位相同。
* 结果文件按钢束记下它展开成的杆（1.20 版）：`tendons` 组下每束一个子组，有钢束名、根数、面积、两端的张拉力、张拉的步，以及沿钢束依次的杆——在结果里的单元行号（`axial_force` 的行）、区域名和每根杆张拉到的力。`vfife tendons 结果.h5` 由它打印钢束力表（12.3 节）。
* Midas 转换（5.3 节）从 1.20 版起把钢束写成这个块，按 Midas 的结构组写 `groups`、短列表写成一行，写 `tendon_defaults` 和剖面 CSV，偏心刚臂写成一条规则（11.16 节）。连续刚构的算例从 6.8 万行降到约 1,300 行，连续梁从 3.6 万行降到约 900 行，连续 T 梁从 9.1 万行降到约 2,400 行（另有钢束剖面的 CSV）。剩下的主要是每束钢束的名字、节点组和偏移，以及变截面梁每个单元一个的截面。`convert(..., expanded=True)` 仍写出展开后的形式。

**各束共用的设置 `tendon_defaults:`（1.20 版）。** 各束相同的键只写一次：

```yaml
tendon_defaults:
  nodes: girder
  section: strand
  count: 12
  profile_z: {table: 钢束_z.csv}      # 有 name 列：每束取自己名字的行
  stress: {ends: both, stress: [1.395e9, 1.395e9]}
  friction: {mu: 0.17, k: 0.0015}
tendons:
  - {name: T1, line: {origin: [0, 0, 0], direction: [1, 0, 0]}, stress: {step: 张拉1}}
  - {name: T2, line: {origin: [0, 0, 0], direction: [1, 0, 0]}, stress: {step: 张拉2, ends: begin}, relaxation: null}
```

* 钢束没写的键从这里取；`stress`、`friction` 这类映射逐键合并，钢束自己写的键优先。上例 T2 只在开始端张拉，其余照共用的设置。钢束的 `stress` 里写了 `stress` 或 `force` 时，共用设置里的这两项都不再取（两者只能有一个）。
* 钢束里写 `null` 就是它自己的值：`relaxation: null` 表示这一束不松弛。
* 可以写钢束的任何键，`name` 除外；写错的键拒绝（HIGH_LEVEL_BLOCK）。
* 剖面写成 `{table: 文件.csv}` 而文件有 `name` 列时，每束取自己名字的行（11.15 节）；钢束自己写 `profile_z: {name: T9}` 时，与共用的表合并，取 T9 的行。
* 可以放在 `include` 的文件里；那里写的表格路径相对那个文件。与本文件重名按键比较，`override: true` 时以本文件的整个键为准（不逐键合并）。
* Midas 转换从 1.20 版起这样写：每束都有、且多数束相同的键写进 `tendon_defaults`，剖面写进 `模型名_tendon_z.csv`（平弯 `_y`）。短形式与 `expanded=True` 的长形式计算结果逐位相同。

### 11.15 `include:`、`groups:` 和 `table:`（1.20 版）

这三种写法都不需要网格，读入时先于钢束块展开。`vfife expand` 同样写出展开后的算例。

```yaml
include: [库/材料.yaml, {path: 库/截面.yaml, override: true}]
groups:
  悬臂: [L1, L2, R1, R2]             # 网格的组或别的组
  主梁: [悬臂, 合拢段]
steps:
  - {name: 悬臂施工, activate: [悬臂]}
  - {name: 合拢, activate: [合拢段], loads: [{table: 二期.csv, keep: true}]}
tendons:
  - {name: T1, ..., profile_z: {table: 钢束.csv, name: T1}}
```

* **`include`**：
  * 把文件里的 `materials`、`sections`、`reinforcement`、`groups`、`tendons`、`tendon_defaults` 并进来，路径相对本文件；被包含的文件可以再包含别的文件。
  * 同一个名字两边都有时拒绝；写成 `{path: ..., override: true}` 时以本文件的为准。
  * 被包含的文件里有别的块（如 `steps`、`solver`）也拒绝：参数只在一个地方。
* **`groups`**：名字 → 网格的组或别的组的列表。
  * 读入后它就是网格里的一个组，单元和节点都是各部分的，相当于 Gmsh 里一个由几块组成的物理组；凡是写区域名的地方都可以用它，含义都一样。例如对组 `assign` 一根索，`unstressed_length` 是整个组的长度。
  * 只能由网格的组组成，不能包括盒子、平面这类在算例里写的区域：它们没有单元。
  * 组名不能和区域、网格的组或 `all` 重名。
  * 它降级为 `mesh.groups`，`vfife expand` 写出的就是这一项。
* **`table`**：CSV 文件，首行是表头，`#` 开头的行是注释，单位跟 `units`。
  * 钢束剖面的列是 `x, z, radius`，平弯用 `x, y, radius`。有 `name` 列时，用 `name:` 从一个文件里挑出一根钢束的行；不写 `name:` 时取这束钢束自己名字的行（1.20 版；表里只有一个名字而不是这束的，仍取全部行，与以前相同）。`name` 列的值去掉首尾空格；一行的第一格以 `#` 开头就是注释，所以 Midas 转换把 `name` 列放在最后。
  * 逐节点荷载的列是 `region`，或 `x, y, z`（取最近的节点），再加 `fx, fy, fz, mx, my, mz`，缺的列为 0。每一行成为一条 `per_node` 荷载，可加 `keep`、`amplitude`。
  * 逐节点质量的列是 `region` 或 `x, y, z`，再加 `mass`，可加 `weight`、`components`。
* Midas 转换从 1.20 版起这样写：
  * 一个施工阶段建完一个结构组的全部区域时，`activate` 里写组名，组只在 `groups` 里写一次；
  * 截面、指派、钢束的参考线这些只含数字的条目写在一行里。

### 11.16 偏心构件的刚臂 `offset_arms:`（1.20 版）

Midas 的主梁常按截面顶缘画（偏心 CT），构件实际在形心线上：转换器在每个画出的节点下面加一个形心节点，用一根刚臂连起来（1.15 版）。刚臂的刚度取它所连偏心构件刚度的若干倍，所以每根刚臂原来各有一个截面——转换出的连续 T 梁有 846 个。现在写成一条规则：

```yaml
offset_arms:
  material: rigid          # 刚臂的材料（取它的 E）
  factor: 30.0             # 所连偏心构件刚度的多少倍
  limit: 1.0e13            # 一个构件传给刚臂的刚度上限（力/长度；不写为 1e13 N/m，按 units 换算）
  regions: [E266, E267, ...]   # 刚臂：每个区域一根杆，从画出的节点到形心节点
```

* 读入时按网格算出每根刚臂的截面。形心端连着的梁，另一端也是所列刚臂的形心节点的，算作偏心构件；画在形心上的墩柱不算。
* 每个偏心构件沿轴向传 EA/L 和 12EIy/L³ 中较大的（不超过 `limit`），转动传 4EIy/L（不超过 limit·L²/3），L 是构件画出的长度。刚臂取各项的最大值，按自己的长度 r：面积 = factor·沿轴向·r/E，iy = iz = factor·max(转动·r, 沿轴向·r³/12)/E，j = 2iy。方向取整体 Z，接近竖直（超过 45°）的取整体 X。
* 梁的刚度从 `assign` 读：区域要是网格的组（或 `groups:` 里的组、网格的节点组），截面要写出 `area`、`iy`，材料要有 `E`。偏心构件的截面按尺寸给出、或梁指派在算例里写的区域（盒子、平面）上，都拒绝，而不是悄悄跳过。
* 相同的截面只写一个，名字是 `offset_arm_1`、`offset_arm_2`……，所以算例里不能再有这样命名的截面；刚臂的区域也不能另有 `assign`。区域不是一根杆、写了两次、形心端没有偏心构件、材料不存在，都拒绝（HIGH_LEVEL_BLOCK）。
* Midas 转换从 1.20 版起这样写。网格里坐标只到 12 位有效数字，规则算出的刚臂刚度与以前转换器直接写的差约 1e-11 以内；对不上的刚臂（偏心构件是短刚接段之类）保留自己的截面，改名为 `offset_arm_own_1`……，其余刚臂照样用规则。`vfife expand` 写出每根刚臂的截面。

## 12 结果输出与后处理

### 12.1 输出设置

```yaml
output:
  path: results/pc_beam.h5
  every: 1                     # 每隔多少步写一帧（分级松弛每级一帧）
  fields: [displacement, rotation, reaction_force, fiber_stress, fiber_damage]
  monitors:
    w_mid:  {kind: displacement, region: mid, dof: z}
    R_left: {kind: reaction, region: left, dof: z}
    sigma_p: {kind: bar, of: tendons, field: axial_stress, reduce: mean}
    dc_span: {kind: element, field: dc, reduce: max, region: span_block}
    eps_bot: {kind: fiber, region: mid, field: strain, at: [0.0, -0.6]}      # [y, z]：1.2 m 高主梁的底面
    sig_bar: {kind: fiber, region: mid, field: stress, at: [0.0, -0.55], fiber_kind: steel}
```

`path` 的相对路径按**当前工作目录**解析（运行命令的目录），不是算例文件所在目录；网格、地震记录、
`initial_state` 等其他路径才相对算例文件。

**字段**（`fields`）是全模型的场量，写在每个输出帧里。一个单元能输出哪些字段，用
`python -m vfife describe <单元>` 查（`output_fields`）；写了不存在的字段在运行前被拒绝。
不写 `fields` 时按模型给默认（1.1）：`displacement`、`rotation`、`von_mises`（实体、杆）、壳的 `von_mises_top/bottom`、
`reaction_force`、`reaction_moment`，构件的带符号内力 `axial_force`、`shear_y`、`shear_z`、`torsion`、`bending_y`、`bending_z`，
有塑性铰时 `hinge_rotation`、`hinge_usage`，有连接器时 `connector_force`、`connector_moment`、`connector_deformation`，
构件能断时 `member_failed`、`capacity_ratio`；模型给不了的名字不写、也不报。不在默认里的：两端内力（`end_actions`）、
包络（`*_max_abs`）、纤维应力与损伤（每根纤维每帧一个数，按名索取）。1.0 的默认是 `[displacement, von_mises]`，
梁和杆模型只写位移。`fields` 里写出的名字模型给不了则拒绝（`UNKNOWN_OUTPUT_FIELD`）；写了 `fields` 就只写所列的。
有几个名字代表一组字段：`end_actions` 写出两端的六个内力（`axial_force_i` … `bending_z_j`），
`connector_force`、`connector_moment`、`connector_deformation`、`connector_slip` 写出各分量（力写作
`connector_force_x/y/z`、`connector_moment_x/y/z`，变形和滑移按分量写作 `_ux` … `_rz`），壳的
`membrane_resultants`、`bending_resultants`、`shear_resultants` 写出各合力分量。

**监测量**（`monitors`）是一条时程曲线：

| kind | 读什么 |
|---|---|
| `displacement` | 区域节点的位移分量（`relative_to: <区域>` 读相对位移） |
| `reaction` | 区域节点的反力合力 |
| `element` | 区域内单元的某个输出量（实体：材料输出；线单元模型：任一构件场，如 `axial_force`、`bending_y_max_abs`），按 `reduce`（max/min/mean/absmax）归约 |
| `bar` | 一组钢筋（指派时的 `name`）的轴向应力、轴力、塑性应变 |
| `fiber` | 纤维截面上指定位置 `at: [y, z]` 的应变或应力（y 沿截面宽度，z 沿截面高度） |

`bar` 只在实体模型上，`fiber` 只在纤维梁上，`element` 在实体和线单元模型（壳除外）上；`reduce` 只用于 `element`/`bar`。
静力计算不写 `every` 时每个增量一帧。`fiber` 的点在截面外轮廓之外时拒绝（`FIBER_MONITOR_OUTSIDE`，1.0 版：本手册曾印过的
`at: [-0.6, 0]` 读的是 0.5 m 宽截面侧面半高处——4e-5，而底面是 1e-3）。`field: stress` 取最近的纤维，写
`fiber_kind: concrete | steel` 时只在混凝土或钢筋/预应力束里找；读的是哪根纤维（单元、积分站、坐标、种类、本构）写在结果里该
监测量的 `read_*` 属性上（docs/result_format.md）。写了模型记录不了的，preflight 报 `MONITOR_UNSUPPORTED`
（过去梁模型把它当位移记下来，或者记 0）。动力与松弛计算的监测量在输出帧上记录；静力计算在每个增量都
记录，`every` 只稀疏帧。两种情况下 `time` 都与每条监测量一样长。`time`、
`residual`、`kinetic_energy`、`age` 是保留名，不能作监测量名（1.0 版）。

**检查点**：`checkpoint_every: N` 约每 N 步把检查点写到结果旁的 `<结果>.ckpt.h5`（在帧或进度检查处取；
N 小于进度间隔时进度间隔降到 N；1.0 版以前只在步号能被 N 整除的输出帧上写）。计算结束和被停下时
也写一个（最终状态不是有限值时除外）。

### 12.2 结果文件

结果是 HDF5 文件，旁边有一个 XDMF 描述文件：

* `monitors/`：每条监测量和 `time`
* `steps/<步号>/`：每帧的场量，如 `displacement (节点, 3)`、`fiber_stress (单元, 积分点, 纤维)`
* `diagnostics/`：能量账（外力功、内能、动能、耗散）与收敛记录
* 属性 `case_yaml`：运行时的完整算例，结果永远能追溯到输入

在 ParaView 中打开 `.xdmf`；较老的 ParaView 读时间序列报错时，打开 `_last.xdmf`（只有最后
一帧）。六分量的场（实体的应力、应变）写成 `Matrix`，另外每个分量单独一个标量：`stress_xx`、
`stress_yy`、`stress_zz`、`stress_xy`、`stress_yz`、`stress_zx`（与存储顺序、监测量和契约的名字一致；1.0 版以前叫
`stress_xz`）——着色时选这些分量，不要依赖
ParaView 对六分量张量的排序（`Tensor6` 的顺序与本程序不同，1.0 版以前标错过）。节点量画在
节点上、单元量画在单元上；断开成质点的构件每一帧用它自己的连接关系。

`monitors/` 下的 `residual` 与 `kinetic_energy` 是**收敛序列**，在每次进度检查时取样，不在输出
帧上取，所以长度与 `time` 不同。分级松弛现在在每个增量内的每次进度检查都记录收敛序列（1.0 版）。

构件内力带符号（1.0 版）：`axial_force` 拉为正；剪力、扭矩、弯矩在构件局部轴、外法线为 +x 的截面上按右手定则取号（局部 z
向上时下挠弯矩为负）；取两端中绝对值大者并保留符号，纤维梁取绝对值最大的积分点。原来的无符号值是 `*_max_abs`。`*_i/_j`
是节点作用在构件上的端力（截面内力 = −i 端、+j 端）。已破坏的构件读 0。续算结果的 `member_failures`/`member_splits` 含全部
历史，前 `rows_before_restart` 行已在原文件里。完整说明见 docs/result_format.md。

完整布局（组、数据集、形状、节点量/单元量、单位、帧命名、各模式下 `time` 的含义、属性和版本规则）
见 docs/result_format.md。结果格式 3（1.0 版）：检查点在单独的 `.ckpt.h5` 里；算例声明的单位写在
根属性 `unit_length`、`unit_force` 等里；`equilibrium` 总是字符串 `"true"`/`"false"`/`"not_applicable"`；
表格带 `columns`/`dims` 属性；静力和松弛结果在 XDMF 里的时钟是记录序号 0、1、2…（弧长法的 λ 会回退），
荷载因子 λ 和龄期作为场数据 `load_factor`、`age`；`_last.xdmf` 只有六个应力分量标量，没有 `Matrix`。

### 12.3 曲线与表格

```bash
python -m vfife plot results/pc_beam.h5 --x w_mid --y R_left    # 监测量曲线 -> PNG
python -m vfife export results/pc_beam.h5                        # 全部监测量 -> CSV
```

导出的 CSV 以 `time` 为第一列，不含收敛序列；要它们时单独点名（`residual`、`kinetic_energy`），
得到以 `check`（第几次进度检查）为第一列的表。两类混在一起点名会被拒绝（`MIXED_SAMPLING`）；
画图时收敛序列用自己的横轴。坐标轴的单位取自算例声明的 `units`（未声明时按推荐的 m、N；1.0 版
以前不管算例用什么单位都标 m、N）。叠放的曲线面板在纵轴上标名称与单位，描述放在面板标题；横轴为 `time [s]` 或
`load factor (completed steps + λ)`。只有一两条记录的序列画成点（单帧结果以前是一张空图）。

**结果摘要**（1.1）：`vfife summary <结果.h5>` 打印一页，在画任何图之前先看：

* 算完了没有、算出的是不是答案（状态、收敛、帧数、残差）；
* 模型的质量、`gravity` 施加的重量、`line_load` 与节点力的合力（最后一步的荷载，各取其幅值在步末的值），以及最后一帧的反力和；
  静力或松弛结果另给"反力 / (重量 + 线荷载 + 节点力)"，荷载只有这些、且这一帧平衡时它等于 1——
  一个按截面算重了 2.8 倍的模型（1.0 版）在这一行上就看得出来；
* 所有帧里最大的位移（总量和各分量）、转角、构件的带符号内力（最大与最小）、应力、连接器力，
  各给出节点或单元、位置和时刻；最先破坏的构件和最后一帧破坏的个数；
* 能量平衡的相对误差（终值与最大值）；每个监测量的终值与范围。

```bash
python -m vfife summary results/pc_beam.h5            # 一页文字
python -m vfife summary results/pc_beam.h5 --json     # 同样的内容，JSON
```

质量、重量和线荷载在运行时写进结果的根属性（`model_mass`、`model_weight`、`model_line_load`）。
1.1 以前写的结果没有它们，加 `--case <算例>` 由算例重建模型得到。只读结果文件里有的字段：
构件内力要在 `output.fields` 里（不写 `fields` 时默认就有，12.1）。

**钢束力表**（1.20 版）：算例有顶层 `tendons:`（11.14 节）时，`vfife tendons <结果.h5>` 按步列出每束钢束在该步最后一帧的力——沿钢束各杆的最小、平均、最大轴力，以及平均值与张拉力之比：

* 张拉之前的步记为“还没张拉”；张拉的那一步，各杆的力正是它张拉到的力（比值 1），以后各步的变化就是弹性压缩、松弛等损失；
* `--bars` 每根杆一行；`--csv 文件` 写成 CSV。表的列是 `tendon, step, time, least, mean, largest, of_jack`（最后一列是平均值/张拉力）；加 `--bars` 时是 `tendon, bar, region, step, time, force, jack`；
* 一步取它最后一帧：正常算完就是步末；中途停下的计算，最后一步取的是停下时的那一帧；
* 要求结果里有 `axial_force`（默认就有）。1.20 版以前写的结果没有 `tendons` 组，要重新计算；`vfife expand` 写出的展开算例已经没有 `tendons:`，它的结果也没有这个组。组的格式见 result_format.md。

```bash
python -m vfife tendons results/model.h5
python -m vfife tendons results/model.h5 --bars --csv bars.csv
```

### 12.5 三维回放网页：`vfife view`

网格交给 Gmsh，大规模的后处理交给 ParaView（1.3、12.2、12.4 节）。这里的两种网页都是只读的。模型页面显示只有 vfife 才知道的东西：支承、连接器、钢束和分析步。结果页面回放计算过程，构件按截面尺寸画，断裂和监测量都在里面，是一个用浏览器就能打开的文件。它们不能编辑模型，也不打算扩展成前后处理程序。

```bash
python -m vfife view results/case_33_falling_beam.h5            # -> results/case_33_falling_beam.html
python -m vfife view results/case_23_suspension_bridge.h5 --case cases/case_23_suspension_bridge.yaml
python -m vfife view results/d1_act1_typhoon.h5 results/d1_act2_quake.h5 results/d1_act3_cut_k3.h5 \
    --case cases/d1_act3_cut_k3.yaml --names "台风,车流+地震,断吊杆 3 处" --max-frames 300 -o demo.html
```

把一个结果文件写成**一个自带数据的网页**：任何线单元、壳、实体（含耦合模型和它的钢筋）的结果，
在浏览器里旋转、缩放、按时间回放。给几个**同一模型**的结果文件，它们成为一页里的几幕（按钮切换，
`--names` 给幕名；同一模型的结果即使因断裂预留的备用质点数不同也可放在一页）。给 `--case`，线构件按截面画尺寸：有形状的按 b/h、d 画，`general` 截面按
A、I 反推（钢按薄壁 h = √(4I/A)，混凝土按实心 √(12I/A)，按 E 区分），索按面积的等效直径；
`--hide rigid,arm` 不画建模用的刚臂、连杆；`--fields a,b` 只放这几个场（页面有体积上限时用）。
`--case` 读不了或与结果不是同一个模型、`--hide` 的区域不存在或不含构件、`--fields` 里有结果中没有的场、
`--names` 的个数与结果文件数不同，都会报错，不再静默忽略。`--fields` 可写字段组名（如 `end_actions`，
展开为结果中有的分量）；结果中有但页面不画的字段（如 `rotation`）会说明只画每节点/每单元一个值
（向量画模）。`--hide` 只用于线构件模型，实体或壳加线构件的模型会报不支持。`--names` 中的空项被忽略。
要画**真实截面外形**（例如流线型箱梁、塔柱）时，从 Python 调 `vfife.post.view.write(...,
profiles={区域: {"outline": [[y, z], ...], "outboard": True}})`：按区域给截面外轮廓（米；y 沿构件宽度、
z 沿构件高度——梁高竖直，近竖直的塔柱则 z 沿桥轴），`outboard` 让轮廓的 +y 朝模型中线外侧
（边箱外缘的风嘴）。这只影响画法，不读也不改计算；D1 演示（nsfc `scripts/d1_xihoumen.py`）就是这样画的。
页面里有：

* **连续着色**（默认开）：每根构件沿轴线从一端的颜色渐变到另一端。节点场（位移）按两端节点的值；
  单元场（承载力比、内力）先在节点上按**同一截面**的构件取平均（主梁的值不和在同一节点相交的索混在
  一起），断开的两侧不互相平均。关掉就是每根构件一个颜色。壳和实体同样按节点平均
* **整体坐标轴**（默认开）：模型包围盒的三条边上画 X、Y、Z 轴和刻度（单位取算例的长度单位），左下角
  一个随视角转动的坐标方向指示；很短的轴（比如桥宽）只标两端的刻度
* 构件按任意标量场着色（下拉菜单：`|u|`、`u_x/u_y/u_z`、结果文件里每个节点场和单元场，如
  `capacity_ratio`、`axial_force`、`von_mises`、`|contact_force|`），图例给该场在全部帧上的范围
* 断了的构件（`member_failed`）画成灰色，可以隐藏：两端还没分开时仍是一段，分开后每个节点带着
  半段（方向跟着它还连着的邻段），断掉的索消失；断裂事件在时间轴上是刻度线，右上角计数
* 没有承载力判据的构件（塔、横梁）在 `capacity_ratio` 云图里是中性灰，不是色标的最低端；
  内力场的色标取 0.5%–99.5% 分位（塔的弯矩比箱梁大三个量级，按最大值取箱梁就全是一个颜色），
  超出的按端色画，图例标 ≤/≥
* 位移放大（自动或 ×1…×1000），默认**相对首帧**放大——从恒载状态起步的桥，放大的是相对恒载的振动，
  不是恒载挠度本身
* 监测量曲线带时间光标；松弛和静力（含弧长法）的结果横轴是荷载因子 λ 而不是秒，曲线按记录序号画，
  所以弧长法回退、变负的荷载因子也在图内；徐变、收缩、龄期的松弛结果同样按记录序号画，读数为混凝土
  龄期（天）；播放、暂停、拖动、速度
* 实体只画外表面（内部面按排序找出一次），壳画面，线构件画成方杆（没有 `--case` 时一个粗细，
  `--thickness`，默认模型对角线的 1/300）

数据压缩：位移按帧量化到 16 位（最大位移的 1/32000），只存运行中用到过的质点（预留给分裂的
备用质点没用上就不存）；位移分量和模在页面里从位置算；`member_failed` 从断裂事件表重建；
分裂后的连接关系只存变化；其他场量化到 8 位（256 色，比云图分得出的还细），不变的场只存一个值；
全部 base64 嵌在 HTML 里。帧数默认最多 400（均匀抽取，末帧
一定保留），`--every k` 每 k 帧取一帧。西堠门四幕各 240 帧、四个云图场，14.6 MB。页面只有
一样东西要联网：three.js 从两个 CDN（cdnjs.cloudflare.com、cdn.jsdelivr.net）取一次。连不上时页面是暗的、有一行提示；
`--scripts 目录` 把 three.js 写进页面，目录里放 three.js r128 的 `three.min.js` 和 `OrbitControls.js`（即 npm 包
`three@0.128.0` 的 `build/` 和 `examples/js/controls/`，或直接放在目录里），页面就不需要联网（1.16；早先版本做的、不带真实截面
轮廓的页面无论联不联网都停在第一帧、一片黑——1.16 版）。`vfife modal` 的模态文件不是运行结果，会被明确拒绝。

**计算之前看模型**（1.20 版）：给 `vfife view` 一个算例文件（`.yaml`），它写出模型页面：

```bash
python -m vfife view bridge.yaml                 # -> bridge.model.html
python -m vfife view bridge.yaml --scripts three_r128 -o 模型.html
```

* 页面里是求解器读到的模型：高层块（11.14–11.16 节）展开后的样子，包括 `tendons:` 加出的钢束节点、杆和刚臂；区域的解析方式与求解器相同。不运行，不建求解器。
* 按分析步看：底部的滑块选步，页面只画该步站着的构件。还没建（或已拆除）的构件淡显，可以关掉；本步新建的标成品红色。
* 构件画成屏幕上固定宽度的细线（`--thickness` 是梁的线宽，单位像素，默认 2），每根构件的节点都画成小点（只连着刚臂的节点也画）；钢束自己的节点不画。着色可以按构件类型（梁、索或杆、钢束、刚臂（红色）、连接器）、截面、建造步或区域。刚臂可以隐藏（立在刚臂上的支承等照画）。区域列表（`assign` 用到的区域）选一个区域时只画它的构件，其余淡显；关掉淡显时其余不画。
* 支承、连接器和土弹簧按常用软件的画法：每个一个符号，每个自由度或分量是什么写在旁边的短代码里；每类有自己的开关（1.20 版）：
  * 支承：节点下一个三角形，约束了平动的实心，只约束转动的空心，约束了转动的下面加一道横杠。代码是 ux uy uz rx ry rz 六个自由度，`1` 约束、`0` 自由（如 `111000`），约束的平动为红色、转动为紫色；有给定运动的自由度为青色，三角形也为青色（该自由度的 `value` 非零、`motion` 不是位移，或 `record` 驱动的平动）。模型级的约束、本步自己的约束、前面步 `keep` 下来的约束都算，被 `release` 的不算。
  * 连接器：首节点一个空心方块，末节点一个空心三角（节点的点从中间透出来），中点画局部轴小三轴（x 红、y 绿、z 蓝；x 沿连接器，y 是 `orientation` 扶正到与它垂直，没写时取与它最接近垂直的整体轴，z = x × y；`coordinate_system: global` 时为整体轴）。代码是六个分量：`K` 刚度，`N` `curves` 表或 `bilinear` 律，`G` `gap` 律，`F` `friction` 或 `pendulum` 律，`D` 只有阻尼，`0` 自由；旁边并有 `connector_damping` 或 `damper` 律的分量为蓝色（如 `KK0000`）。uy、uz 上相同的摩擦、摩擦摆或双线性律是 y–z 平面里的一个律，写成小写（如 `Kff000`）；末尾的 `*` 表示刚度或阻尼是耦合的 6×6 矩阵。
  * 土弹簧（`soil_springs`）：它作用的每个节点上一根到地的短弹簧。
  * 符号在屏幕上大小不变，符号大小滑块调符号和代码的大小（不调点中后的完整画法）。支承的代码先放，连接器的后放。会和已写的代码重叠的代码不写（符号照画）；拉近或关掉代码即可。
  * 点一个支承或连接器，完整画出它：每个约束的自由度是沿该轴的杆（转动是套在轴上的环），每个分量画在自己的轴上——弹簧、黄色弹簧、两块板（间隙）、轨道上的滑块（摩擦、摩擦摆）、螺旋（转动），旁边并排阻尼器；`direction: horizontal` 的土弹簧是一根径向弹簧，画在两个水平方向上，用虚弧连起来；uy、uz 上相同的摩擦或摩擦摆律是 y–z 平面里的一个律，两个符号同样用虚弧相连。
* 荷载：该步有的荷载画成箭头，包括模型级的、本步自己的和前面步 `keep` 下来的。
  * 节点力为红色，指向节点；力偶为紫色，沿力偶矢量。
  * 线荷载为蓝色，画在构件中点；按构件局部轴写的线荷载不画，只列出。
  * 箭头长度按同类荷载里最大的那个缩放。
  * 重力、温度、移动荷载等在左侧面板里列出。
* 点一根构件，右上角显示它的编号和节点、类型、区域、截面（名字和数值）、长度、在哪一步建造和拆除；属于钢束的，还显示钢束名；连接器还显示它的轴和每个分量是什么。点一个支承（或有土弹簧的节点），显示节点、该步约束的自由度和其中有给定运动的自由度。
* 只用于框架模型（梁、杆、索、连接器）；实体和壳的算例会被拒绝（VIEW_MODEL）。`--scripts`、`-o`、`--title` 与看结果时相同。
* 三座真实桥（6,600、4,100、9,300 根构件）生成页面用 6–17 秒，页面 1–3 MB。

### 12.6 Python 接口

`vfife.api` 是给脚本、笔记本和前端用的接口（API 版本 1，1.0 版）。
`vfife.api.__all__` 里的名字就是承诺：1.x 之内签名和含义不变，只会加带默认值的参数。
逐个名字的说明见 `docs/API参考.md`，它由代码的文档字符串生成
（`python -m vfife reference --api`），测试保证两者一致。

**跑一个算例**：

```python
from vfife import api
outcome = api.run_case("pc_beam.yaml", output="results/pc_beam.h5")
print(outcome.status, outcome.converged, outcome.message)
print(outcome.monitors["w_mid"][-1], outcome.times[-1])
```

`run_case` 不会退出进程。数值失败也返回一个结果，失败原因在 `status` 和 `message` 里，
诊断、失败前记录的监测量和检查点照样写出；失败前写的帧都保留，但失败时的状态本身不写成帧（它在 `<结果>.ckpt.h5` 里）。输入错误抛出 `api.UserError`（`ValueError` 的子类，带 `code`、`message`、`hint`；代码见
docs/error_codes.md）；不符合 schema 的算例抛出 pydantic 的 `ValidationError`（也是 `ValueError`），文件不存在抛出
`FileNotFoundError`，所以捕获 `ValueError` 和 `OSError` 就能接住所有输入错误。preflight 不通过不抛异常：结果的
status 为 `PREFLIGHT_FAILED`。要中途停止，让 `on_progress` 返回 False（或按 Ctrl-C）：结果和
检查点写完后抛出 `api.AnalysisInterrupted`，其 `result_path`、`sidecars`、`report` 说明保留了什么，
可用 `restart=` 续算。

**改一个参数再算**：

```python
case = api.load_case("pc_beam.yaml")
case.get("materials.concrete.fpc")                    # 读
stronger = case.with_changes({"materials.concrete.fpc": 5.0e7,
                              "loads[0].line_load[2]": -3.0e4})
api.run_case(stronger, output="results/pc_beam_fpc50.h5")
```

* 键是穿过 YAML 的点路径，列表用 `[i]`（或 `.i`）。
* 只有最后一段可以是新的（例如给没写过的 `solver.threads`）。
  截面名、材料名写错会报错，并列出实际有的名字；字段名写错，由 schema 在运行前拒绝。
* 改过的副本记得原算例所在的文件夹，所以网格、地震记录、`initial_state` 仍按原文件里写的
  相对路径找得到。直接把字典交给 `run_case` 则不行：相对路径会按当前目录解析。

**参数研究**：

```python
rows = api.study("pc_beam.yaml",
                 {"materials.concrete.fpc": [3.0e7, 4.0e7, 5.0e7],
                  "loads[0].line_load[2]": [-2.0e4, -3.0e4]},
                 output_dir="results/fpc_study",
                 extract=lambda o: {"w": o.monitors["w_mid"][-1]})
```

* 默认跑所有组合（上例 6 次）；`combine="zip"` 则逐项配对。
  也可以直接给一个 `[{键: 值}, ...]` 列表，一项跑一次。
* 每次写 `output_dir/<算例名>_<序号>.h5`。
* 每次一行：参数值、状态、是否收敛、结果路径、用时，加上 `extract` 返回的量。
* 某一次出错只记下原因，研究继续跑；`extract` 出错时该次计算的状态、结果路径照常记录，`extract`
  的错误记在 `extract_error` 列。
* 行列表同时写成 `output_dir/study.csv`，`pandas.DataFrame(rows)` 就是一张表。
* 写错的键和字段名（包括材料参数名、徐变/收缩/松弛/龄期块内的键和 `units` 的键）在第一次运行之前就
  报出来；值不合法则只记在该次那一行。

另有 `prepare_case`（校验、读网格、preflight，不建求解器）、`read_monitors`（读结果里的曲线）、
`verify(contract, result)`（按契约检查结果；两个参数写反会以 `VERIFY_ARGUMENTS` 拒绝）、`case_schema`（算例文件本身——materials / sections / assign 等——的 JSON Schema，给界面和外部
生成器用；自带算例全部符合）。

## 13 模型检查与结果校核

### 13.1 运行前检查

```bash
python -m vfife check case.yaml     # 模型质量 JSON：区域、约束、单位量级、网格质量、输出字段
python -m vfife info case.yaml      # 建模、打印摘要，不求解
```

preflight 在每次运行开头也会执行，发现错误直接停止。常见报告：未约束的刚体运动（并给出需要
的约束；六自由度模型直接给出转动自由度，1.0 版）、区域吸附、单元未指派、截面为空、单位量级不符、网格质量差。
`info` 还列出每个连接器截面（区域、单元数、各分量的刚度或本构）以及模型的总质量与重量（按声明的单位）。

### 13.2 不变量探针

```bash
python -m vfife probe case.yaml
```

对模型问四个与单元无关的问题：内力是否是某个势能的梯度、刚体运动是否不产生内力、质量能否
限制时间步、当前状态是否稳定。用于新单元、新材料或可疑模型的诊断。
有预应力、温度、徐变/收缩/松弛或 initial_state 的模型，在参考构形和弯曲构形上跳过"无力"与"稳定"两项（写明原因）；
用 `--result` 检查收敛帧。

### 13.3 验证契约

`verification/` 下每个编号算例都有一份独立的验证契约（YAML），写明它是哪一类证据、对照的是
什么、允许差多少：

| 类别 | 含义 |
|---|---|
| `analytical` | 闭式解 |
| `public_benchmark` | 公开发表的试验或基准（外部目标） |
| `independent_reference` | 独立组装或积分得到的参考解 |
| `regression` | 本项目基线或物理不变量，不作为公开基准 |

```bash
python -m vfife run    cases/case_01_beam_cantilever.yaml
python -m vfife verify cases/case_01_beam_cantilever.yaml
```

`verify` 返回 0 为通过、2 为不通过，并在 `results/verification/` 写出 JSON 与 Markdown 报告。不给 `--contract` 时，
依次找算例所在文件夹旁边的 `verification/<算例名>.yaml`（自带的布局：`cases/` 与 `verification/` 并列）、该文件夹里的、
工作目录下的（1.0 版；以前只找工作目录下的）；不给 `--result` 时读算例 `output.path` 指的文件，没有则读 `results/<算例名>.h5`。
一条指标由来源（`monitor`、`diagnostic`、`field`）、名称、归约方式和期望值组成，归约除
`final`、`max` 等之外，还有 `at`（另一条曲线达到某值时本曲线的值）、`energy`（曲线下面积）、
`at_peak_of`（另一条曲线峰值时本曲线的值），所以契约可以约束整条荷载–位移曲线的形状，而不只
是峰值。用 `source: field` 在 `location` 处读取矢量场时，`final`/`first`/`delta` 须写 `component`
（1.0 版起；此前静默返回 z 分量）。

用户自己的算例也可以写契约，写法照 `verification/README.md`。

### 13.4 测试

**三条对结果的承诺，各有测试守着：**

* 编译的整步与逐步的循环给出相同的结果，逐位相同；
* 停下再续算，与不间断运行逐位相同；
* **结果不依赖输出帧和进度检查落在哪里**（`output.every`、`--progress-every`）：每步出一帧和完全不出帧，终态逐位相同。
  1.12.1 以前带断裂的纤维梁、框架、桁架不是这样（一次本应只读的内力计算会把构件早一步弄断，11.10 节）；
  `tests/test_reading_is_not_a_step.py` 对每一类求解器、每一种会记历史的材料都跑这一对照，新加的求解器或本构要进这张表。

```bash
python -m pytest -q            # 默认层（约 2200 个测试；两核机器约半小时）
python -m pytest -q -m slow    # 逐个求解全部自带算例并对照契约（数小时）
python tools/check_all.py      # 全部检查，在本机并行跑（1.0 版），见下
```

**全部检查（`tools/check_all.py`）**：GitHub 上的夜间验证层（每晚六十个作业、每个最长两小时）
已经关掉，同样的检查在本机跑。分四部分：

* `fast`：默认测试层；
* `slow`：慢测试里除算例契约以外的部分；
* `cases`：每个自带算例求解并对照契约。每个算例一个进程、单线程，`--jobs` 个同时跑，
  默认取核数的一半；
* `package`：构建 wheel，装进一个全新的虚拟环境，在仓库之外跑一个算例（需要 `pip install build`）。

报告写进 `results/check_all/<时间>.md`，有失败时退出码非零。常用写法：

```bash
python tools/check_all.py --jobs 8                        # 八个算例同时跑
python tools/check_all.py --only cases --cases case_24g case_36
python tools/check_all.py --include-slow-cases            # 连 case_15（一到两小时）也跑
```

CI 上仍保留：每次推送跑默认层；验证层只在 Actions 页面
手动触发（Run workflow）时跑。

（"cannot read or write <路径>"）；结果文件被其他程序锁住时提示关闭它。输出管道被关闭
（如 `| head`）时安静退出，退出码 141。`vfife run` 被 Ctrl-C（或界面上的停止）停下时退出码 130，被 SIGTERM
（集群的时限）停下时退出码 143，此前已写好部分结果和检查点。

**退出码**：0 成功；1 输入错误（被拒绝、文件读不了、YAML 或 schema 不对）；2 preflight 不通过（`check`、`info`、`run`）或
`verify` 不通过；3 计算没有收敛（`run`：MAX_STEPS 或 NONFINITE，失败的结果照样写出；`formfind`：内层松弛不收敛）；
130 Ctrl-C；143 SIGTERM；141 管道被关闭。被拒绝时打印其代码：`error [CHECKPOINT_MISMATCH]: …`（1.0 版）。拒绝与 preflight
可能给出的全部代码见 docs/error_codes.md，由代码生成（`python -m vfife reference --codes`）。

每个命令的完整参数用 `python -m vfife <命令> --help` 查看。

## 15 常见问题

**Q：运行报 "did not converge"。**
先看报告的残差最大节点和自由度。荷载级太大就增加 `load_steps`；刚好在开裂或屈服处卡住，
减小该段的级差或增大 `max_steps_per_load`；过了极限点的静力分析本来就不会收敛，改用慢速
动力推覆（第 10.2 节）。见 `docs/convergence_debugging.md`。

**Q：结果看起来合理，但反力和施加的荷载对不上。**
几乎总是区域选错了节点（面编号猜错、容差、吸附）。用 `vfife mesh` 看物理组，用 `vfife check`
看区域报告。

**Q：动力分析的响应被"抹平"了。**
检查阻尼类型：动力分析不要用 `kinetic`。

**Q：静力问题收敛极慢。**
近不可压缩材料（ν → 0.5）下虚拟质量由体积项决定，弯曲模态很软；改用 `mode: dynamic` 加质量
缩放，或预期更多迭代。箱梁作为纤维梁时，先确认 `j` 给了。

**Q：箱梁的扭转频率偏高一倍。**
没有给 `j`，程序用了极惯矩。

**Q：温度荷载下简支梁有应力。**
正常：非线性温度分布中不能保持平截面的部分成为自平衡应力。

**Q：数值差了 1000 倍。**
单位不一致。声明 `units:`，让 preflight 检查量级；网格按毫米画的用 `mesh.scale: 0.001`。

**Q：预应力束的上拱与预期不符。**
先用 `vfife info` 看每根束的应力范围和位置；确认后张束是否需要 `elastic_shortening:
compensate`；确认自重与预应力同时从一开始作用（预应力不能斜坡加载）。

## 16 适用范围与已知限制

vfife 是**分析引擎，不是设计软件**。以下内容不在其中，需要工程师另行处理：

* 规范荷载组合与包络、规范验算流程
* 车道荷载与影响面自动加载、横向分布（移动荷载沿构件轴线走）
* 桩土的辐射阻尼、t–z 与 q–z（桩侧摩阻与桩端）、p–y 的滞回与桩后间隙（p–y 只有非线性弹性，11.13）；地震记录施加在写它的支承上
* 箱梁作为梁建模时的剪力滞、畸变、约束扭转翘曲（纤维截面服从平截面假定）
* 施工阶段（模型从第一步起就是完整的，先简支后连续、悬臂拼装的恒载状态按一次落架；**计划 1.0 之后补**）
* 支座的速度相关摩擦、刚度退化；连接器的非线性只有库仑摩擦、间隙和双线性滞回（11.11 节）
* 按截面真实形状的接触、与实体网格的接触：构件按给定半径的胶囊体接触（`contact.members`，11.12 节）
* 纤维梁的剪切开裂只是构件层面的刚度折减（`shear`，1.0 版），不与弯曲耦合（不是 MCFT），
  不给剪切破坏；需要腹板斜裂缝的应力场时用局部实体模型
* 温度只作为施加的场，不做热传导，材料性质不随温度变化
* 车辆是平面模型（竖向 + 俯仰），没有侧倾和横向分布；车道荷载与冲击系数是规范内容，不在库里
* **壳（shell3、shell4、shell_line）是实验性功能，1.0 不作承诺**（1.0 版）：三角形壳 shell3
  剪切自锁，薄板挠度只有真值的 0.2%–20%，请用四边形网格；shell4 默认的沙漏稳定项使弯曲偏硬
  2%–30%（单元越狭长越硬，加密网格消不掉），扭曲的四边形会自锁。preflight 对每个壳模型给出
  `SHELL_EXPERIMENTAL` 警告。内力分量在单元局部轴下，局部 x 轴取单元第一条边的方向，随节点顺序而变；
  top/bottom 应力不含横向剪应力（`shear_x`、`shear_y` 是剪力 Q，中面峰值 1.5 Q/t）
* warp 后端（GPU）的壳计算不能从检查点续算（`--restart`），换 numba 后端
* 与商业软件的对照是与 Midas Civil，用的是放在仓库外的课程模型（1.15 版）；Midas 转换计入钢束松弛（1.16），不考虑徐变、收缩、温度、移动荷载和板单元刚度
* 只有张拉杆（`jack`）作为荷载的模型，用一个连续的松弛步（`mode: relaxation`，只给 `n_steps`、不给 `load_steps`）算不收敛（残差停在 0.5 附近）：给该步 `load_steps`，或用 `mode: static`（Midas 转换写的就是静力）
* 连续倒塌之后的碎片：1.16 及以前，碎片落地后能量可能无限增长（一座真实钢桁架拆除端柱后约 1.2 s，十几个碎片以 1e13 J
  飞走）。在一座通用桁架（`benchmarks/debris_truss.py`）上找到原因，1.17 已修（1.17 版）：
  - 转动惯量（含稳定下限）是固定在整体轴上的对角阵，步进里没有陀螺项，碎片翻滚后不再对：脱离支承的碎片上，每个质点的三个
    转动惯量取其中最大的一个（保持角动量）。仍与支承（`constraints`）相连的结构不变，模态和没有构件断开的动力结果与
    1.16 逐位相同。只靠接触面站着、没有任何约束的模型，在第一次断开时整体都按碎片处理。一大段脱落的主梁，扭转惯量最多
    被抬高约 250 倍，扭转振动变慢。只在有构件可以分离（`split`）时生效；
  - 可断的梁两端相对扭转四分之一圈即整根移除（`member_failures` 原因 3）。这是共旋框架读扭转角的有效范围（不能过半圈），
    不是材料准则：扭矩不按强度检查，真实钢构件在这之前早已剪切屈服；
  - 两端都已断开的碎片，需求达到承载力两倍时整根移除。两倍是经验取值：碎片断开后是弹性的，没有塑性耗散。
  这三条只对框架和混合线单元求解器；纤维梁的碎片没有改，仍是 1.16 的做法。
  移除构件带走的应变能没有记账，能量误差偏少一侧：通用桁架上结构阻尼 1.0 时 0.3%、0.3 时 8%、无阻尼时 6%。
  同一座真实钢桁架重跑，5 s 全程算完、动能不再增长；但约 0.8 s 时三个支座节点在桁架杆件全部分离、只剩支座连接器时被甩出
  （位移 1e14 m，能量误差从此 50%），原因还没有查，读结果时请排除这类节点。仍请读 `diagnostics/relative_energy_error`

精度与效率：

* 61 份验证契约、402 个指标（按契约分类：31 份闭式解、17 份公开试验或基准、10 份独立参考解、
  3 份回归基线）；每份写明对照的是什么、差多少、为什么。0.4.2 上逐份求解重跑，当时的 50 份全部通过
* 纤维梁受压软化后的下降段对单元长度敏感；承载力由钢筋或钢绞线控制时影响次要
* 静力解默认来自动力松弛：线弹性梁模型几秒；3 × 70 m 一联的纤维模型从几分钟到一小时。
  框架和纤维梁可以改用隐式静力（`mode: static`），Vecchio & Emara 框架从 22 min 到 8 s，
  杭州湾一联带墩的推覆从 50 min（显式动力）到 30 s；自带的静力算例自 1.5 起凡能用它的都用它（见 10.2），
  推过极限状态的钢筋混凝土纤维梁除外
