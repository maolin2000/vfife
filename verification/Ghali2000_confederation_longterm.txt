# Ghali, A., Elbadry, M. & Megally, S. (2000), "Two-year deflections of the
# Confederation Bridge", Can. J. Civ. Eng. 27: 1139-1149.
# FIGURES 18, 19 AND 20 DIGITISED, plus the two numbers the text states
# outright.
#
# Companion to the truck-loading data already used by case_28: same paper,
# same 440 m portal frame, same 27 benchmarks inside the box girder. This file
# carries the LONG-TERM half -- what the bridge did in the 669 days after
# March 9, 1997.
#
# WHAT IS AND IS NOT REPRODUCIBLE FROM THIS PAPER. Read this before using any
# number below as a target.
#
#   * The 54 kN/m superimposed dead load, and the instantaneous deflection it
#     causes, ARE stated (p. 1147) and are reproducible: a stated load on a
#     structure whose geometry is published. That is what case_28d checks.
#   * The three analysis CURVES are not reproducible as curves. They are the
#     whole history -- segment-by-segment erection, external prestressing with
#     friction losses, steel relaxation, shrinkage, and creep of every one of
#     those increments at its own loading age. None of the erection dates or
#     tendon forces are in this paper.
#   * The "recorded properties" curve is not reproducible AT ALL: it uses
#     best-fit creep and shrinkage equations given in Ghali, Tadros & Langohr
#     (1999), which we do not have. Only the MC90 and ACI 209 curves rest on
#     published models, and both of those models are in this library.
#   * ALL THREE analyses EXCLUDE daily temperature variation, which the paper
#     says is why they sit so far above the measurement. Figure 21 puts one
#     hot summer day at 60 mm UP at midspan -- the same order as the entire
#     667-day measured movement. The measured points below are therefore NOT
#     a creep curve; they are creep plus whatever the deck temperature was on
#     the morning of each survey.
#
# ---------------------------------------------------------------------------
#  THE TWO STATED NUMBERS  (p. 1147, quoted)
# ---------------------------------------------------------------------------
#  "the analysis shows that about 70 mm instantaneous deflection occurs at mid
#   span and 80 mm deflection occurs at cantilever tips, as a result of
#   placement of the specified superimposed dead load (54 kN/m). The
#   instantaneous deflection caused by the superimposed dead load is indicated
#   by the jump in the curves of predicted deflection (Fig. 20) after about
#   40 days from the reference date (March 9, 1997)."
#
#  These are outputs of Ghali's OWN analysis, not measurements -- the paper
#  says in the same paragraph that the field never measured them. So a model
#  that reproduces them has reproduced another analysis, which is the weaker
#  of the two kinds of agreement and is labelled as such in the contract.
#
#  The 54 kN/m acts on the drop-in beams too. Each 60 m drop-in beam is simply
#  supported between the tips of two adjacent overhangs (250 m pier spacing =
#  95 + 60 + 95), so each overhang tip additionally takes
#
#       V = 54 kN/m x 60 m / 2 = 1620 kN
#
#  That reaction is drawn as V in the paper's own Fig. 9 frame idealisation.
#  Leaving it out is not a small error: it moves the tip deflection from 28 mm
#  to 107 and midspan from 104 to 79 (benchmarks/generate_confederation.py
#  --check prints both).
#
# ---------------------------------------------------------------------------
#  HOW THE FIGURES WERE DIGITISED
# ---------------------------------------------------------------------------
#  Page 1147 rendered at 400 dpi. The two model curves are the only COLOURED
#  ink on the page -- ACI 209 a magenta dash-dot, CEB-FIP MC90 a blue dot --
#  so they separate from the axes, the pier drawings and the labels by hue
#  alone, and each is read as the median row of its own ink in every pixel
#  column. The "recorded properties" curve is a thin black dash: it is read as
#  the centroid of every black component 6-70 px wide and <= 12 px tall, which
#  picks up its dashes and nothing else. The measured series is the one thick
#  black polyline; its data points are the columns where it is >= 16 px thick,
#  i.e. the filled markers.
#
#  Fig. 20's axes are calibrated on its tick LABELS (six on y, seven on x,
#  least squares). The check on that fit is independent: it puts the drawn
#  x-axis line at -0.03 mm where it should be 0.0. Fig. 18 and Fig. 19 are
#  calibrated vertically on the drawn zero line and the "200" label, and
#  HORIZONTALLY ON THE TWO PIER CENTRELINES, which are dash-dot verticals at
#  exactly -125 m and +125 m -- a better ruler than the tick labels.
#
#  THE CROSS-CHECK, and it is a real one: Fig. 20 is drawn at 115 m from P32,
#  i.e. 10 m from midspan, and Figs. 18 and 19 are profiles containing that
#  same station. Digitised independently, from different panels, with
#  different calibrations:
#
#                        Fig. 20       Fig. 18/19 at midspan
#      327 d  MC90        126.6              128
#      327 d  ACI209      157.6              161
#      467 d  MC90        143.1              144
#      467 d  ACI209      176.2             ~172
#
#  Agreement of about 1-2%, which is the accuracy claimed for everything in
#  this file. One digit of the printed numbers is therefore not meaningful.
#

#  below midspan depends on the load; that it is the SAME ORDER does not, and
#  it is the same thing the 80-against-70 mm of the superimposed dead load
#  says. A model that puts the tips at a third of midspan has left the drop-in
#  beam reaction out.
#
# ---------------------------------------------------------------------------
#  FIG. 7 -- RELAXATION OF THE BRIDGE'S OWN STRAND
# ---------------------------------------------------------------------------
#  Relaxation (%) against time (1 to 10 000 h, log), for specimens stressed to
#  0.8 of their ultimate strength. Five curves: the measured one, and CEB-FIP
#  MC90 and PCI each for stress-relieved and for low-relaxation steel. The
#  paper's conclusion from it (p. 1142) is the reason MC90 appears in the
#  deflection analyses: "With increased time, the measured prestress relaxation
#  values tend to be close to those values predicted by the CEB-FIP MC90 for
#  low-relaxation steel."
#
#  Read at three times, by the hue-free version of the method above -- these
#  curves are all black, so they are separated by ORDER (they never cross) and
#  each is read as the centre of its own ink run in a column that is not on a
#  vertical gridline. Values carry about +/- 0.1 percentage point.
#
#    t (h)     PCI-SR   CEB-SR   measured   CEB-LR   PCI-LR
#      250       9.4      4.9       3.2       2.20     1.81
#     1000      11.7      6.9       4.27      3.11     2.25
#     6000      14.8      9.9       6.04      4.44     2.86
#
#  WHAT THIS IS USED FOR, and what it is NOT. It is NOT a statement of MC90's
#  coefficients: this library does not implement the code formulas, because
#  their constants could not be sourced verbatim and a relaxation law written
#  from memory is worse than none. What it IS: a published
#  MC90 curve for a real strand at a stated stress ratio, which a
#  `model: power` spec can be fitted to and a case can then cite. Fitting
#  `rho(t) = rho_1000 (t/1000)^k` to the CEB-LR row gives
#
#      rho_1000 = 3.1%      k = 0.198   (from the 1000 h and 6000 h points)
#                           k = 0.221   (from the 250 h and 6000 h points)
#
#  so the curve is a power law to about +/- 0.02 in the exponent over this
#  decade and a half. `k = 0.21` reproduces the 1000 h and 6000 h readings
#  within 0.3% and the 250 h one within 5.3%, which is about what the reading
#  itself is worth at 2% relaxation.
#  Both numbers are AT 0.8 f_pu; a code's rho_1000 is quoted at 0.7, and the
#  stress-ratio dependence is strong. Do not carry them to another stress
#  level.
#
#  The measured curve is the one that starts at 1.5% at t = 1 h -- a real
#  specimen loses something the moment it is stressed -- and it is the only
#  curve with visible jitter. The two PCI curves are straight on this axis,
#  i.e. logarithmic in time, which is the older family of relaxation laws.
#
